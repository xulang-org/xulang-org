#xacp 是随 Xu {{xu_version}} SDK 发布的、与传输无关的安全核心：帧上限、XUN 校验、权限和会话生命周期。导入它不会打开控制通道。stdio 与本机回环 TCP 是运行时钩子，只有 xu build --xacp 或 --xacp-port 才会插入。

命令行：xu xacp · 常见问题 · 对应发布源码

以下契约已对照选定发布源码审阅。原生 stdio/TCP 会话、UI 附着、截图和各平台验收仍为待验。

会话

open_session() 返回 STATE_NEW（0）会话，权限为 PERM_NONE，代数为 1，下一个请求 id 为 1。close_session 将其改为 STATE_CLOSED（2），增加代数，清掉活动请求并收回权限。STATE_OPEN 为 1。

同一时刻只能有一个活动请求。begin_request 检查授权，只接受正数且等于 next_id 的 id，预约后推进下一个 id。非法 id 返回 invalid_request_id；第二个活动请求返回 request_in_flight。首个请求不是 hello 时，以 hello_required 关闭会话。finish_request 检查活动 id 和代数（不匹配返回 stale_request）。成功协商的 hello 打开会话；未经协商的 hello 不能打开会话。已关闭会话返回 session_closed。

函数作用

close_session(s $&Session)关闭并清空权限。
cancel_request(s $&Session)丢弃活动请求，不把会话打开。
begin_request(s $&Session, r &Request) Outcome在 authorized 允许时预约下一个单调 id。
finish_request(s $&Session, id int) Outcome释放活动 id。id 1 会打开会话。

Hello 与权限

权限变更是宿主策略。set_permissions 只在会话仍为 STATE_NEW 时成功，并且只接受 0..15 内的位。未知位会被拒绝。请求一旦 finish，权限不再改变。

常量值操作
PERM_NONE0xacp.hello，且仅来自 STATE_NEW
PERM_INFO1proc.status
PERM_PROCESS2proc.output
PERM_UI_READ4ui.tree、ui.screenshot、ui.record
PERM_UI_MUTATE8ui.input、ui.act
PERM_ALL15development_permissions() 与 enable_development()

enable_development(s) 是等同于 set_permissions(s, PERM_ALL) 的显式宿主辅助函数，不绕过 schema 校验、会话生命周期、原生资源释放或上限。hello 完成后调用它返回 false。启动与附着服务改为读取 XU_XACP_TOKEN，在合法 hello 已 begin、尚未 finish_request 时调用 negotiate_hello。

Hello 必须提供 ver: !ver 1.0.0 和非空字符串 nonce，响应会回显 nonce。宿主未设置令牌时，即使客户端发送令牌，权限仍至多为 PERM_INFO。宿主设置令牌时，客户端 args.token 缺失或不匹配会返回 auth_failed 并关闭会话；匹配后至多允许 PERM_ALL（本 SDK 为 15）。可选的 args.permissions 是只包含已知位的 !i 掩码：实际授权为请求值与宿主允许值的交集；省略则请求宿主的全部允许值。响应包含数值 permissions 与 permission_label（none、info、development 或 custom）。

帧与上限

两种传输均使用 XACP/1\n<N>\n，紧接恰好 N 字节的纯 XUN 正文。帧头行以 LF（0x0A）结束；N 是不含帧头的正 ASCII 十进制字节数。按 UTF-8 字节计数，正文换行也计入。没有结束分隔符，帧间不添加额外分隔字节。传输层去掉前缀并读取恰好 N 字节，再调用 parse_frame(body)。该函数只接收 XUN 正文，拒绝空正文、非法 XUN 和超过 MAX_FRAME_BYTES 的正文。validate_request 要求根字典恰好包含 id、op、args；id 是正数 !i。

default_limits() 使用下列硬上限。自定义 Limits 只能更小。

常量值
MAX_FRAME_BYTES1048576（1 MiB）
MAX_STRING_BYTES65536
MAX_FIELDS64
MAX_TABLE_ROWS10000
MAX_NODE_ID16777215

consume_input 与 consume_output 拒绝负数、单次超过帧上限或累计超过会话字节预算的计数。启动期读取器对超限正文返回 frame_too_large，对帧头或正文内部的 EOF 返回 truncated_frame。帧边界上的完整 EOF 关闭会话。帧错误使用 id 0；schema 错误尽量使用有效的 id 提示，否则使用 0。帧、schema 和认证错误会关闭会话。

以下 hello 的正文为 69 字节，帧头为 10 字节（共 79 字节）。每一行都以 LF 结束，包括 nonce 行：

XACP/1
69
id: !i 1
op: xacp.hello
args:
  ver: !ver 1.0.0
  nonce: docs-client

宿主未配置令牌时，对应响应的正文为 109 字节（含帧头共 120 字节）。最后一行同样以 LF 结束。响应使用相同的长度前缀，包含 id、ok，以及 data 或 error.code（还可带 error.msg）。下一帧紧接正文开始：

XACP/1
109
id: !i 1
ok: !b true
data:
  state: OPEN
  nonce: "docs-client"
  permissions: !i 1
  permission_label: info

在启动通道上，not_implemented 发生在 begin_request 之后，因此该 id 已被消耗，下一帧必须使用随后的 id。permission_denied 在 id 前进之前返回。

UI 控制需要显式的 attach_stdio 或 attach_tcp 句柄、通过 register_screen 注册的真实 ui/widgets.Screen，以及 Screen 所属协程在 UI 事件迭代之间调用 poll。这条路径中业务 main 继续运行，退出轮询循环前应注销 Screen。带类型的辅助函数（ui_tree、ui_screenshot、ui_input、ui_act 和录制辅助函数）仍要求相应权限，检查窗口/节点 id、缩放（0.1 至 4.0）、文本以及行数/事件预算。截图返回拥有所有权的 draw.Surface，调用方负责 dispose。dispatch_screen 对 ui.record 返回 stream_required。启动期 --xacp-stdio 与 --xacp-tcp 不会注册 Screen。端到端 UI 行为仍为待验。

传输钩子

src/xacp/stdio.xu 位于同一个包。--xacp 构建会在 main 开头插入 stdio_preflight(port)。那才是控制入口。普通 #xacp 导入不会发出这段启动代码。

  • stdio_preflight(port) 扫描参数直到 --。先遇到的 --xacp-tcp 或 --xacp-stdio 生效，并在不运行 main 其余部分的情况下退出。其他启动方式直接返回，业务 main 照常运行。它们不监听，也不读取控制 stdin。
  • serve_stdio() 读写进程的标准流。请求与响应使用同样的 XACP/1 长度前缀。会话独占标准流。EOF 结束进程。
  • serve_tcp(port) 只在 127.0.0.1:port 监听。构建端口必须是 1..65535；端口 0 关闭 TCP，此时该函数失败。每个已接受的连接有自己的会话。连接按顺序处理。失败的对端只结束自己的会话，监听继续接受后续连接。没有 TLS，也不能绑定其他地址。

--xacp-help 是单独的启动期打印，不是控制会话。它的 capabilities 行是 stdio。构建端口为 0 时还会打印 tcp: disabled (port 0)。正端口会打印 tcp: enabled 和 bind: 127.0.0.1:PORT。启动器模式见命令行参考。

尚未覆盖

  • 没有 TLS。
  • 不能绑定 127.0.0.1 以外的地址。
  • 启动通道上还没有真实的 UI Screen 适配器。proc.output 与各项 UI 操作会先校验，再返回 not_implemented。
  • UI 附着请求默认期限为 5000 ms。XU_XACP_REQUEST_TIMEOUT_MS 接受十进制 1..600000，非法值保留默认值。已经执行的工作不会被中断。目标挂起时，调用方仍需进程/I/O 超时。
  • 生成器只接受 hosted native 可执行程序。库、共享对象、测试脚手架、嵌入式目标以及 --desktop 都会被拒绝。
  • 启动器的 record 在 Windows 上仍不可用。该模式录制的是 stdout，不是 ui.record。
