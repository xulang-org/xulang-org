Frequently Asked Questions (FAQ)

What is the Xu programming language?

Xu is a modern statically-typed, ahead-of-time (AOT) compiled systems programming language designed for high-concurrency cloud backends, network infrastructure, and low-latency systems. It combines deterministic RAII ownership (zero GC overhead) with native user-space coroutines (xu f()) and typed channels (chan T).

Does the Xu compiler use LLVM? Why a custom native backend?

No, Xu does not use LLVM. The compiler utilizes a completely self-hosted, custom MIR (Mid-level Intermediate Representation), register allocators, and direct machine code emitters that output native Mach-O, ELF, PE, and WASM binaries. LLVM's massive pass pipeline is the primary cause of slow C++/Rust compile cycles; Xu targets Go-like sub-second compilation speeds, produces a compact single-binary compiler (~15MB), and requires zero external C++ runtime libraries.

Does Xu use a garbage collector (GC)?

No. Xu has zero runtime GC overhead and no Stop-The-World (STW) pauses. Memory is managed deterministically through compile-time single-ownership tracking and RAII scoping drop, complemented by static shared (&T) and exclusive (&mut T) borrow checking to prevent dangling pointers, leaks, and data races.

How does Xu compare to Rust and Go?

Compared to Rust, Xu delivers memory safety and zero runtime overhead without complex lifetime annotations (such as <'a>), offering first-class language-level coroutines and channels without bulky async runtimes. Compared to Go, Xu compiles to true zero-GC native machine code without runtime STW latency, baseline memory bloat, or background GC threads.

How fast are Xu's compilation speed and runtime throughput?

Reproducible performance measurements: compare Xu with C, Rust, Go, and Swift across 47 workloads on six ARM64 and x86-64 platforms. The benchmark dashboard reports per-platform runtime, CPU time, peak memory and binary size; C and Rust use the lowest measured O1–O3 median for each workload. Compilation timings are available in the source CI reports.

Does Xu support WebAssembly (WASM) out of the box?

Yes, first-class native support. The compiler directly emits wasm32 binary modules (xu build --target wasm32) without Emscripten or external dependencies. The interactive in-browser Playground on xulang.org compiles the Xu compiler itself directly to WebAssembly to run lexical analysis, borrow checking, and execution client-side.

Which editors support Xu, and how do I enable LSP?

The official vscode-xu extension supports VS Code and Cursor. It runs xu lsp to launch the SDK's xu-lsp language server for diagnostics, completion, go-to-definition, hover documentation, document symbols, references, rename, and formatting.

Other LSP-compatible editors can configure xu lsp as their server command, communicating over stdin/stdout using JSON-RPC 2.0. The editor normally starts the server automatically; run xu lsp --help for help.

What is the difference between xu get and xu install?

In a project directory containing xu.xun, run xu get github.com/xulang-org/packages@v0.1.1 to add or update a pinned dependency. It edits require:, installs sources into vendor/, and updates xu.lock. An explicit exact version is required; @latest is not accepted.

xu install installs dependencies already declared in the manifest. Both commands support --offline; use xu build . --frozen to build strictly against the existing lockfile. See Modules & Dependencies; the official packages repository provides 29 extension packages.

How do I use xu native to integrate C code?

xu native covers the native module workflow: xu native compile compiles C sources with interface metadata into a .a archive; xu native archive wraps existing object files with metadata; xu native pack bundles target slices into .xulib; xu native inspect and xu native extract inspect and extract slices.

Use .a for a single target, or .xulib to distribute interface contracts with multiple target slices. Pass the library directly to the build, for example xu build main.xu native/mylib.xulib -o app. Compiling C sources requires the corresponding C toolchain. See Native Modules & .xulib for full examples, or run xu native compile --help.

What operating systems and CPU architectures are supported?

Native multi-platform matrix: operating systems include macOS (Darwin), Linux, Windows (PE AOT), and WebAssembly; hardware architectures include ARM64 (Apple Silicon / AWS Graviton), x86-64 (Intel / AMD), LoongArch64, RISC-V 64/32, and Linux ARM32.
