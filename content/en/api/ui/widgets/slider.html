Slider

Adjust a value within a range

Run the Xu example ↗

The example executes in the browser using the Xu/WASM runtime.

What to try

Drag the slider, or use arrow keys after focusing it, to change the value.

Usage notes

Provide minimum, maximum and current values. Choose a useful step and decide whether changes apply during dragging or only on commit.

Create through Screen

The Screen constructor returns a node ID. Pass that ID to Screen layout, state and event APIs. It is separate from the standalone control object documented below.

Native Xu setup fragment: call configure during initialization of an existing Screen. See the complete example for window creation, event dispatch and cleanup.

#ui/widgets

fn configure(screen $&widgets.Screen) int {
    id := screen.slider(0.0,100.0,40.0) or >>
    screen.place(id,24.0,24.0,320.0,80.0) or >>
    << id
}

Placement, state and events

The application owns the component. Screen.place positions nodes; Screen.set_enabled and Screen.set_visible control availability and visibility. Present again after state changes, handle or errors, and keep topology changes outside paint callbacks. ToastHost uses its own queue API.

Standalone control object API

These types and methods support applications that manage control objects, input and painting directly. Their receiver is a control object, not a Screen node ID. For Screen usage, use the constructor above and the Screen methods in the Widgets module.

pub fn (s $&Slider) set_value(value f64) int

Purpose

Set a slider value, constrained by its configured range and step.

Parameters

s $&Slider
The Slider instance used by this call (exclusive borrow).
value f64
Finite value; it is clamped to the range and snapped to the configured step.

  • NaN or infinity throws widgets: invalid slider value.

($&Slider) input

XuAPI
pub fn (s $&Slider) input(input &ui.InputEvent) Action

Purpose

Handle dragging and keyboard adjustments, distinguishing live changes from a final commit.

Parameters

s $&Slider
The Slider instance used by this call (exclusive borrow).
input &ui.InputEvent
Input event for the same window, canvas and generation, with coordinates in the control's canvas space.

Returns

An Action: kind identifies the action, consumed marks a handled event, request_focus requests focus, and needs_paint requests repainting.

Usage notes

  • ACTION_CHANGE reports live changes; ACTION_COMMIT completes an interaction that changed the value. value is current; set_commit_only suppresses live change actions.

($&Slider) set_commit_only

XuAPI
pub fn (s $&Slider) set_commit_only(enabled bool)

Purpose

Emit only final commit actions when applying changes is expensive.

Parameters

s $&Slider
The Slider instance used by this call (exclusive borrow).
enabled bool
true suppresses live ACTION_CHANGE while retaining the final ACTION_COMMIT.

Returns

No return value; setting this clears the current pending-commit flag.

Usage notes

  • The displayed value still updates during dragging; apply expensive work when handling the commit action.
