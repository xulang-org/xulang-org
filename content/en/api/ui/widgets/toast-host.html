ToastHost

Present transient notifications in one place

Run the Xu example ↗

The example executes in the browser using the Xu/WASM runtime.

What to try

Show a notification and dismiss it.

Usage notes

Manage transient notices in one host. Do not expose important errors only through disappearing notifications; keep undo and dismiss actions accessible.

Create the notification queue

ToastHost is a notification queue owned and presented by the application.

#ui/widgets

fn notifications() widgets.ToastHost {
    $host := widgets.toast_host()
    value := widgets.notice(&"Workspace saved")
    host.enqueue(&value) or >>
    << host
}

Placement, state and events

The application owns the component. Screen.place positions nodes; Screen.set_enabled and Screen.set_visible control availability and visibility. Present again after state changes, handle or errors, and keep topology changes outside paint callbacks. ToastHost uses its own queue API.
