#xacp

#xacp is the transport-neutral safety core: frame limits, XUN checks, permissions, and session lifetime. Importing it does not open a control channel. Stdio and loopback TCP are runtime hooks inserted only by xu build --xacp or --xacp-port.

CLI: xu xacp · FAQ · Runnable example

Session

open_session() returns a session in STATE_NEW (0) with PERM_NONE, generation 1, and the next request id 1. close_session moves it to STATE_CLOSED (2), bumps the generation, clears the active request, and drops permissions. STATE_OPEN is 1.

Only one request may be active. begin_request checks authorization and accepts only a positive id equal to next_id, reserves it, and advances the next id. An invalid id returns invalid_request_id; a second active request returns request_in_flight. A non-hello first request closes the session with hello_required. finish_request checks the active id and generation (stale_request on mismatch). A successfully negotiated hello opens the session; an unnegotiated hello cannot open it. Closed sessions return session_closed.

Hello and permissions

Permission changes are host policy. set_permissions succeeds only while the session is still STATE_NEW, and only for bits inside 0..15. Unknown bits are rejected. After a request has been finished, permissions stay as they are.

ConstantValueOperations
PERM_NONE0xacp.hello, and only from STATE_NEW
PERM_INFO1proc.status
PERM_PROCESS2proc.output
PERM_UI_READ4ui.tree, ui.screenshot, ui.record
PERM_UI_MUTATE8ui.input, ui.act
PERM_ALL15development_permissions() and enable_development()

enable_development(s) is an explicit host helper equivalent to set_permissions(s, PERM_ALL). It does not bypass schema checks, session lifetime, native-resource disposal, or limits. Calling it after hello finishes returns false. Startup and attachment servers instead read XU_XACP_TOKEN and call negotiate_hello after a validated hello has begun and before finish_request.

Hello requires ver: !ver 1.0.0 and a non-empty string nonce, which the response echoes. With no host token configured, grants are capped at PERM_INFO, even if the client sends a token. With a host token, missing or mismatched args.token returns auth_failed and closes the session; a matching token allows up to PERM_ALL (15 in this SDK). Optional args.permissions is an !i mask of known bits: the grant is its intersection with the host allowance. Omitting it requests that allowance. Responses include numeric permissions and permission_label (none, info, development, or custom).

Frames and limits

Both transports use XACP/1\n<N>\n followed by exactly N bytes of plain XUN. Header lines end in LF (0x0A); N is a positive ASCII decimal byte count excluding the header. Count UTF-8 bytes, including any newline in the body. There is no closing delimiter or extra separator between frames. The transport strips the prefix and reads exactly N bytes before calling parse_frame(body). That function accepts only the XUN body and rejects an empty body, invalid XUN, or a body above MAX_FRAME_BYTES. validate_request requires a root dictionary containing exactly id, op, and args; id is a positive !i.

default_limits() uses these hard caps. A custom Limits value may only be smaller.

ConstantValue
MAX_FRAME_BYTES1048576 (1 MiB)
MAX_STRING_BYTES65536
MAX_FIELDS64
MAX_TABLE_ROWS10000
MAX_NODE_ID16777215

consume_input and consume_output reject negative counts, single counts above the frame cap, and totals above the session byte budget. The startup reader returns frame_too_large for an oversized body and truncated_frame for EOF inside a header or body. Clean EOF at a frame boundary closes the session. Frame errors use id 0; schema errors use a valid id hint when available, otherwise 0. Frame, schema, and authentication errors close the session.

This hello has a 69-byte body and a 10-byte header (79 bytes total). Every displayed line ends in LF, including the nonce line:

XACP/1
69
id: !i 1
op: xacp.hello
args:
  ver: !ver 1.0.0
  nonce: docs-client

With no host token configured, the matching response has a 109-byte body (120 bytes including its header). The last line again ends in LF. Responses use the same length prefix, with id, ok, and either data or error.code (plus optional error.msg). The next frame starts immediately after the body:

XACP/1
109
id: !i 1
ok: !b true
data:
  state: OPEN
  nonce: "docs-client"
  permissions: !i 1
  permission_label: info

Known operations

The schema allows only these operations. Anything else is an unknown operation.

OpPermissionStartup control channel
xacp.helloPERM_NONE, STATE_NEW onlyToken and permission negotiation before finish. Returns state: OPEN, echoed nonce, numeric permissions, and a permission label.
proc.statusPERM_INFOEmpty args. Returns the real os.getpid() and state: OPEN.
proc.outputPERM_PROCESSSchema-checked (stream is stdout or stderr). Returns not_implemented with no output adapter.
ui.treePERM_UI_READSchema-checked. Returns not_implemented with no Screen adapter.
ui.screenshotPERM_UI_READSame. No live pixels on this channel.
ui.inputPERM_UI_MUTATESame, including after step checks.
ui.actPERM_UI_MUTATESame. Allowed action names in the schema are focus, click, set_text, and set_checked.
ui.recordPERM_UI_READSame. Schema modes are events and frames. This is not the launcher's stdout record mode.

On the startup channel, not_implemented is returned after begin_request, so that id is consumed and the next frame must use the following id. permission_denied is returned before the id advances.

UI control requires an explicit attach_stdio or attach_tcp handle, a live ui/widgets.Screen registered with register_screen, and poll calls from the Screen-owning coroutine between UI event iterations. Business main continues on this path. Unregister before leaving the poll loop. Typed helpers (ui_tree, ui_screenshot, ui_input, ui_act, and recorder helpers) still require the matching permission and check window/node ids, scale (0.1 through 4.0), text, and row/event budgets. A screenshot returns an owning draw.Surface; the caller disposes it. dispatch_screen returns stream_required for ui.record. Startup --xacp-stdio and --xacp-tcp do not register a Screen. End-to-end UI behavior remains unverified.

Transport hooks

src/xacp/stdio.xu is part of the same package, and an --xacp build inserts stdio_preflight(port) at the start of main. That is the control entry. A normal import of #xacp does not emit it.

  • stdio_preflight(port) scans arguments until --. The first of --xacp-tcp or --xacp-stdio wins and exits without running the rest of main. Other launches return and business main runs. They do not listen and do not read control stdin.
  • serve_stdio() reads and writes the process standard streams. Requests and responses use the same XACP/1 length prefix. The session is exclusive. EOF ends the process.
  • serve_tcp(port) listens on 127.0.0.1:port only. The build port must be 1..65535; port 0 disables TCP and this function fails. Each accepted connection gets its own session. Connections are handled one at a time. A failed peer closes that session and the listener keeps accepting. There is no TLS and no other bind address.

--xacp-help is a separate startup print, not a control session. Its capabilities line is stdio. When the build port is 0 it also prints tcp: disabled (port 0). A positive port prints tcp: enabled and bind: 127.0.0.1:PORT. See the CLI reference for launcher modes.

Gaps

  • No TLS.
  • No bind address other than 127.0.0.1.
  • No real UI Screen adapter on the startup channel. proc.output and the UI ops validate, then return not_implemented.
  • UI attachment requests have a default 5000 ms deadline. XU_XACP_REQUEST_TIMEOUT_MS accepts decimal 1..600000; invalid values retain the default. Work already executing is not interrupted. Callers still need process/I/O timeouts for a stalled target.
  • The generator accepts hosted native executables only. It rejects libraries, shared objects, test harnesses, embedded targets, and --desktop.
  • Launcher record is still unavailable on Windows. That mode captures stdout; it is not ui.record.

Use the matching release source and smoke scripts for the contract. Older example README/design notes may describe obsolete framing, permissions, or timeout behavior.

demo #"github.com/xulang-org/examples/ui_demo"

struct Model{
    label_id int
    count int
}

fn (m $&Model) layout(s $&widgets.Screen) int {
    s.place(m.label_id, 32.0, 36.0, 540.0, 44.0) or >>
    << 0
}

fn inspect_screen(s $&widgets.Screen) int {
    $session := xacp.open_session()
    // The in-process adapter follows the current session lifecycle too.
    // This token belongs only to this local demonstration; no listener is opened.
    permissions := xacp.PERM_UI_READ | xacp.PERM_UI_MUTATE
    limits := xacp.default_limits()
    $nonces := xacp.new_nonce_registry(8, true)
    hello := xacp.parse_frame("id: !i 1\nop: xacp.hello\nargs:\n  ver: !ver 1.0.0\n  nonce: local-screen-demo\n  token: local-screen-demo\n  permissions: !i " + str(permissions) + "\n") or(err) {
        xacp.close_session($&session)
        >> err
    }
    opened := xacp.dispatch_with_token($&session, &hello, &limits, "local-screen-demo", $&nonces)
    if !opened.ok{
        xacp.close_session($&session)
        >> errors.new("xacp_screen: " + opened.err_msg)
    }
    tree := xacp.ui_tree(& * s, $&session, 2, false, 0, 32, &limits) or(err) {
        xacp.close_session($&session)
        >> err
    }
    println("XACP ui.tree: " + str(tree.nodes.len) + " visible nodes")
    for node in tree.nodes{
        println("  #" + str(node.id) + " kind=" + str(node.kind) + " " + node.text)
    }

    $snapshot := xacp.ui_screenshot(& * s, $&session, 3, 1.0, &limits) or(err) {
        xacp.close_session($&session)
        >> err
    }
    println("XACP ui.screenshot: " + str(snapshot.pixel_width) + "x" + str(snapshot.pixel_height) + " pixels")
    snapshot.dispose() or(err) {
        xacp.close_session($&session)
        >> err
    }

    _ := xacp.ui_act(& * s, $&session, 2, 4, "focus", "", false, &limits) or(err) {
        xacp.close_session($&session)
        >> err
    }
    xacp.close_session($&session)
    << 0
}

fn scene(events chan ui.Event) int {
    ready := demo.ready(events) or >>
    if ready.kind == ui.EV_EXIT{ << 0}
    $screen := widgets.screen(&ready) or >>
    screen.resize(640.0, 180.0) or >>
    label_id := screen.label("XACP Screen adapter", 22.0, false) or >>
    button_id := screen.button("Activate locally or through ui.act") or >>
    screen.place(label_id, 32.0, 36.0, 540.0, 44.0) or >>
    screen.place(button_id, 32.0, 96.0, 360.0, 40.0) or >>
    inspect_screen($&screen) or(err) {
        screen.dispose()
        >> err
    }
    $model := Model{label_id: label_id, count: 0}
    $actions := widgets.action_dispatcher(&model, &screen)
    actions.on(button_id, widgets.ACTION_ACTIVATE, activate) or >>
    actions.set_fallback(global_key)
    << widgets.run_screen_actions($&screen, events, $&model, layout_action, &actions) or >>
}

fn worker(events chan ui.Event) {
    scene(events) or(err) {demo.fail(err.msg())
        << }
}

fn launch() int {
    $app := demo.app("Xu / XACP Screen adapter", 640, 180) or >>
    xu worker(app.event_ch)
    << app.run() or >>
}

fn main() int {
    << launch() or(err) {eprintln(err.msg())
        << 1}
}
