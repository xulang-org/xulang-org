Xu 0.13.2 — HTTP buffering, socket scheduling, and file I/O

2026-11-22 · Xu v0.13.2

Xu 0.13.2 improves the HTTP and file paths that run for every request. It also changes how the cooperative scheduler waits for sockets when no task is ready to run.

HTTP and file I/O

The HTTP server bounds pending request buffers. The client bounds receive buffers and decodes chunked responses as bytes arrive. Static file handlers can answer HEAD from metadata and read only the bytes needed for a range response.

DirFS reuses available buffer capacity. Whole-file reads check for EOF before growing the buffer, and Windows directory enumeration frees search buffers on both success and failure.

Runtime and strings

The scheduler waits for multiple sockets in one poll when the runnable queue is empty. This release also reduces hash map memory use and reuses AES initialization tables. ARM64 and x64 can scan shorter byte sequences a word at a time, and prefix and suffix checks have a single-byte path. Split strings retain their own bytes when the result slice grows.

Benchmarks and SDK downloads

The official benchmark dashboard is updated with 72 workloads across all six platforms from the verified Actions run. Native SDK installation and execution passed on Linux, macOS, and Windows on ARM64 and x86-64. The Linux LoongArch64 and RISC-V SDKs are cross-built.
