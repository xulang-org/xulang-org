Operating system development

Use Xu's freestanding profile to build kernel, driver, and firmware code with native AOT compilation. The kernel example covers memory layout, hardware I/O, synchronization, interrupts, and task context switching.

Freestanding ELF64 targets are available in the Xu 0.14.0 SDK.

Build the kernel example

Install the Xu SDK and run these commands from the root of the Xu 0.14.0 source checkout.

xu build --profile=freestanding --target=x64-none examples/baremetal/kernel_poc/main.xu -o kernel-x64.elf
xu build --profile=freestanding --target=arm64-none examples/baremetal/kernel_poc/main.xu -o kernel-arm64.elf
xu build --profile=freestanding --target=riscv64-none examples/baremetal/kernel_poc/main.xu -o kernel-riscv64.elf

Use file kernel-*.elf to inspect the output architecture. The kernel example documents its x86-64 QEMU workflow. Match the boot environment, board support, and hardware setup to the target you intend to run.

Hardware access and core APIs

The freestanding profile builds without host operating system services or libc. Source modules can declare $freestanding. For project and compiler settings, see the freestanding profile reference.

  • Use *raw T for hardware addresses and unsafe { … } for raw pointer dereferencing. Use volatile_read and volatile_write for memory-mapped I/O. See the memory model.
  • Use @repr("C", align: N) or @repr("C", packed) for explicit layout when modeling page tables or hardware descriptors.
  • Use #core/arch for architecture-specific control and #core/mem for low-level memory operations. #core/alloc defines allocator interfaces.
  • Use #core/sync for spinlocks and interrupt guards and #core/task for task contexts and trap frames.
