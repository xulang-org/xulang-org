Operating system development

Use Xu's freestanding and UEFI profiles to build kernels, bootloaders, drivers, and firmware with native AOT compilation. The core substrate covers memory layout, hardware I/O, ACPI/FDT/PCI, UEFI, interrupts, and task context switching.

Freestanding ELF64 and UEFI targets are available in the Xu {{xu_version}} SDK.

Build the kernel & UEFI examples

Install the Xu SDK and run these commands from the root of the Xu {{xu_version}} source checkout:

xu build --profile=freestanding --target=x64-none examples/baremetal/kernel_poc/main.xu -o kernel-x64.elf
xu build --profile=freestanding --target=arm64-none examples/baremetal/kernel_poc/main.xu -o kernel-arm64.elf
xu build --profile=freestanding --target=riscv64-none examples/baremetal/kernel_poc/main.xu -o kernel-riscv64.elf
xu build --profile=freestanding --target=x64-uefi --no-sse --stack-size=65536 main.xu -o BOOTX64.EFI
xu build --profile=freestanding --target=arm64-uefi main.xu -o BOOTAA64.EFI

Use file kernel-*.elf to inspect output architectures. The kernel example documents its x86-64 QEMU workflow. Compiler options include --no-sse, --stack-size, and relocatable DWARF debug info.

Hardware access and #core/* APIs

The freestanding profile builds without host operating system services or libc. Source modules can declare $freestanding. For project and compiler settings, see the freestanding profile reference.

  • Use *raw T for hardware addresses and unsafe { … } for raw pointer dereferencing; use volatile_read / volatile_write for MMIO alongside @interrupt, @panic_handler, @weak, @naked, extern static, and parameterized inline assembly. See the memory model.
  • Use @repr("C", align: N) or @repr("C", packed) for explicit layout when modeling page tables and hardware descriptors.
  • Core CPU, memory & concurrency: #core/arch, #core/mem, #core/alloc, #core/sync, #core/task.
  • Firmware, buses & devices: #core/uefi, #core/acpi, #core/pci, #core/fdt, #core/elf, #core/mmio, and VirtIO 1.0 Modern (#core/virtio).
