Native Modules and .xulib Specification

Xu {{xu_version}} · Native C/C++ Interoperability · Multi-Type ABI Mapping · Universal .a and Portable .xulib Slices

In systems programming, integrating with mature C/C++ native codebases is a core requirement. Xu delivers zero-abstraction-overhead, type-safe native interop. Developers often ask: "Why does Xu introduce .xulib alongside standard universal .a (static archive) files?"

This technical guide details Xu's native interop architecture, the distinct roles of universal static archives versus .xulib containers, the complete multi-type ABI mapping table, and the end-to-end 7 development actions.

1. Core Architecture: Universal .a vs .xulib Containers

  • Standard universal .a (Unix static archives) are first-class peers: You can compile a standard .a using any platform C compiler (e.g. clang, gcc, msvc) and link it directly via xu build main.xu module.a or declare it under native: in xu.xun. It is statically linked by the system linker.
  • .xulib is a multi-target slice distribution container: It is not a proprietary machine-code format. Internally, it bundles standard platform .a static slices, augmented by a strongly typed contract (JSON Manifest) and SHA-256 integrity digests.
DimensionUniversal .a Static ArchivePortable .xulib Container
Primary ScopeSingle-target development, local debugging, private C integrationsCross-platform ecosystem packages (e.g. packages/sqlite)
Target ArchitectureSingle OS/Arch slice (e.g. only linux-x64 or macos-arm64)Multi-target, multi-architecture bundle in a single file
Cross-Platform LinkingRequires custom build scripts to branch per OS/ArchCompiler automatically selects and extracts matching slice based on --target
Type SafetyStripped symbol table without parameter/return typesEmbedded JSON Manifest & XUOBJ metadata for compile-time checking
Tamper ProofingNo built-in cryptographic validationEvery target slice records an embedded SHA-256 digest

2. Multi-Type ABI Mapping Matrix

Under the abi: "xu-c-1" protocol, Xu passes scalar values directly through machine general-purpose registers:

f6464-bit float (IEEE-754)Double-precision float passed via scalar register bit pattern. Converted via inline helpers
booluint8_t / boolBoolean flag (1 represents true, 0 represents false)

3. .xulib Binary Layout

.xulib is a self-describing binary container (specification xulib-1):

+-------------------------------------------------------+
| Magic (7B): "XULIB\x01\x00"                           |
+-------------------------------------------------------+
| Version (u16=1) | Flags (u16=0) | Manifest Length (u32)|
+-------------------------------------------------------+
| JSON Manifest (UTF-8 compact text)                    |
|   - module: global module ID (e.g. "native_add")      |
|   - abi: interface version (e.g. "xu-c-1")            |
|   - exports: function signatures, params and returns  |
|   - slices: platform slices metadata & SHA-256 digests|
+-------------------------------------------------------+
| Slice Count (u32)                                     |
+-------------------------------------------------------+
| Slice Index Table (one entry per slice):              |
|   - target_len (u16) + target_name ("macos-arm64")    |
|   - kind_len (u8) + kind ("archive" or "object")      |
|   - file_offset (u64) + file_size (u64)               |
|   - sha256 (32B binary digest)                        |
+-------------------------------------------------------+
| Payload Area:                                         |
|   - Slice 1: Standard Unix .a (Mach-O + xu.o metadata)|
|   - Slice 2: Standard Unix .a (Linux ELF objects)     |
|   - Slice 3: Standard .a / .lib (Windows COFF objects)|
+-------------------------------------------------------+

Clever Dual Compatibility Design: Each platform slice is fundamentally a standard .a static archive. It bundles native business logic objects (e.g. sqlite3.o, bridge.o) compiled by external toolchains (such as C, C++, Rust, or assembly) together with a fully compliant native metadata object member (xu.o). The host platform linker directly links the native machine code symbols, while the Xu compiler inspects the XUOBJ type contract embedded in the dedicated .xumeta section (in Mach-O: __DATA,__xumeta) for compile-time type verification, achieving seamless zero-conflict coexistence.

Action 1: Write C Bridge Source (bridge.c)

Include xu_native.h and wrap export declarations with XU_NATIVE_SYMBOL(...) to reconcile Mach-O leading underscore conventions with ELF/COFF:

#include "xu_native.h"
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

// 1. int (64-bit integer)
xu_int XU_NATIVE_SYMBOL(xu_native_add_add)(xu_int a, xu_int b) {
    return a + b;
}

// 2. f64 (64-bit float bitwise mapping)
static inline double xu_to_double(xu_int bits) {
    double v; memcpy(&v, &bits, sizeof(double)); return v;
}
static inline xu_int double_to_xu(double v) {
    xu_int b; memcpy(&b, &v, sizeof(xu_int)); return b;
}
xu_int XU_NATIVE_SYMBOL(xu_native_add_scale_f64)(xu_int val_bits, xu_int factor_bits) {
    return double_to_xu(xu_to_double(val_bits) * xu_to_double(factor_bits));
}

// 3. bool (boolean)
uint8_t XU_NATIVE_SYMBOL(xu_native_add_is_even)(xu_int n) {
    return (n % 2 == 0) ? 1 : 0;
}

// 4. i32 (32-bit signed int clamp)
int32_t XU_NATIVE_SYMBOL(xu_native_add_clamp_i32)(int32_t val, int32_t min_v, int32_t max_v) {
    if (val < min_v) return min_v;
    if (val > max_v) return max_v;
    return val;
}

// 5. u32 (32-bit unsigned int bitwise rotate)
uint32_t XU_NATIVE_SYMBOL(xu_native_add_rotate_left_u32)(uint32_t val, uint32_t shift) {
    shift &= 31;
    if (shift == 0) return val;
    return (val << shift) | (val >> (32 - shift));
}

// 6. u8 (8-bit unsigned byte mask)
uint8_t XU_NATIVE_SYMBOL(xu_native_add_mask_u8)(uint8_t b, uint8_t mask) {
    return (uint8_t)(b & mask);
}

// 7. void (stateful procedure with side-effects)
static xu_int g_counter = 0;
void XU_NATIVE_SYMBOL(xu_native_add_reset_counter)(void) { g_counter = 0; }
void XU_NATIVE_SYMBOL(xu_native_add_add_to_counter)(xu_int delta) { g_counter += delta; }
xu_int XU_NATIVE_SYMBOL(xu_native_add_get_counter)(void) { return g_counter; }

Action 3: Compile Target Slices (xunative compile)

# macOS Apple Silicon (ARM64)
python3 path/to/xu/scripts/xunative.py compile \
  --manifest native.json --target macos-arm64 bridge.c \
  -o native/native_add-arm64.a

# macOS Intel (x86_64)
python3 path/to/xu/scripts/xunative.py compile \
  --manifest native.json --target macos-x64 bridge.c \
  -o native/native_add-x64.a

Action 4: Pack Multi-Target Archive (xunative pack)

python3 path/to/xu/scripts/xunative.py pack \
  --manifest native.json \
  --slice macos-arm64=native/native_add-arm64.a \
  --slice macos-x64=native/native_add-x64.a \
  -o native/native_add.xulib

Action 5: Declare Native Dependency (xu.xun)

module: my_project
version: !ver 0.1.0
xu: !ver {{xu_version}}

native:
  native_add: file:./native/native_add.xulib

Action 6: Import & Call from Xu Code (main.xu)

@main

#native_add

fn main() int {
    println("=== Xu <-> Native C Multi-Type Interop Demo ===")

    // 1. int
    sum := native_add.add(20, 22)
    println("1. int add(20, 22) = " + str(sum))

    // 2. f64
    scaled := native_add.scale_f64(1.5, 3.0)
    println("2. f64 scale_f64(1.5, 3.0) * 10 = " + str(int(scaled * 10.0)))

    // 3. bool
    println("3. bool is_even(42) = " + str(native_add.is_even(42)))

    // 4. i32
    clamped := native_add.clamp_i32(i32(150), i32(0), i32(100))
    println("4. i32 clamp_i32(150, 0, 100) = " + str(int(clamped)))

    // 5. u32
    rotated := native_add.rotate_left_u32(u32(1), u32(4))
    println("5. u32 rotate_left_u32(1, 4) = " + str(int(rotated)))

    // 6. u8
    masked := native_add.mask_u8(u8(255), u8(15))
    println("6. u8 mask_u8(255, 15) = " + str(int(masked)))

    // 7. void
    native_add.reset_counter()
    native_add.add_to_counter(100)
    c := native_add.get_counter()
    println("7. void state counter = " + str(c))

    println("=== All Native Type Assertions Passed ===")
    << 0
}

5. Frequently Asked Questions (FAQ)

Q: Can I use single-platform .a directly without creating a .xulib?
A: Yes! You can point directly to native_add: file:./native/native_add-arm64.a in xu.xun or pass it on the command line: xu build main.xu ./native/native_add-arm64.a. Ensure the archive contains the xu.o metadata member produced by xunative compile or xunative archive.

Q: Does .xulib introduce any runtime overhead?
A: Zero runtime overhead. .xulib operates purely at compile time. The selected slice is directly fed to the native platform linker, producing an identical static binary with zero runtime wrappers.
