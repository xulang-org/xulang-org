Docs

Install

These docs target Xu {{xu_version}}. Download availability is determined by the actual assets on GitHub Releases.

Use a complete SDK with bin/, src/, and the tools. Standard-library sources are required to compile imports; placing a renamed compiler on PATH alone does not provide a complete development environment.

Install the SDK

Open Releases from the download page and choose a published archive for your host. Unix archives typically use xu-v<version>-<target>.tar.gz; Windows uses .zip. After extracting, run from the SDK root:

# macOS / Linux
./install.sh
# Verify in a new terminal
xu --version
xu doctor
# Windows PowerShell
.\install.ps1
# Verify after restarting PowerShell
xu --version
xu doctor

The default install directory is ~/.xu. On Unix, use ./install.sh --prefix /absolute/path to select a directory, or source env.sh to activate an extracted SDK temporarily. PowerShell uses . .\env.ps1.

Update an installation

With Python 3.9+ installed, run xu up or xu update to download and compile official release sources from GitHub. xu up --check only checks versions; xu update --ref main selects development sources. The compiler, tools and standard library are replaced after the build and runtime checks succeed. See CLI for options.

Verify compilation

xu check hello.xu
xu run hello.xu
xu build hello.xu --output hello

macOS / Linux executables already have execute permission. In PowerShell, prefer --output for output paths.

Environment and source builds

XU_ROOT selects the SDK or compiler checkout; XU_STDLIB_ROOT explicitly selects its src/. XUPATH adds search roots and does not replace external-module require: declarations. Keep xu-fmt, xu-doc, xu-map, xu-doctor, and xu-desktop beside xu in bin.

Sources are in the xu repository. make xu self-hosts with an existing hosted product seed and rebuilds the tools. A clean checkout requires a product seed and the bootstrap companion repository first. packages, examples, and vscode are maintained separately.
