Install

These docs target Xu {{xu_version}}. Download availability is determined by the actual assets on GitHub Releases.

Use a complete SDK with bin/, src/, and the tools. Standard-library sources are required to compile imports; placing a renamed compiler on PATH alone does not provide a complete development environment.

Option 1: Instant Browser Sandbox (Zero Install)

Jump directly into the xulang.org Online Playground. Powered by a client-side WebAssembly build of Xu (running 100% in your browser without server queues), you can test and experiment with full language features instantly.

Option 2: One-Liner Fast Install (Recommended)

Xu provides standalone installer scripts with embedded compilers and standard library sources that automatically register persistent system environment variables:

macOS / Linux (One command in terminal)

# Detects architecture (ARM64 / x86_64), downloads, and configures environment automatically
curl -fsSL https://xulang.org/install.sh | bash

Or download standalone unprivileged CLI installers (self-contained binaries without third-party dependencies) directly from GitHub Releases:

chmod +x xu-setup-linux-x64 && ./xu-setup-linux-x64 -y

Windows (PowerShell or GUI Wizard)

PowerShell One-Liner:

irm https://xulang.org/install.ps1 | iex

Native GUI Wizard:
Download xu-setup-windows-x64.exe from GitHub Releases and double-click to run the zero-dependency self-rendered wizard. Automatically configures user Path and XU_ROOT.

Open a new terminal window and type xu --version to run from anywhere.

Option 3: Standalone Native Installers & Offline SDK Archives

For air-gapped environments, enterprise distribution, or explicit version pinning, download the native installer packages directly:

Offline SDK Archive Installation

If you downloaded a full SDK archive (.tar.gz on Unix or .zip on Windows) from the Download page or GitHub Releases, the native installer is bundled directly at the root:

# Windows: Double-click xu-setup.exe in File Explorer, or in terminal:
.\xu-setup.exe -y

# macOS / Linux: Run xu-setup directly in the extracted directory:
./xu-setup -y

The default installation directory is ~/.xu (macOS .pkg defaults to /usr/local/xu). Use --prefix /custom/path to customize the target directory. In automated CI pipelines, you may also use ./install.sh or .\install.ps1; for temporary evaluation, run source env.sh (or . .\env.ps1 in PowerShell).

Verify Global Environment

After installation, open a new terminal window (CMD, PowerShell, Terminal, or VS Code integrated terminal) and verify that the toolchain is globally active:

xu --version
xu env
xu doctor

Update an installation

Run xu up or xu update to directly download and install the official Release package for your system from GitHub. xu up --check checks for available updates without installing, and xu update --version <version> selects a specific version. Tools and the standard library are replaced after download and verification succeed. See CLI for options.

Verify compilation

xu check hello.xu
xu run hello.xu
xu build hello.xu --output hello

macOS / Linux executables already have execute permission. In PowerShell, prefer --output for output paths.

Environment and source builds

XU_ROOT selects the SDK or compiler checkout; XU_STDLIB_ROOT explicitly selects its src/. XUPATH adds search roots and does not replace external-module require: declarations. Keep xu-fmt, xu-doc, xu-map, xu-doctor, xu-desktop, and xu-lsp beside xu in bin.

Sources are in the xu repository. make xu self-hosts with an existing hosted product seed and rebuilds the tools. A clean checkout requires a product seed and the bootstrap companion repository first. packages, examples, and vscode-xu are maintained separately.
