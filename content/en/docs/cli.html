CLI & Toolchain Reference

Xu {{xu_version}} · Unified single-binary driver xu <command> [options] [arguments]

The xu command line tool uses a unified single-binary driver architecture, integrating the AOT compiler, semantic checker, test runner, dependency package manager, code formatter, documentation extractor, flowchart mapper, LSP daemon, and atomic release updater into a single toolchain. Every command and sibling tool fully supports standard --help and -h structured help output.

1. Compilation & Execution (build / run / check)

Input Rules

  • File input: xu build main.xu. Single or multiple .xu files are compiled directly.
  • Directory input: xu build app/. The target directory must contain a xu.xun manifest; compiles every *.xu in that directory as one unified package (non-recursive).
  • Native archives: Supports passing module.a or module.xulib directly on the CLI to link native module archives.

Build & Optimization Flags

OptionDescription

--no-optDisable all MIR optimizations and default register allocation (disables inlining and reduction) for fastest compile speeds.

Examples

# 1. Compile and execute
xu build main.xu -o myapp
xu run main.xu -- --port 8080 --verbose

# 2. Cross-compile directly to WebAssembly
xu build src/calc.xu --target wasm32 -o dist/calc.wasm

# 3. Production frozen and offline build
xu build . --frozen -o release/server

# 4. View compiler phase breakdown and register allocation metrics
xu build main.xu --timings -o server

Compiler Diagnostics in 0.9.4

Use these environment variables to investigate compilation or optimization problems.

Environment variableBehavior
XU_VERIFY=1Run the full MIR verifier after each optimization pass to check intermediate-representation consistency.
XU_DUMP_MIR=<function>Dump a named function's MIR to inspect lowering and optimization results.
XU_PATTERNS_OFF=allDisable all named backend patterns, or supply a comma-separated list of pattern names. Use for differential comparison with a default build; unknown names are rejected.
# macOS / Linux: verify each pass and inspect pattern hits
XU_VERIFY=1 xu build main.xu --timings -o myapp

# Dump main's MIR
XU_DUMP_MIR=main xu build main.xu -o myapp

# Build a reference executable with backend patterns disabled
XU_PATTERNS_OFF=all xu build main.xu -o myapp-reference

In PowerShell, set the variable first, for example $env:XU_VERIFY = '1', then run the same xu build command. Clear it afterward with Remove-Item Env:XU_VERIFY.

XACP control (xu xacp / xu-xacp)

Documented from the language repository at 0.10.10-dev.1 (xu#23). xu xacp executes the sibling binary xu-xacp (tool module 0.1.1). A source tree builds that binary with make xu-xacp. The published {{xu_version}} download is a separate snapshot. The safety core is #xacp. Importing that package does not embed discovery or a control loop. The runnable sample is examples/xacp in the language repository. examples/xacp/STDIO-CONTROL-DESIGN.md is an earlier note; its “no TCP in this phase” line is superseded.

xu --help summarizes the tool as “inspect, run, and debug”. xu xacp --help is the full mode list: inspect, run, debug, record, control, and connect PORT.

Build and discovery

xu build --xacp examples/xacp/main.xu -o app
xu build --xacp-port 4321 examples/xacp/main.xu -o app
./app --xacp-help

--xacp-port implies --xacp. The generator accepts a hosted native executable only. Libraries, shared objects, test harnesses, embedded targets, and --desktop are rejected. --xacp-help prints and exits. It is not a control session. For port 0 the summary ends with tcp: disabled (port 0). A positive port prints tcp: enabled and bind: 127.0.0.1:PORT. capabilities stays stdio in both cases. Scanning stops at --, so a business argument --xacp-help after that mark does not print discovery.

Launcher modes

ModeWhat it does
xu xacp inspect <program>Runs <program> --xacp-help and prints the discovery text. No business arguments. The target is executed.
xu xacp run <program> -- args...Runs business main. Inserts an extra -- before the forwarded arguments. Does not read control stdin.
xu xacp debug <program> -- args...Inspects first, then runs with the same boundary. Not a breakpoint debugger. A failed inspect does not continue to run.
xu xacp record <program> -- args...Streams at most 1 MiB of stdout. Redirect it yourself. Stderr stays on the terminal. Unix only; Windows prints record is not available on Windows yet and exits 1. This is not an XACP UI frame file.
xu xacp control <program>Spawns <program> --xacp-stdio and inherits the caller's stdin and stdout. No business arguments. Business main does not run. A validated xacp.hello calls enable_development() before the request is finished.
xu xacp connect PORTRelays framed stdin/stdout to 127.0.0.1:PORT. One request, then its response. The target must already be listening with --xacp-tcp. PORT is 1..65535. Input frames end with === and a newline. EOF at a frame boundary disconnects.

Arguments for run, debug, and record must follow the tool's --. inspect and control reject extra arguments. A failing child returns its exit status when the tool can read one.

Stdio and loopback TCP

# stdio: pipe frames; business main is skipped
xu xacp control ./app < control.xun

# TCP: build a positive port, listen, then connect from another terminal
xu build --xacp-port 4321 main.xu -o app
./app --xacp-tcp
xu xacp connect 4321 < control.xun

Both control modes use the same frame, session, and operations. The frame is a XUN document between --- !xacp and ===. The startup reader also requires the newline after ===. The first of --xacp-stdio and --xacp-tcp before -- wins. A normal start does not listen and does not read control stdin.

TCP listens on 127.0.0.1 only. There is no TLS and no other bind address. Each connection is its own session. Connections are handled one at a time. A bad peer ends that session; the listener keeps accepting. Stdio exits when its session ends. A half frame at EOF returns truncated_frame. A frame over 1 MiB returns frame_too_large and closes that session. Invalid frames and schema errors use id 0.

After a validated hello, proc.status returns the real pid. proc.output and ui.tree, ui.screenshot, ui.input, ui.act, and ui.record are validated and return not_implemented until the program registers a Screen or output adapter. There is no host timeout if the target produces no output or does not exit.

2. Automated Testing (test)

xu test discovers and builds automated test runners. Any source file containing fn test_* (or named test.*.xu) runs natively:

OptionDescription
-run <REGEXP>Filter: only run test functions matching the regular expression.
-vVerbose: output execution status and elapsed time for each test function.
-count <N>Repeat the test suite N times (up to 100 times) to diagnose flaky concurrency bugs.
-failfastImmediately stop after the first assertion failure.
-listList matching test names and exit 0 without executing tests.
-shortShort run: sets testing.short() to true to skip expensive integration scenarios.
-bench <REGEXP>Also run performance benchmark functions matching the regex (fn bench_*).
--coverCollect and display basic-block code coverage statistics upon completion.
# Run all tests with timing logs
xu test app/ -v

# Run only networking tests and stop on first error
xu test . -run "net_.*" -failfast

# Execute SHA-256 benchmarks
xu test . -bench "bench_sha256"

3. Project Initialization & Dependency Management (init / get / install)

The 0.8.x series delivers a reproducible, hermetic project management and package resolution model:

xu init [module]: Initialize Manifest & Entry

Quickly bootstrap a standardized Xu project in the current working directory:

# 1. Initialize using current directory name as module name
xu init

# 2. Explicitly specify module name
xu init myapp
  • Automatic Manifest Generation: Generates a canonical xu.xun file with the current compiler version pinned (e.g. xu: !ver {{xu_version}}). If xu.xun already exists, execution halts with an error to prevent overwriting.
  • Starter Entry Source: If main.xu is absent in the directory, creates a clean starter Hello World file.
  • Ready to Run: Execute xu run . immediately after initialization to compile and run in milliseconds.

xu get <module>@<version> (New in 0.8.12)

Explicitly add or update a dependency root in the current project:

xu get github.com/xulang-org/packages@v0.1.1
  • Explicit versions required: Must specify a strict SemVer tag (e.g. @v0.1.1); rejects @latest or open ranges to ensure reproducibility.
  • Transactional safety: Updates require: in xu.xun, resolves dependencies, downloads sources to vendor/, verifies SHA-256 digests, and writes xu.lock. If network or checksum validation fails, it automatically rolls back with zero project corruption.
  • Offline resolution: Supports xu get <module>@<version> --offline using existing local caches.

xu install [dir]

Populate and verify the entire vendor tree matching the project's xu.xun:

xu install                      # Install dependencies for current directory
xu install --offline            # Offline mode: use local cache (~/.xu/pkg) only

See Official Packages Catalog and Modules and Dependency Specifications.

4. Code Quality & Documentation (fmt / doc / map)

xu fmt: Code Formatting

xu fmt src/main.xu -w           # Rewrite single file in place
xu fmt src/ -w                  # Recursively format all .xu sources in src/
xu fmt main.xu                  # Emit formatted result to stdout without file writes

xu doc: API Extraction & Web Server

# 1. Extract public API signatures into Markdown
xu doc src/net --public -o docs/net.md

# 2. Launch built-in XUDOCS Web documentation preview (defaults to 127.0.0.1:6060)
xu doc src/ --serve --addr 127.0.0.1:8080

The --serve HTTP server provides interactive navigation at /, raw Markdown at /docs.md, and a /health probe endpoint.

xu map: Code Topologies & Call Graphs

# Generate Mermaid flowchart diagram
xu map src/main.xu -o flow.mmd

# Output machine-parseable node and edge data lines for custom visualizers
xu map src/ --graph

5. System Maintenance & Updates (doctor / setup / update)

xu doctor: Diagnostics

xu doctor                       # Check host linkers and toolchain health
xu doctor --desktop             # Verify desktop packaging dependencies (WebKitGTK, GTK4, WebView2, MinGW)

xu setup: Native Installer

The companion xu-setup utility includes a self-rendering GUI installer and silent console modes:

xu setup -y                     # Silent automated install to global PATH and XU_ROOT
xu setup --prefix /opt/xu -y   # Install into a custom target directory
xu setup --cli                  # Force CLI interactive mode on headless servers

xu up / xu update: Official Release Updates

Upgrade the xu toolchain and standard library atomically from official GitHub Releases:

xu up --check                   # Check if a new official release is available
xu up                           # Upgrade to the latest stable release
xu update --version {{xu_version}}        # Pin or downgrade to a specific version
xu update --force               # Reinstall the current version

6. Native C Modules & Packaging (xu native)

The companion tool xu-native is integrated as a first-class subcommand xu native, providing native C bridge building, metadata injection, and multi-slice container bundling without external scripts:

# 1. Compile C sources and inject .xumeta into an archive slice (.a)
xu native compile --manifest native.json --target macos-arm64 bridge.c -o native/native_add-arm64.a

# 2. Bundle multi-target slices into a portable container (.xulib)
xu native pack --manifest native.json --slice macos-arm64=native/native_add-arm64.a --slice macos-x64=native/native_add-x64.a -o native/native_add.xulib

# 3. Inspect .xulib slice architectures, sizes, and SHA-256 digests
xu native inspect native/native_add.xulib

# 4. Extract a target slice from a .xulib container
xu native extract native/native_add.xulib --target macos-arm64 -o slice.a

8. Language Server Protocol & IDEs (xu lsp)

The companion tool xu-lsp implements the standard Language Server Protocol (JSON-RPC 2.0) over stdin/stdout, integrating with modern editors (VS Code, Cursor, Neovim, Helix, etc.):

# Start the LSP server daemon (usually managed by editor extensions)
xu lsp

# Show LSP options and flags
xu lsp --help

Core capabilities: realtime syntax & borrow diagnostics, F12 / Cmd+Click jump to definition, Markdown hover documentation, document symbol outline (Cmd+Shift+O), smart completion, find all references (Shift+F12), and symbol rename (F2). See VS Code / Cursor Guide.

Source debugging (0.10.5)

xu debug builds a DWARF-enabled executable and launches the host LLDB/GDB; install a debugger first. Use --break for a source-line or function breakpoint, --eval for a debugger command, --batch for batch operation, or --binary to inspect an existing executable.

xu debug --help
xu debug --break main.xu:8 --run main.xu
xu debug --binary ./app --batch --eval "image lookup -n main"
