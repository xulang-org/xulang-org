Build and run the local LLM engine

examples/llm_engine/main.xu is a self-contained Transformer, DeepSeek MLA, and Mixture-of-Experts (MoE) inference and fine-tuning engine supporting HuggingFace model directories (config.json + single model.safetensors or sharded model.safetensors.index.json + tokenizer.json / tokenizer_config.json with F32/F16/BF16/F8_E4M3 tensors), single-file Safetensors, PEFT LoRA adapters (--lora <dir_or_safetensors> & --lora-scale across q/k/v/o/w1/w2/w3/lm_head in F32/F16/BF16, plus a pure-Xu train-lora subcommand using #tensor backprop, --max-grad-norm L2 gradient clipping, and adamw_step_f32 with SafeTensors export), lossless speculative decoding (--draft <model> / --draft-k <N> with batched verification and exact KV-cache rollback), and GGUF v2/v3 (mixed-quantization Q4_K_M & Q5_K with Q4_K/Q5_K/Q6_K + --q8k-act integer K-quant activation dots, plus F32, F16, BF16, FP8 E4M3, Q4_0, Q5_0, Q8_0 layer weights packed to p4k4 SIMD, and zero-copy #tensor compacted weights), DeepSeek-V2/V3/R1 Multi-head Latent Attention (MLA) (kv_lora_rank, q_lora_rank, qk_nope_head_dim, qk_rope_head_dim, v_head_dim), full MoE routing & shared experts, YaRN NTK-by-parts RoPE scaling, Gemma-2/Qwen3 extensions, auto-detected chat templates (ChatML, Llama-3, Gemma, Mistral) with multi-turn tool formatting, compact paged KV caches, SentencePiece + GPT-2 BPE merges, $O(L)$ sampling with logit_bias, and a multi-slot continuous-batching #net/http server exposing OpenAI endpoints (/v1/completions, /v1/chat/completions with <think> reasoning_content sync+SSE and SSE delta.tool_calls, stateful POST /v1/responses supporting instructions, previous_response_id, max_output_tokens, tools/function_call_output, and SSE events, and batch /v1/embeddings) alongside Anthropic Messages API /v1/messages (sync+SSE, x-api-key auth).

./bin/xu build --tensor-fusion --tensor-fast-math examples/llm_engine/main.xu -o llm_engine
# (or XU_TENSOR_FUSION=1 XU_TENSOR_FAST_MATH=1 ./bin/xu build ...)

# Verify sequential vs continuous-batching parity with FP8 KV cache
./llm_engine verify model.gguf --kv-dtype fp8_e4m3fn

# Generate text with BPE merges, LoRA adapter, lossless draft speculative decode, and penalties
./llm_engine generate model.gguf "Hi Paris" 64 700 40 \
  --kv-dtype f16 --top-p 900 --min-p 50 --repeat-penalty 1100 \
  --presence-penalty 100 --frequency-penalty 50 --seed 42
./llm_engine generate model.gguf "Hi Paris" 64 0 40 --lora ./lora_adapter --draft ./draft.gguf --draft-k 4

# Pure-Xu LoRA adapter training with #tensor backprop + grad clipping + AdamW + SafeTensors export
./llm_engine train-lora model.safetensors "1,2,3,4,5" ./out_lora --lora-rank 4 --steps 20 --lr 0.05 --max-grad-norm 1.0

# Start an OpenAI-compatible HTTP server (/health, /v1/models, /v1/completions, /v1/chat/completions, /v1/responses, /v1/embeddings)
# Supports SSE streaming ("stream": true, "stream_options": {"include_usage": true}), batch embeddings, CORS, and Bearer auth
./llm_engine serve model.gguf 127.0.0.1:8080 --kv-dtype bf16 --max-slots 4 --api-key secret

Supported CLI flags across modes:

  • --ctx <N> — override maximum sequence length / context window.
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> — choose paged KV-cache storage precision (halving or quartering KV memory).
  • --lora <path>, --lora-scale <f>, --lora-rank <N>, --lora-alpha <f>, --steps <N>, --lr <f>, --max-grad-norm <f> — load PEFT SafeTensors LoRA adapters for inference or train/export LoRA weights via pure-Xu train-lora with L2 gradient clipping.
  • --draft <model>, --draft-k <N> — enable lossless target-verified speculative decoding with exact KV rollback across greedy and stochastic sampling.
  • --top-p <milli>, --min-p <milli>, --repeat-penalty <milli>, --presence-penalty <milli>, --frequency-penalty <milli>, --seed <int> — deterministic filtering and repetition/presence/frequency penalties (1000 = 1.0; unbounded top_k supported).
  • --max-slots <N>, --api-key <K> — configure concurrent continuous-batching scheduler slots and optional Bearer authentication (excluding /health) in serve mode.
  • --rope-type <auto|norm|neox> — select RoPE pairing layout (norm interleaved pairs vs split-half NeoX; auto-detected from GGUF/architecture).
  • --ignore-eos — continue generation past EOS stop tokens for fixed-length evaluation.

@main
#tensor

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

Compiler options & MIR tensor fusion

When building with --tensor-fusion (or XU_TENSOR_FUSION=1), the compiler's MIR tensor-lowering pass pattern-matches idiomatic pure-Xu numerical loops (including the primitives in #tensor and custom kernels in user code) and lowers them directly into hand-tuned ARM64 NEON / SDOT and x86-64 SSE2 / SSSE3 runtime kernels, while keeping the frozen C/runtime ABI unchanged:

Kernel familyMIR runtime symbol(s)Hardware instructions
Vector ops __xu_tensor_dot_f32, __xu_tensor_axpy_f32, __xu_tensor_vadd_inplace_f32, __xu_tensor_vsub_f32, __xu_tensor_vmul_f32 ARM64 NEON fmul.4s/fmla.4s/fsub.4s; x64 SSE2 mulps/addps/subps
Norms & activation __xu_tensor_add_sqsum_f32, __xu_tensor_norm_f32, __xu_tensor_swiglu_f32, __xu_tensor_softmax_scaled_f32 Vectorized variance/exp reductions across hidden dimensions
Dense & quantized GEMV/GEMM __xu_tensor_gemv4_f32, __xu_tensor_gemm4x4_f32, __xu_tensor_gemv4_q4_0_p4k4_signed_f16_q8_0_f32, __xu_tensor_gemm4x8_q8_0_p4k4_f16_q8_0_f32 4×8 tiled microkernels with ARM64 sdot.4s & x64 SSE2/SSSE3 parity

  • --tensor-fusion / XU_TENSOR_FUSION=1 — enable pattern-matched SIMD / quantized matrix lowering (verified bit-exact in fusion-strict mode).
  • --tensor-fast-math / XU_TENSOR_FAST_MATH=1 — unlock fast reassociated reductions, fast exponential approximations, and unrolled sdot pipelines.

GPU compute via packages/metal

For Apple Silicon GPUs, the official packages/metal (v1.9.0, exporting 176 native symbols across all 6 .xulib slices) module provides F32Matrix, F16Matrix (MPSDataTypeFloat16), raw byte uploads (write_bytes), and six quantized matrix formats — Q4Matrix (matrix_q4_0), Q5Matrix (matrix_q5_0), Q8Matrix (matrix_q8_0), Q4KMatrix (matrix_q4_k), Q5KMatrix (matrix_q5_k), and Q6KMatrix (matrix_q6_k) — with limits raised to 262,144 per dimension / 536,870,912 cells, read/write lock separation for concurrent readers, and multi-op Batch command encoding synchronized with non-blocking Fence handles and compile-time borrow + runtime shape/alias/device guards:

@main
metal #"github.com/xulang-org/packages/metal"
#errors

fn gpu_ffn_batch(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                 w_gate &metal.Q4Matrix, w_up &metal.Q4Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>

    $b := d.begin_batch() >>>
    _ := b.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := b.gemv_q4_0_f32($&g, &normed, w_gate) >>>
    _ := b.gemv_q4_0_f32($&u, &normed, w_up) >>>
    _ := b.swiglu_f32($&out, &g, &u) >>>
    $f := b.commit() >>>
    _ := f.wait() >>>
    << out
}
