AI development and local inference

The Xu compiler can recognize numerical loops and lower them to native CPU kernels. The llm_engine example uses these kernels for local language-model inference in pure Xu.

Available in Xu 0.14.1. Build with the compiler and standard library from the Xu 0.14.1 SDK or matching source checkout.

Build and run the example

From the Xu 0.14.1 source checkout, set XU to your installed or built compiler and run the following from the repository root. Choose token IDs from your model's vocabulary.

XU_STDLIB_ROOT="$PWD/src" XU_TENSOR_FUSION=1 "$XU" build examples/llm_engine/main.xu -o llm_engine

On macOS ARM64, sign the executable locally with codesign -fs - ./llm_engine before running it.

./llm_engine generate ./model.gguf 'ids:1,7,42' 16 0 40 --ctx 128

The example loads compatible GGUF v2/v3 models with F32/F16 or Q4_0 layer weights and an F32/F16, Q4_0 or Q8_0 output projection. It also loads the F32 Safetensors layout used by the test fixture. The maximum model width is 2048. GGUF loading streams weights from the local file. A paged key/value cache serves prompt prefill and token decoding, and the example includes a coroutine scheduler for continuous batching.

  • generate MODEL PROMPT [MAX_TOKENS] [TEMP_MILLI] [TOP_K] accepts text or ids: followed by comma-separated token IDs. Text uses greedy vocabulary matching. Supply explicit IDs for exact tokenization. Temperature 0 selects greedy decoding.
  • verify MODEL compares sequential and batched results and checks that KV pages return to the pool. verify-f32act uses F32 activations.
  • bench MODEL [STEPS] [single] [PROMPT_LEN] measures load, prefill and decode. single skips continuous-batch timing. bench-f32act uses F32 activations.

Use a positive --ctx N to cap the model context. The default cap is 512 tokens. Generation stops at EOS unless you pass --ignore-eos.

Compiler options

XU_TENSOR_FUSION=1 enables loop pattern matching when building an optimized native ARM64 or x64 executable. Eligible patterns include quantized matrix-vector and matrix-matrix multiplication, RMSNorm, RoPE, and paged attention. Kernel selection depends on the operation, layout and target. XU_TENSOR_FAST_MATH=1 additionally permits eligible kernels to reassociate floating-point operations or fuse multiply and add. Builds with fast math can produce different low bits.

Express the numerical work as Xu loops. The compiler emits and calls its own __xu_tensor_* helpers.

Verify and measure inference

The regression suite generates compatible test models and compares float and quantized inference against a reference implementation. It also checks batched prefill, decoded tokens, and KV page reuse.

python3 scripts/test_llm_engine.py --compiler "$XU"
python3 scripts/test_tensor_opt.py --compiler "$XU"

Use the example's bench mode to measure an individual model. Record the model and quantization, CPU, context length, and compiler settings with the prefill and decode results.

Numerical and slice APIs

  • math.float16_to_f32(h int) f32 converts a binary16 bit pattern to f32.
  • slice.reserve(n int) ensures capacity for at least n elements.
  • slice.resize_zero(n int) sets the length of a mutable primitive slice and zero-initializes newly visible elements.
