Build and run the local LLM engine

examples/llm_engine/main.xu is a self-contained Transformer inference engine supporting Safetensors and GGUF v2/v3 (mixed-quantization Q4_K_M with Q4_K/Q6_K, plus F32, F16, BF16, FP8 E4M3, Q4_0, Q5_0, Q8_0, and zero-copy compacted weights / p4k4 layouts), reading GGUF metadata (rope_freq_scale, logit_softcap, tokenizer model/architecture, and chat templates). It supports Qwen3/Gemma2 per-head qk_norm, auto-detected chat templates (ChatML, Llama-3, Gemma, Mistral) with multi-EOS stopping, compact paged KV caches (--kv-dtype f32|f16|bf16|fp8_e4m3fn), hidden dimensions beyond 2048, SentencePiece (▁ / <0xHH>) + GPT-2 pre-tokenization & BPE merges, $O(L)$ sampling (top_k, top_p, --min-p, --repeat-penalty, --presence-penalty, --frequency-penalty), and a multi-slot continuous-batching #net/http OpenAI server with batched ARM64 decode, SSE client-disconnect cancellation, Prefix KV Cache reuse, batch /v1/embeddings, stream_options.include_usage, CORS preflight, --api-key auth, and --max-slots.

./bin/xu build --tensor-fusion --tensor-fast-math examples/llm_engine/main.xu -o llm_engine
# (or XU_TENSOR_FUSION=1 XU_TENSOR_FAST_MATH=1 ./bin/xu build ...)

# Verify sequential vs continuous-batching parity with FP8 KV cache
./llm_engine verify model.gguf --kv-dtype fp8_e4m3fn

# Generate text with BPE merges, min-p / top-p sampling, and penalties
./llm_engine generate model.gguf "Hi Paris" 64 700 40 \
  --kv-dtype f16 --top-p 900 --min-p 50 --repeat-penalty 1100 \
  --presence-penalty 100 --frequency-penalty 50 --seed 42

# Start an OpenAI-compatible HTTP server (/health, /v1/models, /v1/completions, /v1/chat/completions, /v1/embeddings)
# Supports SSE streaming ("stream": true, "stream_options": {"include_usage": true}), batch embeddings, CORS, and Bearer auth
./llm_engine serve model.gguf 127.0.0.1:8080 --kv-dtype bf16 --max-slots 4 --api-key secret

Supported CLI flags across modes:

  • --ctx <N> — override maximum sequence length / context window.
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> — choose paged KV-cache storage precision (halving or quartering KV memory).
  • --top-p <milli>, --min-p <milli>, --repeat-penalty <milli>, --presence-penalty <milli>, --frequency-penalty <milli>, --seed <int> — deterministic filtering and repetition/presence/frequency penalties (1000 = 1.0; unbounded top_k supported).
  • --max-slots <N>, --api-key <K> — configure concurrent continuous-batching scheduler slots and optional Bearer authentication (excluding /health) in serve mode.
  • --ignore-eos — continue generation past EOS stop tokens for fixed-length evaluation.

Compiler options & MIR tensor fusion

When building with --tensor-fusion (or XU_TENSOR_FUSION=1), the compiler's MIR tensor-lowering pass pattern-matches idiomatic pure-Xu numerical loops (including the primitives in #tensor and custom kernels in user code) and lowers them directly into hand-tuned ARM64 NEON / SDOT and x86-64 SSE2 / SSSE3 runtime kernels, while keeping the frozen C/runtime ABI unchanged:

Kernel familyMIR runtime symbol(s)Hardware instructions
Vector ops __xu_tensor_dot_f32, __xu_tensor_axpy_f32, __xu_tensor_vadd_inplace_f32, __xu_tensor_vsub_f32, __xu_tensor_vmul_f32 ARM64 NEON fmul.4s/fmla.4s/fsub.4s; x64 SSE2 mulps/addps/subps
Norms & activation __xu_tensor_add_sqsum_f32, __xu_tensor_norm_f32, __xu_tensor_swiglu_f32, __xu_tensor_softmax_scaled_f32 Vectorized variance/exp reductions across hidden dimensions
Dense & quantized GEMV/GEMM __xu_tensor_gemv4_f32, __xu_tensor_gemm4x4_f32, __xu_tensor_gemv4_q4_0_p4k4_signed_f16_q8_0_f32, __xu_tensor_gemm4x8_q8_0_p4k4_f16_q8_0_f32 4×8 tiled microkernels with ARM64 sdot.4s & x64 SSE2/SSSE3 parity
Paged attention & RoPE __xu_tensor_rope_f32, __xu_tensor_attn_scores_paged_f32, __xu_tensor_attn_vsum_paged_f32 Supports head_dim % 4 == 0 (64, 128, 40, ...) across ARM64 & x64
  • --tensor-fusion / XU_TENSOR_FUSION=1 — enable pattern-matched SIMD / quantized matrix lowering (verified bit-exact in fusion-strict mode).
  • --tensor-fast-math / XU_TENSOR_FAST_MATH=1 — unlock fast reassociated reductions, fast exponential approximations, and unrolled sdot pipelines.

GPU compute via packages/metal

For Apple Silicon GPUs, the official packages/metal (v1.4.0) module provides F32Matrix, F16Matrix (MPSDataTypeFloat16), raw byte uploads (write_bytes), and quantized buffers — Q4Matrix (matrix_q4_0), Q8Matrix (matrix_q8_0), and Q4KMatrix (matrix_q4_k) — with limits raised to 262,144 per dimension / 536,870,912 cells, read/write lock separation for concurrent readers, and multi-op Batch command encoding synchronized with non-blocking Fence handles and compile-time borrow + runtime shape/alias/device guards:

@main
metal #"github.com/xulang-org/packages/metal"
#errors

fn gpu_ffn_batch(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                 w_gate &metal.Q4Matrix, w_up &metal.Q4Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>

    $b := d.begin_batch() >>>
    _ := b.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := b.gemv_q4_0_f32($&g, &normed, w_gate) >>>
    _ := b.gemv_q4_0_f32($&u, &normed, w_up) >>>
    _ := b.swiglu_f32($&out, &g, &u) >>>
    $f := b.commit() >>>
    _ := f.wait() >>>
    << out
}

Available GPU ops across standalone dispatches and Batch methods: gemm_f32, gemm_f32_nt, rmsnorm_f32, layernorm_f32, softmax_f32, gelu_f32, swiglu_f32, add_f32, mul_f32, scale_f32, rope_f32, qk_norm_f32, kv_cache_append_f32, attention_decode_f32, causal_attention_f32, embedding_f32, argmax_f32, gemm_f16, gemm_f16_nt, f16_to_f32, f32_to_f16, and fused quantized GEMV kernels (gemv_q4_0_f32, gemv_q8_0_f32, gemv_q4_k_f32) computing $x \cdot \mathrm{dequant}(W)^T$ on-the-fly in GPU registers for full end-to-end GPU Transformer decoding.

OpenAI SDK, MCP, vector databases & agent automation

Beyond tensor kernels and local inference, the Xu ecosystem includes pure-Xu client/server packages and built-in compiler protocols for complete AI applications:

  • OpenAI & MCP (packages): github.com/xulang-org/packages/openai provides a typed pure-Xu OpenAI-compatible client (list_models, chat, chat_stream / chat_stream_chan SSE streaming, tool calling, and embeddings), while github.com/xulang-org/packages/mcp implements Model Context Protocol JSON-RPC 2.0 (2025-03-26) for both stdio servers and Streamable HTTP JSON/SSE clients (tools, resources, prompts).
  • Vector databases (packages): native Xu clients for qdrant, milvus, and chroma over HTTP/gRPC transports, enabling RAG pipelines compiled into a single static binary.
  • Agent automation (XACP & #xacp API): structured capability introspection, bounded event/frame recording, and audited UI interaction for local desktop applications built with Xu.
