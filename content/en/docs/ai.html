Build and run the local LLM engine (llm_engine)

examples/llm_engine/main.xu modularizes model loaders, vision projectors, GBNF grammars, and quantization into pure-stdlib subpackages (models, vision, gbnf, quantize) while preserving all MIR tensor-fusion kernels in main.xu. Since Xu v0.14.3+ embeds Mach-O LC_CODE_SIGNATURE ad-hoc signing directly on Apple Silicon builds, no manual codesign step is required.

Common CLI flags across modes:

  • --threads <N>, --ctx <N>, --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> — control multi-threaded CPU execution, context window, and paged KV-cache storage precision.
  • --grammar <path_or_inline>, --json-schema <path_or_json>, --gbnf-max-branches <N> — constrain decoding via VocabIndex Trie grammars or JSON Schema with tunable NFA branch bounds.
  • --mmproj <path>, --image <path|url|data_uri|rgb:...> — attach mmproj.gguf or SafeTensors vision encoders with inline <image> interleaving.
  • --draft <model>, --draft-k <N>, --lora <path>, --lora-scale <f> — combine lossless target-verified speculative decoding and LoRA adapters.
  • --top-p <milli>, --min-p <milli>, --repeat-penalty <milli>, --presence-penalty <milli>, --frequency-penalty <milli>, --seed <int>, --rope-type <auto|norm|neox>, --ignore-eos — sampling penalties (1000 = 1.0), RoPE layout, and stop control.
  • --max-slots <N>, --api-key <K>, --models-dir <dir>, --stride <N> — continuous-batching slots, Bearer auth, cache path, and perplexity stride.

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

Compiler options & MIR tensor fusion

When building with --tensor-fusion (or XU_TENSOR_FUSION=1), the compiler's MIR tensor-lowering pass pattern-matches idiomatic pure-Xu numerical loops (including the primitives in #tensor and custom user kernels) and lowers them directly into hand-tuned ARM64 NEON / SDOT and x86-64 SSE2 / SSSE3 runtime kernels (including v0.14.3 K-quant SIMD kernels), while keeping the frozen runtime ABI unchanged:

Kernel familyMIR runtime symbol(s)Hardware instructions
Vector ops __xu_tensor_dot_f32, __xu_tensor_axpy_f32, __xu_tensor_vadd_inplace_f32, __xu_tensor_vsub_f32, __xu_tensor_vmul_f32 ARM64 NEON fmul.4s/fmla.4s/fsub.4s; x64 SSE2 mulps/addps/subps
Norms & activation __xu_tensor_add_sqsum_f32, __xu_tensor_norm_f32, __xu_tensor_swiglu_f32, __xu_tensor_softmax_scaled_f32 Vectorized variance/exp reductions across hidden dimensions
Dense & quantized GEMV/GEMM __xu_tensor_gemv4_f32, __xu_tensor_gemm4x4_f32, __xu_tensor_gemv4_q4_0_p4k4_signed_f16_q8_0_f32, __xu_tensor_gemm4x8_q8_0_p4k4_f16_q8_0_f32 + K-quant SIMD 4×8 tiled microkernels with ARM64 sdot.4s & x64 SSE2/SSSE3 parity plus K-quant SIMD dot paths

  • --tensor-fusion / XU_TENSOR_FUSION=1 — enable pattern-matched SIMD / quantized matrix lowering (verified bit-exact in fusion-strict mode).
  • --tensor-fast-math / XU_TENSOR_FAST_MATH=1 — unlock fast reassociated reductions, fast exponential approximations, and unrolled sdot pipelines.

Known Limitations & Engineering Trade-offs

Developer caveat: Xu's AI stack optimizes for zero external C/C++ inference bindings and compact standalone binaries, which carries explicit scope limits:

  • llm_engine is multi-threaded CPU-only (use llm_metal / gpu for GPU): examples/llm_engine supports multi-threaded CPU execution via --threads N without calling CUDA or Metal directly; end-to-end Apple Silicon GPU LLM inference lives in packages/llm_metal, and cross-backend GPU kernels live in packages/gpu (metal / cuda_native / vulkan_native / CPU fallback).
  • Quantization, training & media bounds: GGUF supports F32/F16/BF16/FP8/Q4_0/Q4_1/Q5_0/Q5_1/Q8_0 and K-quants (Q2_K–Q8_K), while imatrix IQ1–IQ4 formats are unsupported; llm_engine train-* and llm_metal.train_lora_step focus on single-node f32 LoRA fine-tuning/alignment rather than distributed pretraining; image decoding covers PNG, JPEG, PPM, and uncompressed 24-bit BMP (no WebP/AVIF/HEIC).
  • Vector store scale & production gateway notes: rag.SqliteVectorStore caches rows in memory for exact $O(N)$ scoring (best under ~10k chunks; use pooled PgVectorPool HNSW or QdrantVectorStore beyond that); gateway supports Redis-backed shared state in v1.16.0+, while SSE failover still applies only before the first chunk arrives; terminate TLS/RBAC in front of a2a and pair guardrails.strict_policy with check_safety_openai in high-risk flows.
  • Built-in Apple Silicon signing: Since Xu v0.14.3, xu build embeds Mach-O LC_CODE_SIGNATURE ad-hoc signatures automatically—no manual codesign step is required before running generated binaries.
