Build and run the local LLM engine

examples/llm_engine/main.xu is a self-contained Transformer inference engine supporting Safetensors and GGUF v3 (F32, F16, BF16, FP8 E4M3, Q4_0, Q8_0 weights plus packed p4k4 weight layouts). It uses #tensor for mixed-precision weight arenas and compact paged KV caches (--kv-dtype f32|f16|bf16|fp8_e4m3fn), supports arbitrary hidden dimensions past 2048, decodes GPT-2 byte-level tokens and tokenizer.ggml.merges BPE merges, and embeds a concurrent #net/http OpenAI-compatible server.

XU_TENSOR_FUSION=1 XU_TENSOR_FAST_MATH=1 ./bin/xu build examples/llm_engine/main.xu -o llm_engine

# Verify sequential vs continuous-batching parity with FP8 KV cache
./llm_engine verify model.gguf --kv-dtype fp8_e4m3fn

# Generate text with BPE merges, nucleus sampling, and repeat penalty
./llm_engine generate model.gguf "Hi Paris" 64 700 40 \
  --kv-dtype f16 --top-p 900 --repeat-penalty 1100 --seed 42

# Start an OpenAI-compatible HTTP server (/health, /v1/models, /v1/completions, /v1/chat/completions, /v1/embeddings)
# Supports SSE streaming ("stream": true) and custom "stop" sequences
./llm_engine serve model.gguf 127.0.0.1:8080 --kv-dtype bf16

Supported CLI flags across modes:

  • --ctx <N> — override maximum sequence length / context window.
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> — choose paged KV-cache storage precision (halving or quartering KV memory).
  • --top-p <milli>, --repeat-penalty <milli>, --seed <int> — deterministic nucleus filtering and repetition penalty controls (1000 = 1.0).
  • --ignore-eos — continue generation past eos_token_id for fixed-length evaluation.

Compiler options & MIR tensor fusion

When building with XU_TENSOR_FUSION=1, the compiler's MIR tensor-lowering pass pattern-matches idiomatic pure-Xu numerical loops (including the primitives in #tensor and custom kernels in user code) and lowers them directly into hand-tuned ARM64 NEON / SDOT and x86-64 SSE2 / AVX2 runtime kernels, while keeping the frozen C/runtime ABI unchanged:

Norms & activation __xu_tensor_add_sqsum_f32, __xu_tensor_norm_f32, __xu_tensor_swiglu_f32, __xu_tensor_softmax_scaled_f32 Vectorized variance/exp reductions across hidden dimensions

  • XU_TENSOR_FUSION=1 — enable pattern-matched SIMD / quantized matrix lowering (verified bit-exact in fusion-strict mode).
  • XU_TENSOR_FAST_MATH=1 — unlock fast reassociated reductions, fast exponential approximations, and unrolled sdot pipelines.

GPU compute via packages/metal

For Apple Silicon GPUs, the official packages/metal module provides explicit binary32 GPU matrix buffers (F32Matrix), Metal Performance Shaders matrix multiplications, and compiled Metal compute shaders synchronized with non-blocking Fence handles and compile-time borrow + runtime shape/alias/device checks:

@main
metal #"github.com/xulang-org/packages/metal"
#errors

fn gpu_ffn_step(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                w_gate &metal.F32Matrix, w_up &metal.F32Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    f_rms := metal.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := f_rms.wait() >>>

    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    f_g := metal.gemm_f32_nt($&g, &normed, w_gate) >>>
    f_u := metal.gemm_f32_nt($&u, &normed, w_up) >>>
    _ := f_g.wait() >>>
    _ := f_u.wait() >>>

    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    f_sw := metal.swiglu_f32($&out, &g, &u) >>>
    _ := f_sw.wait() >>>
    << out
}

Available GPU matrix ops in metal/matrix_f32.xu (full Transformer block coverage): gemm_f32 ($A B$), gemm_f32_nt ($A B^T$), rmsnorm_f32, layernorm_f32, softmax_f32, gelu_f32, swiglu_f32, add_f32, mul_f32, scale_f32, rope_f32, and causal_attention_f32.

Vector databases & agent automation (XACP)

Beyond tensor kernels and local inference, the Xu ecosystem includes pure-Xu client packages and built-in compiler protocols for complete AI applications:

  • Vector databases (packages): native Xu clients for qdrant, milvus, and chroma over HTTP/gRPC transports, enabling RAG pipelines compiled into a single static binary.
  • Agent automation (XACP & #xacp API): structured capability introspection, bounded event/frame recording, and audited UI interaction for local desktop applications built with Xu.
