Supported CLI flags across modes:

  • --ctx <N> — override maximum sequence length / context window.
  • --stride <N> — configure sliding-window step size for perplexity evaluation.
  • --grammar <path_or_inline>, --json-schema <path_or_json> — constrain generate sampling (or HTTP grammar, response_format, and text.format in serve) to any GBNF grammar or JSON Schema.
  • --models-dir <dir> — override the local model cache directory (~/.xu/models or XU_MODELS_DIR) for models list|rm|pull.
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> — choose paged KV-cache storage precision (halving or quartering KV memory).
  • --lora <path>, --lora-scale <f>, --lora-rank <N>, --lora-alpha <f>, --dataset <path>, --grad-accum <N>, --warmup-steps <N>, --lr-schedule <constant|cosine>, --save-ckpt <path>, --resume-ckpt <path>, --type <q4_0|q8_0|q4_k|q5_k|q6_k|q4_k_m|q5_k_m>, --mmproj <path>, --image <path|url|data_uri|rgb:...>, --verifier <contains|exact|json|math>, --group-size <K>, --gen-tokens <N>, --temp <milli>, --dpo-beta <f>, --clip-eps <f>, --kl-beta <f>, --teacher <path>, --distill-temp <f>, --distill-alpha <f>, --steps <N>, --lr <f>, --max-grad-norm <f> — load/merge PEFT SafeTensors LoRA adapters, quantize HF directories/SafeTensors/GGUF to GGUF (quantize), or run pure-Xu SFT train-lora (with AdamW checkpoint resume), train-dpo, train-grpo, online verifiable-reward train-rlvr, and train-distill fine-tuning.
  • --draft <model>, --draft-k <N> — enable lossless target-verified speculative decoding with exact KV rollback across greedy and stochastic sampling.
  • --top-p <milli>, --min-p <milli>, --repeat-penalty <milli>, --presence-penalty <milli>, --frequency-penalty <milli>, --seed <int> — deterministic filtering and repetition/presence/frequency penalties (1000 = 1.0; unbounded top_k supported).
  • --max-slots <N>, --api-key <K> — configure concurrent continuous-batching scheduler slots and optional Bearer authentication (excluding /health) in serve mode.
  • --rope-type <auto|norm|neox> — select RoPE pairing layout (norm interleaved pairs vs split-half NeoX; auto-detected from GGUF/architecture).
  • --ignore-eos — continue generation past EOS stop tokens for fixed-length evaluation.

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

Compiler options & MIR tensor fusion

When building with --tensor-fusion (or XU_TENSOR_FUSION=1), the compiler's MIR tensor-lowering pass pattern-matches idiomatic pure-Xu numerical loops (including the primitives in #tensor and custom kernels in user code) and lowers them directly into hand-tuned ARM64 NEON / SDOT and x86-64 SSE2 / SSSE3 runtime kernels, while keeping the frozen C/runtime ABI unchanged:

GPU compute via packages/metal

For Apple Silicon GPUs, the official packages/metal (v1.11.0 packages bundle, exporting 176 native symbols across all 6 .xulib slices) module provides F32Matrix, F16Matrix (MPSDataTypeFloat16), raw byte uploads (write_bytes), and six quantized matrix formats — Q4Matrix (matrix_q4_0), Q5Matrix (matrix_q5_0), Q8Matrix (matrix_q8_0), Q4KMatrix (matrix_q4_k), Q5KMatrix (matrix_q5_k), and Q6KMatrix (matrix_q6_k) — with limits raised to 262,144 per dimension / 536,870,912 cells, read/write lock separation for concurrent readers, and multi-op Batch command encoding synchronized with non-blocking Fence handles and compile-time borrow + runtime shape/alias/device guards:

@main

#errors

fn gpu_ffn_batch(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                 w_gate &metal.Q4Matrix, w_up &metal.Q4Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>

    $b := d.begin_batch() >>>
    _ := b.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := b.gemv_q4_0_f32($&g, &normed, w_gate) >>>
    _ := b.gemv_q4_0_f32($&u, &normed, w_up) >>>
    _ := b.swiglu_f32($&out, &g, &u) >>>
    $f := b.commit() >>>
    _ := f.wait() >>>
    << out
}

Known Limitations & Engineering Trade-offs

Developer caveat: Xu's AI stack optimizes for zero external C/C++ runtime bindings and compact standalone binaries, which entails clear scope limits and performance trade-offs.

  • Multi-threaded CPU inference & standalone GPU packages: examples/llm_engine supports parallel CPU execution via --threads N alongside continuous-batch coroutine serving, while the standalone packages repository (v1.17.0) provides llm_metal, cuda_native, vulkan_native, and the unified gpu facade for GPU acceleration.
  • Quantization speed asymmetry & unsupported GGUF types: #tensor and llm_engine now support F32, Q4_0, Q5_0, Q8_0, Q4_1, Q5_1, and K-quants Q2_K/Q3_K/Q4_K/Q5_K/Q6_K/Q8_K. ARM64 SDOT / p4k4 SIMD fast paths focus on F32, Q4_0, and Q8_0, whereas higher-arity/legacy quants run slower block paths, and imatrix IQ1–IQ4 GGUF types remain unsupported.
  • VLM --mmproj & image format limits: vision/mod.xu now supports both mmproj.gguf and Xu's F32 SafeTensors ViT+MLP layout (vision.*, v.patch_embd.weight, v.blk.*, mm.0/mm.2); image decoding covers PNG, JPEG, PPM, and uncompressed 24-bit BMP (no WebP, AVIF, or HEIC).
  • GBNF & --json-schema constraints: NFA normalization caps active branches at 64 (work queue 512, nesting depth 48). json_schema_to_gbnf handles type, properties, required, items, enum, const, anyOf, and oneOf in fixed key order (required then optional keys); $ref/$defs, allOf, regex pattern, numeric/length bounds, and arbitrary key order under additionalProperties: false are unsupported. Step masking on 128k+ vocabularies is slower than precompiled DFA/bitmask engines.
  • Training scope & built-in macOS signing: train-lora/train-dpo/train-grpo/train-rlvr/train-distill perform CPU f32 LoRA updates only (merge-lora exports F32 SafeTensors). Starting in Xu 0.14.3, release and debug macOS Mach-O binaries embed built-in ad-hoc LC_CODE_SIGNATURE directly from the compiler.
  • packages operational boundaries: rag.SqliteVectorStore scans loaded rows in memory ($O(N)$ exact search — best under ~10k chunks, use PgVectorClient HNSW or QdrantVectorStore beyond that); PgVectorClient wraps a single driver.Conn without pooling (though both postgres and sqlite bind arbitrary numbers of NamedValue parameters); a2a and single-node gateway hold state in memory unless Redis distributed state is configured, and SSE failover applies only before the first chunk arrives; AgentSwarm composes OpenAI-compatible Agents; local guardrails heuristics should be paired with check_safety_openai against obfuscated/non-ASCII attacks; eval.evaluate_json_schema validates flat []SchemaFieldRule specs rather than full Draft-2020-12 JSON Schema.
