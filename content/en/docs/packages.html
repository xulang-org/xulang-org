Official External Packages

Official module: github.com/xulang-org/packages · SDK module version 1.0.0 · 29 service integrations and the shared transport package

The Xu {{xu_version}} SDK bundles the external drivers and their native source resources. The matrix below is scoped to that bundle; API pages display their own package source identity (currently 1.0.2), which differs from the SDK bundle’s 1.0.0 manifest. Do not infer bundled capabilities from a newer API declaration. Drivers cover databases, caches, messaging, object storage and service discovery; check each package for protocol and platform limits.

1. Select the SDK bundle or a fixed source commit

Place your project beside the extracted SDK and declare its bundled packages using a local source locator. Adjust the relative path if you installed the SDK elsewhere:

module: my_app
version: !ver 0.1.0
xu: !ver {{xu_version}}
require:
  "github.com/xulang-org/packages": file:../xu-v{{xu_version}}/packages

To fetch the source used by this SDK instead, select its full immutable commit:

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@96693e6cce8d51eba45e4f68dc12ce06f7a2336b

From your project directory, resolve and lock dependencies, then check and build:

xu install
xu check main.xu --offline
xu build main.xu -o my_app

Module versions and Git tags have separate roles: this bundle declares module version 1.0.0. The fixed source locator above selects the exact source independently of tag availability. Keep xu.lock with your application and consult modules and dependencies for frozen, vendor and proxy workflows.

2. Importing Packages in Source Code

Xu enforces an explicit namespace alias convention for all external packages: alias #full/module/path/pkg. This eliminates global namespace pollution and makes all external dependencies visible directly at the top of the file.

@main

// 1. Standard library modules have no alias; prefixed with #
#database/sql

// 2. External packages declare an alias and full repository path
mysql    #github.com/xulang-org/packages/mysql
redis    #github.com/xulang-org/packages/redis
postgres #github.com/xulang-org/packages/postgres

fn main() int {
    // Access APIs directly through the declared alias
    println("Drivers loaded successfully")
    << 0
}

Important: Do not write #mysql or #redis. External module imports require an explicit alias and full module path. Standard library imports and local package imports (such as #util) follow their own resolution rules. The integrations listed here belong to github.com/xulang-org/packages; other external modules have their own identities.

3. Hands-on Quickstart Examples

Example 1: Using the MySQL Driver with database/sql

The standard library database/sql provides connection pooling, transactions, and result row abstractions; the concrete MySQL driver is implemented by packages/mysql:

@main
#database/sql
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    dsn := "root:123456@tcp(127.0.0.1:3306)/test_db?tls=false"
    $db := sql.open(mysql.driver(), dsn)
    db.ping() >>> (err) {
        println("Database ping failed: " + err.msg())
        << 1
    }
    println("Connected to MySQL successfully!")
    db.close() >>> (err) { << 1 }
    << 0
}

Example 2: Redis Client Operations

@main
redis #github.com/xulang-org/packages/redis

fn main() int {
    $client := redis.open("127.0.0.1:6379") >>> (err) {
        println("Redis connect error: " + err.msg())
        << 1
    }
    client.set("app_version", "demo") >>> (err) { << 1 }
    val := client.get("app_version") >>> (err) { << 1 }
    println("Key 'app_version': " + val)
    client.close()
    << 0
}

Example 3: Object Storage with S3 / MinIO

@main
s3 #github.com/xulang-org/packages/s3

fn main() int {
    $client := s3.open("http://127.0.0.1:9000", "access_key", "secret_key", "us-east-1")
    client.put_object("my-bucket", "welcome.txt", "Hello from Xu!", "text/plain") >>> (err) {
        println("S3 upload failed: " + err.msg())
        << 1
    }
    println("Object uploaded successfully")
    << 0
}

5. Boundaries & Production Builds

  • SQLite & Metal Pure-FFI Architecture: The SQLite driver now dynamically loads (dlopen) system libsqlite3 via pure-Xu sqlite_native (Windows automatically uses built-in winsqlite3.dll, overridable via XU_SQLITE_LIBRARY), eliminating the legacy requirement to compile .xulib slices with make native. The optional Metal GPU compute package dynamically loads libxu_metal.dylib via metal_native (built via python3 metal/native/build.py, overridable via XU_METAL_LIBRARY).
  • Frozen Builds in Production: For immutable CI/CD deployment pipelines, commit the generated vendor/ directory and xu.lock to Git, then run xu build main.xu --frozen. This strictly forbids outbound network calls during build for 100% reproducible builds.

For more details on MVS resolution, checksum verification, and private proxies, see: Modules and Dependencies Specification and Native Modules Specification.
