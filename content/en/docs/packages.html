Official External Packages

Official ecosystem monorepo: github.com/xulang-org/packages · Module version v0.1.1 · 29 production-ready packages

To keep the core compiler and standard library minimal, secure, and bloat-free, official third-party service drivers (such as relational databases, in-memory caches, message brokers, object storage, and cloud connectors) are maintained in the standalone packages repository. Developers do not need to manually clone repositories or hand-write fragile build configs: simply declare the dependency in xu.xun and run xu install to fetch and verify everything automatically.

1. Declare & Install Dependencies Automatically (Zero Manual Config)

Create or edit your project's xu.xun manifest file in the root directory. We recommend referencing official SemVer releases:

module: my_app
version: !ver 0.1.0
xu: !ver {{xu_version}}

require:
  "github.com/xulang-org/packages": v0.1.1

Run a single command in your project directory. The Xu compiler automatically resolves the dependency graph, verifies cryptographic digests, downloads sources into vendor/, and creates the immutable xu.lock:

# Automatically fetch dependencies into vendor/ and generate xu.lock
xu install

# Subsequent offline compilation and verification (zero network calls)
xu check main.xu --offline
xu build main.xu --output my_app
Advanced Options: Pin to Git Commits or Local Workspace

Pin to a reviewed Git commit or tag:

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@<commit_hash>

Local multi-repo co-development (project placed beside packages checkout):

require:
  "github.com/xulang-org/packages": file:../packages

2. Importing Packages in Source Code

Xu enforces an explicit namespace alias convention for all external packages: alias #full/module/path/pkg. This eliminates global namespace pollution and makes all external dependencies visible directly at the top of the file.

@main

// 1. Standard library modules have no alias; prefixed with #
#database/sql
#fmt

// 2. External packages declare an alias and full repository path
mysql    #github.com/xulang-org/packages/mysql
redis    #github.com/xulang-org/packages/redis
postgres #github.com/xulang-org/packages/postgres

fn main() int {
    // Access APIs directly through the declared alias
    fmt.println("Drivers loaded successfully")
    << 0
}

Important: Do not write #mysql or #redis. The bare # is reserved exclusively for standard library modules. All external packages belong to the github.com/xulang-org/packages monorepo and require their full path identity.

3. Hands-on Quickstart Examples

Example 1: Using the MySQL Driver with database/sql

The standard library database/sql provides connection pooling, transactions, and result row abstractions; the concrete MySQL driver is implemented by packages/mysql:

@main
#database/sql
#fmt
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    dsn := "root:123456@tcp(127.0.0.1:3306)/test_db?tls=false"
    mut db := sql.open(mysql.driver(), dsn)
    db.ping() or (err) {
        fmt.println("Database ping failed:", err.msg())
        << 1
    }
    fmt.println("Connected to MySQL successfully!")
    db.close() or (err) { << 1 }
    << 0
}

Example 2: Redis Client Operations

@main
#fmt
redis #github.com/xulang-org/packages/redis

fn main() int {
    mut client := redis.connect("127.0.0.1:6379") or (err) {
        fmt.println("Redis connect error:", err.msg())
        << 1
    }
    client.set("app_version", "v0.8.11") or (err) { << 1 }
    val := client.get("app_version") or (err) { << 1 }
    fmt.println("Key 'app_version':", val)
    client.close()
    << 0
}

Example 3: Object Storage with S3 / MinIO

@main
#fmt
s3 #github.com/xulang-org/packages/s3

fn main() int {
    mut client := s3.new("endpoint.example.com", "access_key", "secret_key", "my-bucket")
    client.put_object("welcome.txt", "Hello from Xu!") or (err) {
        fmt.println("S3 upload failed:", err.msg())
        << 1
    }
    fmt.println("Object uploaded successfully")
    << 0
}

5. Boundaries & Production Builds

  • SQLite Native C-Bridge: SQLite relies on a native C bridge. When working directly in the packages source checkout, run make native in the packages root directory to compile native architecture slices.
  • Frozen Builds in Production: For immutable CI/CD deployment pipelines, commit the generated vendor/ directory and xu.lock to Git, then run xu build main.xu --frozen. This strictly forbids outbound network calls during build for 100% reproducible builds.

For more details on MVS resolution, checksum verification, and private proxies, see: Modules and Dependencies Specification.
