Official External Packages

Official module: github.com/xulang-org/packages · SDK module version 0.2.0 · 29 service integrations and the shared transport package

The Xu {{xu_version}} SDK bundles the external drivers and their native source resources. The API is generated from that bundle. Drivers cover databases, caches, messaging, object storage and service discovery; check each package for protocol and platform limits.

1. Select the SDK bundle or a fixed source commit

Place your project beside the extracted SDK and declare its bundled packages using a local source locator. Adjust the relative path if you installed the SDK elsewhere:

module: my_app
version: !ver 0.1.0
xu: !ver {{xu_version}}
require:
  "github.com/xulang-org/packages": file:../xu-v{{xu_version}}/packages

To fetch the source used by this SDK instead, select its full immutable commit:

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@0122e87a5f87b52d3ead9390ad01165e7d7645ad

From your project directory, resolve and lock dependencies, then check and build:

xu install
xu check main.xu --offline
xu build main.xu -o my_app

Module versions and Git tags have separate roles: this bundle declares module version 0.2.0. The fixed source locator above selects the exact source independently of tag availability. Keep xu.lock with your application and consult modules and dependencies for frozen, vendor and proxy workflows.

2. Importing Packages in Source Code

Xu enforces an explicit namespace alias convention for all external packages: alias #full/module/path/pkg. This eliminates global namespace pollution and makes all external dependencies visible directly at the top of the file.

@main

// 1. Standard library modules have no alias; prefixed with #
#database/sql
#fmt

// 2. External packages declare an alias and full repository path
mysql    #github.com/xulang-org/packages/mysql
redis    #github.com/xulang-org/packages/redis
postgres #github.com/xulang-org/packages/postgres

fn main() int {
    // Access APIs directly through the declared alias
    fmt.println("Drivers loaded successfully")
    << 0
}

Important: Do not write #mysql or #redis. The bare # is reserved exclusively for standard library modules. All external packages belong to the github.com/xulang-org/packages monorepo and require their full path identity.

3. Hands-on Quickstart Examples

Example 1: Using the MySQL Driver with database/sql

The standard library database/sql provides connection pooling, transactions, and result row abstractions; the concrete MySQL driver is implemented by packages/mysql:

@main
#database/sql
#fmt
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    dsn := "root:123456@tcp(127.0.0.1:3306)/test_db?tls=false"
    mut db := sql.open(mysql.driver(), dsn)
    db.ping() or (err) {
        fmt.println("Database ping failed:", err.msg())
        << 1
    }
    fmt.println("Connected to MySQL successfully!")
    db.close() or (err) { << 1 }
    << 0
}

Example 2: Redis Client Operations

@main
#fmt
redis #github.com/xulang-org/packages/redis

fn main() int {
    mut client := redis.connect("127.0.0.1:6379") or (err) {
        fmt.println("Redis connect error:", err.msg())
        << 1
    }
    client.set("app_version", "v0.8.12") or (err) { << 1 }
    val := client.get("app_version") or (err) { << 1 }
    fmt.println("Key 'app_version':", val)
    client.close()
    << 0
}

Example 3: Object Storage with S3 / MinIO

@main
#fmt
s3 #github.com/xulang-org/packages/s3

fn main() int {
    mut client := s3.new("endpoint.example.com", "access_key", "secret_key", "my-bucket")
    client.put_object("welcome.txt", "Hello from Xu!") or (err) {
        fmt.println("S3 upload failed:", err.msg())
        << 1
    }
    fmt.println("Object uploaded successfully")
    << 0
}

5. Boundaries & Production Builds

  • SQLite Native C-Bridge & .xulib: SQLite relies on a native C bridge. The official package uses a portable .xulib multi-target slice container (bundling generic .a slices for macos-arm64, macos-x64, etc., along with ABI verification metadata). When working directly in the packages source checkout, run make native in the packages root directory to compile native architecture slices. For architecture details, see Native Modules & .xulib Specification.
  • Frozen Builds in Production: For immutable CI/CD deployment pipelines, commit the generated vendor/ directory and xu.lock to Git, then run xu build main.xu --frozen. This strictly forbids outbound network calls during build for 100% reproducible builds.

For more details on MVS resolution, checksum verification, and private proxies, see: Modules and Dependencies Specification and Native Modules & .xulib Specification.

Build the SQLite native bridge

SQLite examples require a native bridge built from the bundled C sources. On macOS ARM64, run these commands from the SDK packages directory with the matching C toolchain. Other targets require a matching native toolchain and target slice.

cd xu-v{{xu_version}}/packages
xu native compile --manifest sqlite/native/native.json --target macos-arm64 -O2 -DSQLITE_THREADSAFE=1 -DSQLITE_OMIT_LOAD_EXTENSION=1 sqlite/native/bridge.c sqlite/vendor/sqlite3.c -o sqlite/native/sqlite-macos-arm64.a
xu native pack --manifest sqlite/native/native.json --slice macos-arm64=sqlite/native/sqlite-macos-arm64.a -o sqlite/native/sqlite.xulib
