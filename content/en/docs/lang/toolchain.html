Toolchain

Xu {{xu_version}} provides build, run, check, test, install, fmt, map, doc, and doctor. Product builds self-host with the Xu compiler; the frozen Rust bootstrap serves as a primer and correctness oracle.

The default target is the host. Use --target linux-arm64 or XUOS/XUARCH for cross-compilation. XUPATH uses : on Unix and ; on Windows, independently of the target. External imports still require xu.xun mappings.

Ordinary AOT builds emit native output directly. Desktop host code and native extensions such as SQLite require their platform toolchains. --emit-obj emits XUOBJ; --shared exports primitive int/bool/string/f64/i32/u32/u8 signatures.

Native Inputs & .a / .xulib Specification

When compiling executables, xu build and xu run support accepting native static archives on the command line or declaring module mappings in the native: section of xu.xun:

# Command-line input
xu build main.xu module.a -o main
xu build main.xu module.xulib -o main

# Or declared in xu.xun
native:
  sqlite_native: file:./native/sqlite.xulib

The toolchain natively supports both standard generic .a (Unix static archives) and portable .xulib multi-target slice containers:

  • Generic .a Archives: Directly linked on a single platform, suitable for local development and debugging. The archive embeds an object slice (xu.o) containing export signatures, linked by the platform host linker.
  • Portable .xulib Containers: Designed for cross-platform ecosystem distribution. While generic .a archives are tied to a single architecture and lack parameter/return type contracts, .xulib bundles a strongly-typed JSON Manifest alongside standard .a slices for all target platforms. During xu build, the compiler selects the matching slice by --target, verifies its SHA-256 digest, enforces static type constraints, and produces zero-overhead native machine code.

The companion tool xunative.py provides compile (C compilation with injected metadata), archive (packaging precompiled objects), and pack (bundling slices into .xulib). Run xu doctor to inspect host linker and C toolchain availability.
