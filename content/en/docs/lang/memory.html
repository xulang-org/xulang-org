Memory

An owning value has one owner. Pass/return/store by value moves. Drop is deterministic at end of scope. Use-after-move is a compile error.

FormMeaning
by-value string / []Tmove
&xshared borrow
$&x (x must be declared $x)exclusive borrow
*rderef a scalar (writes need $&)

While a shared borrow is live you cannot write / move / take $&. There is no unsafe keyword. Hosted targets reject volatile stores to arbitrary addresses.

Borrow Diagnostics in 0.9.4

Borrow checking traverses nested expressions. For example, f($&v, &v) takes exclusive and shared borrows of v simultaneously and is rejected even inside int(f64(f($&v, &v)) * 32.0). Pass separate values, or split the operations so mutable use ends before taking a shared borrow.

Borrows taken inside a loop remain live across its back edge; a later iteration that conflicts with a still-live borrow is rejected. If upgrading exposes these diagnostics, adjust borrow scopes or ownership transfers. See the 0.9.4 release announcement for migration details.

File and Conn are affine resources: moves transfer ownership and scope exit closes them. Their native handles are package-private. Borrow the resource for I/O and observe explicit EOF/error data and write-progress results when using the progress APIs.
