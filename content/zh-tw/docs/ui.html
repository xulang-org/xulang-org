UI / WebView

Xu {{xu_version}} 正式 SDK 包含繪圖、保留佈局、編輯控制元件、人體工學 Screen 上下文、結構化選單、螢幕查詢、桌面與 WebView 非同步請求，以及統一樣式控制元件。請從下載頁面安裝對應版本。

生成 iOS 和 Android 專案的步驟見移動應用指南和 #ui/phone API。

#ui 管理視窗、事件與桌面服務；#ui/draw 記錄繪圖幀；#ui/layout 計算佈局；#ui/chart 繪製原生圖表與資料視覺化；#ui/widgets 管理控制元件、互動與保留場景；#ui/webview 承載網頁及請求橋接。

瀏覽器畫布與原生 / WebView 邊界

瀏覽器畫布：可先執行演練場計數器專案。WASM 直譯器與畫布介面卡只實現繪圖和控制元件互動的子集。此瀏覽器路徑不提供原生視窗、桌面服務、系統對話方塊、原生 IME 行為或 ui/webview 宿主；瀏覽器輸出不能證明桌面能力對等。

原生 / WebView：需要本機 SDK 與目標系統庫：macOS 的 AppKit / WebKit、Windows 原生宿主 / WebView2、Linux 的 GTK4 / WebKitGTK 6.0。打包前執行 xu doctor --desktop --target <target>。跨目標構建成功僅證明程式碼生成；GUI 互動、IME、資源釋放和 WebView 行為仍需目標機驗收，此處各平臺結果仍屬待驗。

選擇目標前，請檢視下載平臺邊界與狀態說明。

瀏覽器演練場

無需安裝 SDK，即可在演練場的專案模板庫中選擇 46 個控制元件體驗，檢視和修改 Xu 原始碼後重新執行。所有元件體驗均執行 Xu/WASM；部分使用組合或受限實現，例如 DatePicker 日期條、WebView 佔位和基本按鍵文字編輯，具體範圍以模板說明為準。也可從三頁控制元件畫廊開始。

任務操作
手機工作區切換「檔案」「編輯」「預覽」「輸出」會保留當前程式碼與控制元件狀態。執行 UI 示例後顯示預覽，普通程式顯示輸出；模板詳情可返回列表，保留篩選。
檢視畫布「適應視窗」顯示完整畫布；「100%」保留原尺寸。畫布超出檢視區域時，開啟「平移」後拖動檢視，關閉平移後再點選或拖動控制元件。桌面還可「擴大預覽」。
選擇與勾選ComboBox 點選後顯示候選選單，可用方向鍵和 Enter 選擇；MultiSelect 展開後逐項勾選，Escape 關閉選單並保留選擇。
浮層與對話方塊Popover 的 Apply 儲存偏好，Cancel、外點或 Escape 放棄未儲存修改；Modal 開啟時阻止背景操作，Tab 在對話方塊內切換焦點，關閉後恢復觸發按鈕焦點。
調整顏色ColorPicker 可拖動通道滑塊，釋放後仍可用方向鍵調節；畫布與輸出同步顯示色值。檢視模式須關閉「平移」。
鍵盤操作先點選畫布或用 Tab 聚焦。Tab / Shift+Tab 切換控制元件，Enter / 空格啟用，方向鍵調整支援的控制元件。Escape 優先關閉選單或浮層，具體行為由控制元件處理。

工作區與示例使用固定的 XUUI 設計參考。焦點使用硃紅色的單層邊界，選中狀態使用主題色，控制元件文字按可見字形垂直對齊；畫布控制元件的焦點由 Xu 繪製。示例使用固定的 XUUI 主題，外圍預覽面板跟隨網站主題。瀏覽器文字佈局仍使用估算度量，尚不等同於完整原生塑形、IME 或逐控制元件讀屏語義。

閱讀文件或僅開啟首頁不會預載入 WASM；點選執行或開啟指定示例時按需載入，首次執行可能需要等待。下載或初始化失敗後可再次執行，停止會終止當前 worker。執行器線性記憶體從 32 MiB 開始，最多增長到 256 MiB，並非預先佔滿；普通程式最長執行 10 秒，Widgets 示例最長執行 30 秒。需要網路、系統服務、完整文字編輯或原生視窗時，請使用本機 SDK。

繪圖幀與資源

一個 worker 消費 App.event_ch；等待 canvas_ready 後，用 draw.context_of 取得 Context。Context 與資源屬於 canvas_id / generation，關閉視窗後失效。每次以 Context.new_frame / Frame.begin 開始，記錄完整幀後只呼叫一次 present；失敗時 cancel。空閒時保留上一幀，不持續重繪。可先合併排隊事件，再提交一次繪製。

Frame 的座標是浮點邏輯畫素，原點在左上角；Frame.scale(1.0, 1.0) 是原比例。相容的包級 draw.scale(100, 100) 使用百分比。push / pop 同時儲存變換、裁剪與畫筆；棧必須配對。Frame 上限為 4 MiB、100000 條命令、256 層狀態。DisplayList 複用命令，Surface / SurfaceCache 複用柵格結果。

畫布預設不平移。 macOS、Windows、Linux 都需要在畫布就緒後顯式呼叫 draw.set_pan_enabled(1) 才啟用內建拖拽 / 滾輪相機；關閉時重置偏移。應用仍可接收拖拽和滾輪事件。控制元件 attach 會啟用輸入並關閉相機。

Image、TextLayout、DisplayList、Surface、快取與輸入會話都有顯式釋放方法。資源必須保留到引用它們的 Frame 被 present、freeze 或 snapshot 成功接受；已接受的記錄會持有所需資源版本。複製資源控制代碼不建立獨立資源；使用相應 clone / dispose 契約。

保留佈局與事件

Constraints 從父向子傳遞，尺寸從子向父返回。佈局樹支援 row / column / stack / padding；單樹最多 4096 節點、深度 64。View 儲存穩定節點 ID、髒標記、命中與重繪邊界；這不是按需構建的虛擬列表。

透過 dispatch_event 路由鍵盤和指標，並把原生文字事件、剪貼簿結果交給 Editor.event。節點回撥中的繪製矩形、指標位置為節點區域性座標；node_bounds / Editor.place 使用畫布座標。佈局或祖先滾動改變後，在繪製前呼叫 place_editor 同步命中和 IME 幾何。拖動捲軸時為節點開啟 set_capture_outside，使指標離開視口後仍可拖動。

統一控制元件樣式

dark_styles、light_styles、contrast_styles 返回完整 Styles。font 和 text_scale 控制文字，density 控制幾何；各 ControlStyle 可用 inherit_font = false 單獨選擇字型。外觀包括顏色、圓角、邊框、焦點、內邊距、最小尺寸、對齊和陰影。

@main
#ui/draw
#ui/widgets

fn main() int {
    $styles := widgets.light_styles()
    styles.text_scale = 1.4
    styles.density = 0.85
    styles.button.radius = 10.0
    styles.button.icon_placement = widgets.ICON_TRAILING
    $rule := widgets.state_paint(widgets.STATE_FOCUSED | widgets.STATE_INVALID)
    rule.unless = widgets.STATE_DISABLED
    rule.fields = widgets.PAINT_BORDER | widgets.PAINT_FOCUS
    rule.border = draw.rgb(220, 38, 38)
    rule.focus = draw.rgb(251, 113, 133)
    styles.button.states.push(rule)
    styles.validate() or (err) {
        eprintln(err.msg())
        << 1
    }
    << 0
}
控制元件可調整內容與入口
Buttonmeasure_styled / paint_styled；圖片用 measure_icon_styled / paint_icon_styled，支援四向位置、間距和禁用透明度
Checkbox字型、間距、指示器尺寸、標記線寬；勾選標記與標籤分別取色
Input / TextArea字型、行高、內邊距、佔位、選區前景 / 背景、游標、預編輯下劃線、只讀與錯誤狀態
Progress軌道、指示條、尺寸、圓角、禁用和錯誤狀態
Scroll捲軸寬度、邊距、最小滑塊、焦點和狀態；paint_scrollbar 放在 overlay_styled 中

基礎狀態位為 disabled=1、hovered=2、pressed=4、focused=8、selected=16、invalid=32、read_only=64。預設背景優先順序是禁用 → 錯誤 → 只讀 → 選中 → 按下 → 懸停 → 普通。StatePaint 的 when 位須全部匹配，unless 位須全部不匹配；按陣列順序覆蓋，後匹配規則勝出，僅修改 fields 指定的顏色 / 圖示透明度。每個控制元件最多 32 條規則。

作用域、測量與快取

View.set_styles 設定根主題。set_style_scope 儲存完整主題快照，後代繼承到下一作用域；全域性主題變化不會覆蓋顯式區域性主題。clear_style_scope 恢復繼承；styles_for 返回獨立克隆。顏色或裝飾變化只使繪製快取失效；字型或尺寸變化還會重新測量透過 set_style_measure 註冊的節點。

@main
#ui/widgets

fn configure(view $&widgets.View, brand_node int, label_node int) int {
    styles := widgets.light_styles()
    view.set_styles(&styles) or >>
    $local := styles.clone()
    local.button.radius = 12.0
    view.set_style_scope(brand_node, &local) or >>
    view.set_style_measure(label_node, true) or >>
    view.mark_measure(label_node) or >>
    << 0
}
fn main() int { << 0 }

StyledPainter 的 measure_styled / paint_styled / overlay_styled 借用當前有效主題。呼叫 layout_styled，同步編輯器位置，再呼叫 present_styled；無髒更新時返回 false。snapshot_styled 用於離屏結果。標籤使用 StyledLabel 快取排版；修改文字後 set_text 並 mark_measure。回撥中不修改 View 或拓撲；資源在視窗關閉時釋放。

舊的八欄位 Theme 和 paint 介面繼續相容。主題由應用顯式切換；原生選單 / 對話方塊跟隨平臺外觀，WebView 使用 CSS。陰影是最多八層的有界近似。擴充套件控制元件見下方說明；自定義控制元件透過 StyledPainter 接入。

編輯控制元件與 IME

widgets.input 與 text_area 建立持久 Editor。聚焦時原生 TextInput 會話擁有編輯和預編輯狀態；失焦後 Editor 保留提交值。支援選區拖動、方向鍵、Home / End、Shift 擴選、系統複製 / 剪下 / 貼上；單行 Enter 提交，多行 Enter 換行。剪貼簿非同步結果僅用於發起時的會話版本。

set_read_only(true) 釋放原生輸入會話，保留本地選擇、導航和複製，拒絕輸入、剪下和貼上，遲到 IME 提交不改值。enable(false) 禁用互動。文字最多 16384 位元組 UTF-8，不含 NUL；大文字和大字型組合還受原生排版預算限制。選區索引為 UTF-8 位元組位置。Windows 命中查詢需要 DirectWrite；舊 Wine 缺少對應實現。

結構化選單與螢幕

Window.set_menu_entries 原子替換每窗選單樹。根 parent=-1 且必須是 submenu，其餘 parent 是更早的 submenu 陣列下標；最多 256 項、深度 8。只有 menu_check 可 checked，只有 action / check 可設定快捷鍵。menu_primary 在 macOS 對應 Command，在 Windows / GTK 對應 Control。點選以 ev_menu_clicked 返回，應用更新勾選狀態後重新設定選單。macOS 在未提供時補充標準 Edit 選單。

@main
#ui

fn configure_menu(window &ui.Window) int {
    $entries := []ui.MenuEntry{}
    entries.push(ui.submenu("document", "Document", -1))
    $reset := ui.menu_action("reset", "Reset", 0)
    reset.key = 82
    reset.modifiers = ui.MENU_PRIMARY | ui.MOD_SHIFT
    entries.push(reset)
    entries.push(ui.menu_separator(0))
    entries.push(ui.menu_check("readonly", "Read only", 0, false))
    window.set_menu_entries(entries) or >>
    << 0
}
fn main() int { << 0 }

Window.screens_async 返回 Request；完成後用 screen_result 解碼 bounds、work_area、scale、primary / current。先檢查 primary_known / work_area_known。Windows 桌面矩形是物理畫素，macOS / GTK 是邏輯桌面座標，由 physical_coordinates 標明；均不能直接當作畫布區域性座標。

擴充套件控制元件與統一樣式切換

Switch、Radio、Slider、Stepper、Tabs、Select、Badge、Divider、Card 與 ListBox 共享 Styles、組合狀態繪製規則、陰影及圖示位置。使用 widgets.style_switcher() 建立深色、淺色和高對比預設；呼叫 use_preset、set_text_scale、set_density 後，透過 apply 應用到保留 View，或用 cycle 切換並應用下一預設。這些方法可能失敗，須處理錯誤。View 接收完整樣式快照，控制元件的顯式覆蓋繼續生效。

非同步桌面請求

剪貼簿、檔案選擇、提示、螢幕與 WebView 原生查詢返回 ui.Request；接收 ev_request 後用 request_of 解碼，再用 result.matches 校驗完整身份。提交成功只代表已受理。status 分別為 completed=0、cancelled=1、failed=2、unsupported=3、timed_out=4；空字串也可能是成功結果。

@main
#ui

fn handle_result(event &ui.Event, pending &ui.Request) int {
    if event.kind != ui.EV_REQUEST { << 0 }
    result := ui.request_of(event) or >>
    if !result.matches(pending) { << 0 }
    if result.status == ui.REQUEST_COMPLETED { println(result.value) }
    << 0
}
fn main() int { << 0 }

RequestOptions.timeout_ms=0 使用 5000 ms，合法顯式範圍為 1–3600000 ms；提示框預設 300000 ms。Request.cancel 返回是否受理取消，不能撤銷已經完成的剪貼簿寫入。保持事件消費者執行，關閉視窗後不再複用該 generation 的請求或資源。

WebView 請求生命週期

用 bind_ipc_requests_www 接收 InvokeRequest（id、window_id、generation、name、payload），與 App.run 分開在 Xu worker 中執行。網頁呼叫如下；返回值是帶 id 和 cancel() 的 Promise。JS 預設超時 30000 ms，顯式範圍 1–3600000 ms；支援 AbortSignal。listen 返回解除訂閱函式。

const controller = new AbortController();
const pending = window.__XU__.invoke("echo", "Hello 世界", {
  timeoutMs: 5000,
  signal: controller.signal
});
pending.then(value => console.log(pending.id, value))
       .catch(error => console.log(error.name, error.message));
// pending.cancel();  // or controller.abort()

單個 invoke 請求（含協議頭）及返回值最多 1 MiB；最多 64 個活躍派發額度，排隊請求體 / 結果共用 8 MiB。請求名最多 256 個 UTF-8 位元組。取消、導航和關閉會丟棄遲到結果；取消不能強制中斷正在執行的使用者回撥，額度待回撥返回後釋放。併發請求可亂序完成。

WebView.eval_async、find_async、cookies_async、set_cookie_async、clear_cookies_async 使用相同 ui.Request / ev_request 生命週期，原生結果最多 64 KiB。原生完成回撥在 UI 執行緒；應用派發在 Xu worker。相容等待介面不消費 App 的公開事件佇列。每窗 / 文件身份隔離，導航後不能把舊結果應用到新頁面。

繪圖與遊戲引擎邊界

這是面向桌面工具、編輯器和小型原型的二維繪圖層。平臺後端使用 CoreGraphics、Cairo 和 GDI+；公共 API 沒有提供遊戲引擎所需的 GPU 渲染管線、著色器、繪製批處理和顯示同步的幀排程契約。DisplayList 與 Surface 快取可複用工作，但不能據此宣稱達到遊戲幀耗時預算；應按實際負載在目標平臺測量。
