工具鏈

Xu {{xu_version}} 提供 build、run、check、test、install、fmt、map、doc、doctor。產品構建由 Xu 編譯器自舉；凍結的 Rust bootstrap 用作初始引導與正確性參照。

構建、執行和測試預設開啟最佳化，可用 --no-opt 關閉。用 --xacp 或 --xacp-port 顯式啟用 XACP 控制通道。正式版測試覆蓋原生 stdio 與迴環 TCP。

預設目標為本機；交叉編譯使用 --target linux-arm64 或 XUOS/XUARCH。XUPATH 在 Unix 用 :、Windows 用 ;，與目標平臺無關；外部匯入仍須有 xu.xun 對映。

普通 AOT 構建直接生成原生產物。--emit-obj 輸出 XUOBJ，--target wasm32-wasi 生成 WASI 模組。桌面宿主和 SQLite 等原生擴充套件需要對應平臺工具鏈。

原生輸入與 .a / .xulib 規範

在編譯可執行檔案時，xu build 與 xu run 既支援在命令列直接追加原生靜態庫，也支援透過專案清單 xu.xun 的 native: 欄位宣告模組對映：

1. 命令列直接傳入原生庫進行編譯連結：

xu build main.xu module.a -o main
xu build main.xu module.xulib -o main

2. 或在專案工程清單 xu.xun 中宣告原生模組對映：

native:
  sqlite_native: file:./native/sqlite.xulib

工具鏈同時支援標準通用的 .a（Unix 靜態歸檔）與行動式 .xulib 容器：

  • 通用 .a 靜態庫：單平臺原生直連，適合本地開發與臨時除錯；靜態庫內嵌入帶有匯出簽名的目標切片（xu.o），由系統原生連結器完成最後一步連結。
  • 行動式 .xulib 容器：用於跨平臺模組分發。通用的 .a 僅包含單一系統架構且丟失函式引數/返回值型別後設資料；.xulib 容器內嵌強型別 JSON Manifest 與各平臺標準的 .a 架構切片。xu build 在編譯期根據 --target 自動提取匹配切片並驗證 SHA-256，靜態型別檢查期嚴格約束 C 匯出呼叫，執行期保持零中介軟體開銷。

編譯器內建一級子命令 xu native 提供 compile（單目標 C 編譯並注入後設資料）、archive（原生物件打包）、pack（多切片聚合為 .xulib）、inspect（容器檢視）與 extract（切片提取）命令。執行 xu doctor 可診斷本機 C 連結器與宿主構建環境的就緒狀態。
