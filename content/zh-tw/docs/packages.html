官方擴充套件包 (Packages)

官方模組：github.com/xulang-org/packages · SDK 內模組版本 1.0.0 · 29 個服務整合包及共享 transport 包

Xu {{xu_version}} SDK 包含外部驅動及原生原始碼資源，下方矩陣以該安裝包為範圍；API 頁顯示各自的包來源身份（當前為 1.0.2），與 SDK 內 1.0.0 清單不同，不能從較新 API 宣告推斷內建能力。驅動涵蓋資料庫、快取、訊息、物件儲存與服務發現；協議和平臺邊界見各包說明。

1. 選擇 SDK 內建包或固定原始碼提交

將專案放在解壓後的 SDK 旁，透過本地來源宣告內建 packages；安裝位置不同時調整相對路徑：

module: my_app
version: !ver 0.1.0
xu: !ver {{xu_version}}
require:
  "github.com/xulang-org/packages": file:../xu-v{{xu_version}}/packages

也可以指定該 SDK 使用的完整不可變提交來獲取原始碼：

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@96693e6cce8d51eba45e4f68dc12ce06f7a2336b

在專案目錄中解析並鎖定相依性，再檢查和構建：

xu install
xu check main.xu --offline
xu build main.xu -o my_app

模組版本與 Git 標籤分別管理：本安裝包宣告模組版本 1.0.0，以上固定原始碼地址直接選擇準確提交。請將 xu.lock 與應用一同維護；凍結構建、vendor 和代理用法見模組與相依性。

2. 在程式碼中引用擴充套件包

Xu 對所有外部擴充套件包採用明確的名稱空間別名機制，語法格式為：別名 #完整包路徑。這不僅避免了全域性命名汙染，也保證了所有程式碼相依性關係透明可見。

@main

// 1. 標準庫無需別名，以 # 開頭
#database/sql

// 2. 外部 packages 擴充套件包宣告別名與完整路徑（別名即程式碼中的呼叫名稱空間）
mysql    #github.com/xulang-org/packages/mysql
redis    #github.com/xulang-org/packages/redis
postgres #github.com/xulang-org/packages/postgres

fn main() int {
    // 使用別名進行呼叫
    println("Drivers loaded successfully")
    << 0
}

注意：不能寫 #mysql 或 #redis。外部模組必須使用顯式別名與完整模組路徑。標準庫與本地包（如 #util）各有解析規則。本文所列整合包屬於 github.com/xulang-org/packages，其他外部模組使用各自的模組標識。

3. 快速上手實戰示例

實戰 1：配合 database/sql 使用 MySQL 驅動

標準庫 database/sql 提供連線池、事務與結果集抽象，具體的驅動實現由 packages 的 mysql 包提供：

@main
#database/sql
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    dsn := "root:123456@tcp(127.0.0.1:3306)/test_db?tls=false"
    $db := sql.open(mysql.driver(), dsn)
    db.ping() >>> (err) {
        println("Database ping failed: " + err.msg())
        << 1
    }
    println("Connected to MySQL successfully!")
    db.close() >>> (err) { << 1 }
    << 0
}

實戰 2：連線與操作 Redis 快取

@main
redis #github.com/xulang-org/packages/redis

fn main() int {
    $client := redis.open("127.0.0.1:6379") >>> (err) {
        println("Redis connect error: " + err.msg())
        << 1
    }
    client.set("app_version", "demo") >>> (err) { << 1 }
    val := client.get("app_version") >>> (err) { << 1 }
    println("Key 'app_version': " + val)
    client.close()
    << 0
}

實戰 3：使用 S3 / MinIO 進行物件儲存

@main
s3 #github.com/xulang-org/packages/s3

fn main() int {
    $client := s3.open("http://127.0.0.1:9000", "access_key", "secret_key", "us-east-1")
    client.put_object("my-bucket", "welcome.txt", "Hello from Xu!", "text/plain") >>> (err) {
        println("S3 upload failed: " + err.msg())
        << 1
    }
    println("Object uploaded successfully")
    << 0
}

5. 邊界與注意事項

  • SQLite 與 Metal 純 FFI 架構：SQLite 驅動現透過純 Xu 包 sqlite_native 動態載入（dlopen）系統 libsqlite3（Windows 平臺自動識別系統內建 winsqlite3.dll，亦可透過 XU_SQLITE_LIBRARY 覆蓋路徑），無需再透過 make native 編譯打包靜態 .xulib。Metal GPU 計算包透過 metal_native 動態載入 libxu_metal.dylib（可由 metal/native/build.py 構建，支援 XU_METAL_LIBRARY 覆蓋）。
  • 離線與生產構建（Frozen Builds）：在生產 CI/CD 流水線中，建議提交生成的 vendor/ 和 xu.lock，並使用 xu build main.xu --frozen。編譯器將嚴格禁止任何外部網路請求，保障構建的 100% 確定性與安全。

更多模組圖解析細節與原生模組規範，請參考：模組與相依性規範 (Modules & Dependencies) 與 原生模組規範。
