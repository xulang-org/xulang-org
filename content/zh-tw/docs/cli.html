命令列與工具鏈參考

Xu {{xu_version}} · 統一單二進位制驅動 xu <command> [options] [arguments]

xu 採用統一單二進位制驅動架構，原生整合了 AOT 編譯器、語義檢查器、測試執行器、相依性包管理、程式碼格式化、文件提取、流程圖繪製、LSP 語言服務以及線上熱更新等完整工具鏈。所有命令與子工具均已完整支援官方統一的 --help 與 -h 結構化排版幫助輸出。

1. 編譯與執行 (build / run / check)

輸入規則

  • 檔案輸入：xu build main.xu。單個或多個 .xu 檔案直接參與編譯。
  • 目錄輸入：xu build app/。目標目錄必須包含 xu.xun 清單，會將該目錄下所有 *.xu 原始碼合併編譯為一個包，不遞迴遍歷子目錄。
  • 靜態庫連結：支援在命令列直接追加 module.a 或 module.xulib 原生靜態庫歸檔參與目標連結。

編譯與最佳化選項

xu build、xu run 和 xu test 預設開啟最佳化。傳入 --no-opt 關閉最佳化。Xu 0.12.2 已移除 -O0 至 -O3。

選項說明
-o, --output <path>指定輸出檔案路徑。Windows 平臺自動附加 .exe 副檔名。
--no-opt關閉編譯器最佳化。
--debug-build無最佳化構建，同時生成標準 DWARF 行號表與除錯資訊。
-g, --debug按所選最佳化策略構建，並生成 DWARF 除錯資訊。
--offline離線構建模式：僅從本地 vendor/ 或快取目錄讀取相依性，絕不觸發網路請求。
--frozen凍結構建模式：離線且嚴格匹配現有的 xu.lock；若相依性缺失或摘要不符則強制失敗。
--xacp嵌入 XACP 啟動發現資訊與 stdio 控制鉤子。./app --xacp-help 印表機器可讀摘要（capabilities: stdio）。僅限 hosted native 可執行程式。
--xacp-port <PORT>同時啟用 XACP。PORT 為 0 到 65535 的整數（也接受 --xacp-port=PORT）。0 關閉 TCP。正埠是 <app> --xacp-tcp 在 127.0.0.1 上監聽的埠。
--desktop圖形桌面程式打包模式：呼叫 xu-desktop 打包（生成 macOS .app、Windows .exe、Linux ELF）。不能與 --xacp 一起使用。
--phone生成移動應用專案。輸入為模組目錄，目標為 ios-arm64、ios-simulator-arm64 或 android-arm64。用 -o 指定一個尚不存在的輸出目錄。
--phone-profile <ui|game>選擇 --phone 的移動宿主模式：ui（預設 Canvas UI 宿主）或 game（原生 SDL GPU 遊戲宿主，支援 #app 資源打包）。
--bundle-id <ID>為 --phone 設定移動應用標識，例如 org.example.gallery。
--www <dir>桌面打包時指定嵌入的本地靜態前端資產目錄（覆蓋預設 www/）。
--emit-obj生成目標平臺的 XUOBJ 中間物件檔案供外部目標連結器使用，而不直接生成可執行檔案。

將 XU_DUMP_MIR 設為函式標籤的子串，可在機器碼生成前檢視命中函式最佳化後的型別化 MIR。設為 * 可輸出全部函式。

常用示例

# 使用預設最佳化編譯和執行
xu build main.xu -o myapp
xu run main.xu -- --port 8080 --verbose

# 關閉最佳化後執行
xu run main.xu --no-opt -- --port 8080

# 編譯為 WASI 執行時可載入的模組
xu build src/calc.xu --target wasm32-wasi -o dist/calc.wasm

# 根據現有鎖檔案離線構建
xu build . --frozen -o release/server

XACP 控制通道（xu xacp / xu-xacp）

#xacp API 已包含在正式 {{xu_version}} SDK 提取結果中。本節依據對應釋出原始碼。xu xacp 執行伴生工具 xu-xacp，原始碼樹用 make xu-xacp 構建。匯入 #xacp 不會嵌入發現資訊或控制迴圈。契約以釋出原始碼和冒煙指令碼為準；舊樣例 README/設計說明的分幀、許可權和超時描述可能過時。原生會話和平臺/UI 執行驗收仍為待驗。

xu --help 把該工具概括為 “inspect, run, and debug”。xu xacp --help 才是完整模式：inspect、run、debug、record、control、attach，以及 connect PORT。

構建與發現

xu build --xacp examples/xacp/main.xu -o app
xu build --xacp-port 4321 examples/xacp/main.xu -o app
./app --xacp-help

--xacp-port 隱含 --xacp。生成器只接受 hosted native 可執行程式。庫、共享物件、測試腳手架、嵌入式目標和 --desktop 都會被拒絕。--xacp-help 列印後退出，它不是控制會話。埠為 0 時摘要以 tcp: disabled (port 0) 結束。正埠會列印 tcp: enabled 和 bind: 127.0.0.1:PORT。兩種情況下 capabilities 都是 stdio。掃描在 -- 處停止，因此寫在該標記之後的業務引數 --xacp-help 不會觸發發現。

啟動器模式

模式行為
xu xacp inspect <program>執行 <program> --xacp-help 並列印發現文字。不接受業務引數。目標程式會被執行。
xu xacp run <program> -- args...執行業務 main。在轉發引數前再插入一個 --。不讀取控制 stdin。
xu xacp debug <program> -- args...先發現，再按同樣邊界執行。不是斷點偵錯程式。發現失敗則不會繼續執行。
xu xacp record <program> -- args...流式輸出最多 1 MiB 的 stdout，由呼叫方自行重定向。stderr 仍留給終端。僅 Unix；Windows 列印 record is not available on Windows yet 並以狀態 1 退出。它與 ui.record 的有界 XAR1 UI 取樣不同。
xu xacp control <program>以 <program> --xacp-stdio 啟動，並繼承呼叫方的 stdin 與 stdout。不接受業務引數。業務 main 不執行。Hello 在請求 finish 之前協商 INFO 或宿主令牌許可權。
xu xacp attach <program> -- args...執行業務 main；應用必須呼叫 attach_stdio、註冊 Screen，並在所屬協程中輪詢。協議獨佔 stdin/stdout；日誌寫入 stderr。UI 執行行為待驗。
xu xacp connect PORT把帶幀的 stdin/stdout 中繼到 127.0.0.1:PORT。一次請求，再等一次響應。目標必須已經用 --xacp-tcp 在監聽。PORT 為 1..65535。輸入幀使用 XACP/1\n<N>\n，後接恰好 N 位元組正文。幀邊界上的 EOF 會斷開連線。

run、debug、record、attach 的引數必須寫在工具自己的 -- 之後。inspect 與 control 拒絕額外引數。子程序失敗時，工具能讀到退出狀態就會原樣返回。

stdio 與本機迴環 TCP

用 Python 3 生成與指南完全一致的 hello 位元組，儲存為 control.xacp：

python3 - <<'PY'
from pathlib import Path
body = b"id: !i 1\nop: xacp.hello\nargs:\n  ver: !ver 1.0.0\n  nonce: docs-client\n"
Path("control.xacp").write_bytes(b"XACP/1\n" + str(len(body)).encode("ascii") + b"\n" + body)
PY
# stdio：管道送入幀；業務 main 被跳過
xu xacp control ./app < control.xacp

# TCP：用正埠構建，先監聽，再從另一個終端連線
xu build --xacp-port 4321 main.xu -o app
./app --xacp-tcp
xu xacp connect 4321 < control.xacp

兩種傳輸均使用 XACP/1\n<N>\n 加恰好 N 位元組純 XUN 正文。按 UTF-8 位元組計數，包含正文換行，不含字首；沒有結束分隔符或額外分隔位元組。傳輸解碼後，parse_frame 只接收正文。API 指南給出 69 位元組 hello 和 109 位元組響應。-- 之前首個 --xacp-stdio 或 --xacp-tcp 生效；普通啟動不監聽，也不讀取控制 stdin。

TCP 只監聽 127.0.0.1。沒有 TLS，也不能繫結其他地址。每個連線是獨立會話。連線按順序處理。失敗的對端只結束自己的會話，監聽繼續接受。stdio 會話結束時程序退出。EOF 時的半幀返回 truncated_frame。超過 1 MiB 的幀返回 frame_too_large 並關閉該會話。幀錯誤的 id 為 0；schema 錯誤儘量使用有效的 id 提示，否則使用 0。

Hello 必須提供 ver: !ver 1.0.0 和非空 nonce。宿主未設定 XU_XACP_TOKEN 時許可權至多為 INFO；設定後，客戶端令牌缺失或不匹配會以 auth_failed 關閉會話，匹配後允許請求 PERM_ALL（15）的子集。INFO 下 proc.status 返回 pid。輸出/UI 操作需要相應許可權位，沒有介面卡時返回 not_implemented。啟動控制沒有註冊 Screen；UI 附著需要註冊和輪詢，預設請求期限為 5000 ms，可用 XU_XACP_REQUEST_TIMEOUT_MS（1..600000）配置。目標掛起時，呼叫方仍需程序/I/O 超時。

2. 自動化測試 (test)

向 xu test 傳入一個或多個 Xu 原始檔。0.12.2 構建的臨時程式會執行所提供的 main 函式，請在該入口呼叫測試。將示例儲存為 test.example.xu。

@main

fn test_add() {
    assert(1 + 1 == 2)
}

fn main() {
    test_add()
}
xu test test.example.xu
xu test test.example.xu --no-opt
xu test test.example.xu -list

-list 列出無引數的 fn test_* 宣告。

3. 專案初始化與相依性管理 (init / get / install)

0.8.x 提供了現代化、零外部相依性的專案管理與相依性解析體系，從根源杜絕相依性漂移：

xu init [module]：初始化工程清單與入口

在當前目錄下快速初始化一個規範的 Xu 專案：

# 1. 採用當前目錄名作為模組名初始化工程
xu init

# 2. 顯式指定模組名稱初始化工程
xu init myapp
  • 自動生成清單：生成規範的 xu.xun 清單檔案並自動登記當前編譯器版本（例如 xu: !ver {{xu_version}}）。若當前目錄已存在 xu.xun，則自動報錯攔截，避免覆蓋現有配置。
  • 自動生成入口原始碼：若當前目錄下尚未建立 main.xu，自動生成標準的入口原始碼模板。
  • 即開即用：初始化完成後，在當前目錄直接執行 xu run . 即可秒級編譯執行。

xu get <module>@<version> (0.8.12 核心新增)

在當前專案根目錄下顯式新增或更新單個相依性模組：

xu get <module>@<version>

上述命令為語法模板，請將佔位符替換為真實模組及其釋出標籤。本站官方擴充套件包請使用SDK 內建包或對應固定原始碼提交，再執行 xu install。

  • 顯式版本約束：必須提供精確的 SemVer 版本（選擇的模組已釋出且確認存在的標籤）；拒絕使用 @latest 或萬用字元，從根源確保構建絕對確定性。
  • 事務原子保障：自動解析相依性圖、下載原始碼到本地 vendor/、校驗 SHA-256 完整性並更新 xu.xun 和 xu.lock。若過程中斷或網路失敗，自動原子回滾，不破壞現有工程。
  • 離線更新：支援 xu get <module>@<version> --offline，僅使用本地已有的包快取完成新增。

xu install [dir]

根據專案 xu.xun 中已宣告的 require: 規則，一鍵還原整個相依性拓撲圖至本地 vendor/：

xu install                      # 還原當前目錄專案相依性
xu install --offline            # 離線模式：僅使用本地全域性快取 (~/.xu/pkg)

詳見 官方擴充套件包列表 與 模組與相依性規範細則。

5. 系統維護與線上更新 (doctor / setup / update)

xu doctor：環境健康體檢

xu doctor                       # 診斷當前系統 C 連結器與基礎編譯工具
xu doctor --desktop             # 診斷桌面打包工具鏈 (WebKitGTK, GTK4, WebView2, MinGW)

xu setup：原生安裝嚮導

配套的 xu-setup 擁有自繪純原生圖形嚮導與控制檯靜默模式，可隨時重新配置全域性環境：

xu setup -y                     # 靜默一鍵配置全域性 PATH 與 XU_ROOT
xu setup --prefix /opt/xu -y   # 指定目標安裝目錄進行安裝
xu setup --cli                  # 強制控制檯互動模式 (無圖形介面的伺服器)

xu up / xu update：官方 Release 熱升級

直接自舉更新 xu 自身及伴生工具鏈，支援自動校驗 SHA-256 簽名並執行原子替換：

xu up --check                   # 僅檢查官方 GitHub Releases 是否有新版本
xu up                           # 自動下載並升級至最新正式穩定版
xu update --version {{xu_version}}        # 鎖定並更新/降級至指定版本
xu update --force               # 強制重新安裝當前相同版本

6. 原生 C 模組與多目標打包 (xu native)

伴生原生工具 xu-native 已全面整合為一級子命令 xu native，負責在不相依性任何額外指令碼的情況下完成跨平臺原生 C 橋接庫的構建、後設資料嵌入與多架構切片聚合：

# 1. 編譯 C 原始碼並注入 .xumeta 規範切片 (.a)
xu native compile --manifest native.json --target macos-arm64 bridge.c -o native/native_add-arm64.a

# 2. 聚合多平臺切片為行動式單一分發容器 (.xulib)
xu native pack --manifest native.json --slice macos-arm64=native/native_add-arm64.a --slice macos-x64=native/native_add-x64.a -o native/native_add.xulib

# 3. 檢視 .xulib 容器切片架構、大小與 SHA-256 校驗和
xu native inspect native/native_add.xulib

# 4. 從 .xulib 提取指定目標架構的切片
xu native extract native/native_add.xulib --target macos-arm64 -o slice.a

7. 環境變數與全域性配置 (xu env)

執行 xu env 可以快速列印當前工具鏈的有效環境變數配置。常用控制變數如下：

環境變數預設值作用與配置說明

XU_STDLIB_ROOT$XU_ROOT/src顯式指定標準庫原始碼所在目錄。

8. 語言服務協議與編輯器支援 (xu lsp)

伴生工具 xu-lsp 原生實現了微軟語言服務協議（Language Server Protocol, JSON-RPC 2.0），透過標準輸入輸出 stdin/stdout 與各類現代 IDE（VS Code、Cursor、Neovim、Helix 等）無縫協作：

# 啟動 LSP 守護程序（一般由編輯器外掛後臺自動啟動）
xu lsp

# 檢視 LSP 引數與使用說明
xu lsp --help

核心服務能力包括：語法與借用錯誤實時診斷、F12 / Cmd+Click 跳轉定義、Markdown 型別與文件懸停提示、符號大綱（Cmd+Shift+O）、智慧程式碼補全、查詢全部引用（Shift+F12）與重新命名重構（F2）。詳見 VS Code / Cursor 外掛指南。

原始碼除錯（0.10.5）

xu debug 生成帶 DWARF 的除錯程式並呼叫宿主 LLDB/GDB；需先安裝偵錯程式。--break 設定原始碼行或函式斷點，--eval 執行偵錯程式命令，--batch 用於批處理。--binary 可除錯已有可執行檔案。

xu debug --help
xu debug --break main.xu:8 --run main.xu
xu debug --binary ./app --batch --eval "image lookup -n main"
