자주 묻는 질문 (FAQ)

Xu 언어 설계, 메모리 모델, OS 커널 및 베어메탈 개발, AOT 컴파일러, 네이티브 UI, 에디터 지원, 의존성 관리 및 C 네이티브 상호 운용에 관한 핵심 Q&A

총 23개 질문

Xu 프로그래밍 언어란 무엇인가요?

Xu는 컴파일 타임 메모리 안전성을 갖춘 고성능 시스템 프로그래밍 언어입니다. Go 스타일의 코루틴과 채널 동시성 모델에 C/Rust급 Zero-GC 결정론적 메모리 관리를 결합했습니다.

Xu의 핵심 설계 목표는 무엇인가요?

핵심 목표는 런타임 오버헤드 제거, 자동 소유권 추론을 통한 간결한 문법, 라이프타임 주석의 복잡성 제거, 독립형 네이티브 AOT 컴파일러 및 C/C++ 상호 운용성입니다.

Xu는 가비지 컬렉터(GC) 없이 어떻게 메모리 안전성을 보장하나요?

단일 소유권 및 대여 검사 메커니즘을 적용하여 컴파일 타임에 리소스 수명을 추적하고 스코프 종료 즉시 자동으로 정리(RAII)하여 메모리 누수를 원천 차단합니다.

Xu의 대여 검사기(Borrow Checker)는 어떻게 작동하나요?

불변 대여 &T와 가변 대여 &mut T를 지원하며, 컴파일러가 동시성 안전 규칙(다중 읽기 또는 단일 쓰기)을 엄격히 검증합니다.

Xu의 동시성 모델은 어떻게 설계되었나요?

xu 키워드로 초경량 사용자 공간 코루틴을 생성하고, 타입 안전한 chan<T> 채널을 통해 락 없이 스레드 안전한 데이터 교환을 수행합니다.

Xu에서 데이터 레이스(경합 상태)가 발생할 수 있나요?

코루틴 간 데이터 전송 시 소유권 이동(Move) 또는 불변 복사를 강제하므로 컴파일 타임에 데이터 레이스 가능성이 제거됩니다.

Xu 코루틴의 스케줄링 및 실행 모델은 무엇인가요?

M:N 하이브리드 스케줄러와 플랫폼별 비동기 I/O(epoll, kqueue, IOCP)를 결합하여 단일 프로세스에서 수백만 동시 연결을 안정적으로 처리합니다.

Xu의 오류 처리 메커니즘은 무엇인가요?

예외(try/catch) 대신 기호 기반 제어 흐름(<< 반환, >> 오류)과 catch 표현식으로 명시적이고 빠른 오류 처리를 제공합니다.

Xu는 객체 지향 프로그래밍을 지원하나요?

클래스 상속 대신 '상속보다 조합' 원칙을 채택하여 struct, 확장 메서드, interface를 통해 유연한 다형성을 구현합니다.

Xu는 운영체제 커널 및 베어메탈 펌웨어 개발을 어떻게 지원하나요?

Xu는 운영체제 마이크로커널, 임베디드 펌웨어 및 하드웨어 디바이스 드라이버 개발을 네이티브로 지원합니다. 런타임 가비지 컬렉터(GC)에 의존하는 언어나 복잡한 수동 수명(Lifetime) 주석이 필요한 언어와 달리, Xu는 엄격하게 계층화된 시스템 아키텍처를 제공합니다:

  • 일반 시스템 컴포넌트 및 커널 서비스 로직에서는 암시적 소유권 추론과 컴파일 타임 제로 GC 결정론적 소멸을 유지하여 수동 수명 주석(<'a>) 없이도 안전합니다;
  • 최하위 하드웨어 제어(전체 코드의 약 5%)에서는 프리스탠딩(freestanding) 모드, 원시 포인터(*raw T), 휘발성 MMIO 메모리 배리어(volatile_read / volatile_write), 순수 정적 코어 라이브러리(#core)를 통해 마이크로 아키텍처를 정밀하게 제어합니다.

커널 예제 및 명세는 공식 kernel_poc 개념 검증 프로젝트 및 Xu 0.14.0 릴리스 노트를 참조하세요.

프리스탠딩(Freestanding Profile)이란 무엇이며, 외부 OS 의존성을 어떻게 차단하나요?

프리스탠딩 프로파일은 컴파일된 실행 파일이 외부 운영체제의 시스템 호출(Syscalls), 동적 링커 및 C 런타임 라이브러리(libc)에 전혀 의존하지 않는 모드입니다. Xu는 세 가지 설정 방식을 제공합니다:

  • 소스코드 레벨: 소스 파일 첫 줄에 $freestanding 컴파일 태그 선언;
  • 프로젝트 매니페스트: 프로젝트 설정 파일 xu.xun에 profile: freestanding 명시;
  • CLI 컴파일 옵션: 빌드 시 --profile=freestanding 또는 --no-std 인자 전달.

이 모드를 활성화하면 호스트 OS 런타임과 기본 코루틴 스케줄러가 완전히 제거되며, 1.9 KB ~ 2.4 KB 크기의 순수 베어메탈 ELF/PE 커널 이미지를 직접 생성합니다.

표준 라이브러리가 없는 베어메탈 환경에서 #core는 어떤 하드웨어 추상화를 제공하나요?

Xu는 시스템 호출과 암시적 메모리 할당이 없는 순수 정적 기반 라이브러리 #core를 제공합니다:

  • #core/arch: CPU 특권 명령(cli, sti, hlt, pause, wfi), 컨트롤 레지스터(CR0/CR2/CR3/CR4, VBAR, SCTLR), 8259A PIC 재매핑, 8254 PIT 타이머 초기화, IDT 게이트 디스크립터 로드(load_idt);
  • #core/sync: 인터럽트 안전 스핀락 IrqSpinlock 및 Spinlock, RAII 가드(IrqGuard, SpinGuard)를 통한 스코프 종료 시 결정론적 언락 및 인터럽트 플래그 자동 복원(EFLAGS / PSTATE);
  • #core/task: 아키텍처 공통 192바이트 16바이트 정렬 TaskContext, 원자적 하드웨어 컨텍스트 스위칭(switch_context), TrapFrame 예외 스냅샷 및 시스템 호출 디스패치 엔트리;
  • #core/virtio: 정적 VirtIO MMIO 드라이버 프레임워크, VirtQueue 디스크립터 링, VirtioBlkDriver 블록 디바이스 및 VirtioNetDriver 가상 네트워크 카드;
  • #core/mem & #core/alloc: 제로 할당 메모리 프리미티브(memset/memcpy/memcmp) 및 플러그형 GlobalAlloc 전역 할당자 인터페이스.

커널에서 물리 메모리 매핑(MMIO)과 원시 포인터 연산을 안전하게 수행하려면 어떻게 하나요?

하드웨어 레지스터 및 디바이스 메모리 접근은 엄격한 문법적 격리 장치를 통해 처리됩니다:

  • 원시 포인터 타입 *raw T 및 unsafe { ... } 블록: 절대 물리 주소 재해석과 포인터 산술을 허용하지만, 역참조는 반드시 unsafe { ... } 블록 내에서만 수행되어야 합니다. 소유권 추론은 원시 포인터를 건너뛰므로 위험한 하드웨어 조작이 안전한 커널 로직으로 전파되지 않습니다;
  • 휘발성 메모리 배리어(Volatile MMIO): 내장 volatile_read 및 volatile_write 원시 연산자를 제공하여 컴파일러 최적화(DCE, LICM)로 인한 메모리 접근 누락이나 재배치를 방지합니다;
  • 정밀한 메모리 레이아웃 제어: @repr("C", align: N)(PML4 페이지 테이블용 4096바이트 정렬 등) 및 @repr("C", packed)(하드웨어 패킷 헤더용 무패딩 배치) 지원;
  • 스캐폴딩 및 에뮬레이션: xu init --baremetal my_os 명령어로 멀티 아키텍처 커널 프로젝트, 링커 스크립트(linker.ld) 및 Makefile을 한 번에 생성하고, make qemu로 QEMU 에뮬레이터에서 즉시 부팅 및 디버깅할 수 있습니다.

Xu는 C/C++ 네이티브 라이브러리와 어떻게 상호 운용하나요?

오버헤드 없는 C FFI 인터페이스를 통해 기존 C/C++ 정적 라이브러리(.a) 및 동적 라이브러리(.so, .dll, .dylib)를 즉시 링크하여 사용할 수 있습니다.

Xu는 어떤 운영체제 및 CPU 아키텍처를 지원하나요?

macOS(Apple Silicon, Intel), Linux(ARM64, x64, LoongArch, RISC-V), Windows(x64, ARM64), WebAssembly(WASI)를 공식 지원합니다. 또한 --profile=freestanding 옵션을 통해 베어메탈 및 OS 커널 개발(x86_64, aarch64, riscv64 ELF)을 완벽히 지원합니다.

Xu는 WebAssembly를 지원하나요?

완벽히 지원합니다. 컴파일러 백엔드가 wasm32-wasi 바이트코드를 직접 생성하여 브라우저 및 샌드박스 환경에서 구동됩니다.

Xu는 모듈과 종속성을 어떻게 관리하나요?

xu.xun 프로젝트 매니페스트와 xu.lock을 통해 의미론적 버전 관리(SemVer) 및 체크섬 무결성을 검증하여 재현 가능한 빌드를 보장합니다.

Xu에는 중앙 패키지 저장소가 있나요?

분산형 Git 저장소 참조 방식을 채택하며 공식 검증 패키지 생태계를 함께 제공합니다.

.xulib 정적 배포 패키지란 무엇인가요?

.xulib는 다중 아키텍처 바이너리와 심볼 정보를 하나로 패키징한 Xu 전용 네이티브 배포 형식입니다.

Xu의 네이티브 데스크톱 UI / WebView 아키텍처는 무엇인가요?

GPU 하드웨어 가속 기반의 선언형 데스크톱 UI 프레임워크와 양방향 통신을 지원하는 네이티브 WebView를 내장하고 있습니다.

Xu는 iOS 및 Android 모바일 앱 개발을 어떻게 지원하나요?

xu build --phone 명령으로 iOS 프레임워크 및 Android NDK 네이티브 라이브러리를 직접 빌드할 수 있습니다.

Xu에는 어떤 개발자 도구 및 IDE 통합이 제공되나요?

공식 VS Code 및 Cursor 확장 프로그램(xu-lsp)을 통해 지능형 코드 완성, 실시간 진단, 정의 이동, LLDB 디버깅을 지원합니다.

Xu의 현재 안정성 및 릴리스 상태는 어떠한가요?

현재 0.x 공식 릴리스 주기에 있으며, 핵심 구문 스펙은 이미 동결되었고 6대 주요 플랫폼에서 100% CI 검증을 통과했습니다.
