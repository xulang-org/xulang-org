模块与依赖

Xu {{xu_version}} · 0.8.4 签名校验日志 · 0.8.6 依赖图快照重构 · 0.8.8 跨架构依赖验证与构建分发规范

Xu 项目使用根目录下的 xu.xun 作为模块元数据清单。其中：module: 标识模块身份命名空间，version: 标识模块自身版本，xu: 声明最低兼容的 Xu 编译器版本。外部导入必须采用显式别名，并在 require: 中声明所属的根模块。

1. 声明与自动安装依赖 (xu get / xu install)

使用本站 API 时，请选择正式 SDK 内置的 packages 或对应的不可变源码提交。清单中的模块版本并不代表远端存在同名 Git 标签。

方式 A：使用 SDK 内置包

将项目放在解压后的 SDK 旁，在 xu.xun 中声明依赖；安装位置不同时调整本地路径：

module: app
version: !ver 0.1.0
xu: !ver {{xu_version}}
require:
  "github.com/xulang-org/packages": file:../xu-v{{xu_version}}/packages

方式 B：获取对应源码提交

将上述本地来源替换为 SDK 使用的固定源码快照：

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@96693e6cce8d51eba45e4f68dc12ce06f7a2336b

随后在项目目录执行：

xu install

对已经确认发布 SemVer 标签的模块，可使用 xu get <module>@<version> 添加或更新依赖、安装源码并更新 xu.lock。请将两个占位符替换为真实模块标识及发布标签。SDK 兼容性与原生桥准备见官方扩展包。

在源码中使用显式别名引用依赖

在 .xu 源码中使用显式别名导入具体的子包：

@main
#fmt
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    _ := mysql.driver()
    fmt.println("MySQL driver loaded successfully.")
    << 0
}

在 require: 中声明的是官方根模块 github.com/xulang-org/packages，代码中则通过完整的子路径导入具体包（如 mysql、redis、postgres、s3 等）。完整扩展包清单请查阅 官方扩展包 (Packages)。

2. 版本选择与来源定位

除 SemVer 发行版外，还可以指定已审查的不可变 Git 提交，或在本地协同研发时使用相对路径：

# 选项 A：锁定到指定 Git 提交
require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@<commit>

# 选项 B：本地协同开发（让 app 与 packages 目录同级放置）
require:
  "github.com/xulang-org/packages": file:../packages

Xu 采用 MVS（最小版本选择，Minimal Version Selection） 算法读取全部可达版本的清单，为每个模块选择图中最高的最低要求。MVS 不查询 latest，也不接受不可控的浮动版本范围。v2 及以上主版本模块使用匹配的 /vN 路径后缀。显式 file / Git / tar 来源继续获得原生支持，来源冲突时编译器会明确报错。

3. 安装、锁定与离线/冻结构建

对于工业级软件与 CI/CD 流程，Xu 提供了确定性锁机制与纯离线构建保障：

# 1. 开发阶段安装依赖
xu install

# 2. 离线环境类型与所有权检查（严禁联网下载）
xu check main.xu --offline

# 3. 生产发布完全冻结构建（要求依赖 100% 匹配现有锁，禁止任何网络与改写）
xu build main.xu --frozen --output app
构建模式 编译与网络行为规范
默认模式 允许联网下载并建立锁条目；已锁定的依赖哈希不匹配时立即报错失败。
--offline 禁止任何网络下载，仅使用本地来源、已校验缓存或 vendor/；仍可在本地建立锁条目。
--frozen 隐含离线模式。要求必须已有完全匹配的锁条目，严禁写依赖缓存或补锁；本地 file: 依赖须先安装为 vendor/ 快照。

推荐团队审查并提交 xu.lock 至版本控制系统。显式来源使用 v2 锁，版本图使用 v3 锁。xu install 在 vendor/ 中保留全部可达版本快照，支持无网络离线重放 MVS 依赖图。冻结依赖模式不会冻结主项目自身源码或编译产物。

4. 代理服务器与私有模块 (XUPROXY / XUPRIVATE)

# 配置镜像代理与直接连接回退
XUPROXY='https://proxy.example.com,direct' xu install

# 配置企业私有模块前缀（跳过公共代理与校验数据库）
XUPRIVATE='example.com/private/*' xu install

XUPROXY 接受 HTTP(S)、绝对 file://、direct 与 off，默认值为 direct。逗号仅在发生 404/410 时向后回退；竖线允许在任何请求错误后回退。模块身份或完整性哈希不匹配时始终立即中断失败。直接版本发现原生支持 GitHub 仓库，其他代码托管主机建议使用显式来源或配置企业专属 Xu 代理。

XUPRIVATE 是以逗号分隔的私有模块前缀 glob 列表；XUNOPROXY 默认沿用其取值并控制代理绕过。Xu 不假定公共代理已上线，Go 模块代理中的清单不能作为 Xu 依赖清单。

5. 独立校验与防篡改日志 (XUSUMDB)

自 0.8.4 起，Xu 引入了透明签名校验日志系统。XUSUMDB 接受可信 Ed25519 verifier 公钥及可选服务 URL。对 SemVer 模块，客户端会严格验证签名树头（Signed Tree Head）、模块摘要、包含证明（Inclusion Proof）以及日志追加一致性后才接受依赖。未设置或设为 off 时沿用首次使用信任（Trust on First Use）原则。XUNOSUMDB 独立控制校验绕过，默认继承 XUPRIVATE。

6. 原生 C/C++ 模块与 .xulib 支持

除了纯源码依赖，Xu 支持在 xu.xun 的 native: 节声明 C/C++ 原生模块。编译器既支持通用的标准 .a 静态归档库，也支持自带 ABI 元数据契约与跨平台架构切片的便携式 .xulib 容器包。详细规范与开发指南请参阅 原生模块与 .xulib 规范。

7. 旧版本工程平滑迁移

旧版本点式包路径已全面改为现代斜杠（/）路径规范，仅保留域名、版本号以及源码字段/方法访问中的点。当模块身份或旧锁格式发生变化时，请在审查后重新执行 xu install 刷新锁文件。严禁为跳过内容不匹配而直接删除当前锁文件。
