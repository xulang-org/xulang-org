工具链

Xu {{xu_version}} 提供 build、run、check、test、install、fmt、map、doc、doctor。产品构建由 Xu 编译器自举；冻结的 Rust bootstrap 用作初始引导与正确性参照。

语言仓库 0.10.10-dev.1 另有 xu xacp 以及构建标志 --xacp / --xacp-port。该控制通道写在命令行参考中，不属于上方已发布的 {{xu_version}} 命令清单。导入 #xacp 不会启用它。

默认目标为本机；交叉编译使用 --target linux-arm64 或 XUOS/XUARCH。XUPATH 在 Unix 用 :、Windows 用 ;，与目标平台无关；外部导入仍须有 xu.xun 映射。

普通 AOT 构建直接生成原生产物；桌面宿主和 SQLite 等原生扩展需要对应平台工具链。--emit-obj 输出 XUOBJ；--shared 导出支持 int/bool/string/f64/i32/u32/u8 基础类型签名。

原生输入与 .a / .xulib 规范

在编译可执行文件时，xu build 与 xu run 既支持在命令行直接追加原生静态库，也支持通过项目清单 xu.xun 的 native: 字段声明模块映射：

1. 命令行直接传入原生库进行编译链接：

xu build main.xu module.a -o main
xu build main.xu module.xulib -o main

2. 或在项目工程清单 xu.xun 中声明原生模块映射：

native:
  sqlite_native: file:./native/sqlite.xulib

工具链同时支持标准通用的 .a（Unix 静态归档）与便携式 .xulib 容器：

  • 通用 .a 静态库：单平台原生直连，适合本地开发与临时调试；静态库内嵌入带有导出签名的目标切片（xu.o），由系统原生链接器完成最后一步链接。
  • 便携式 .xulib 容器：用于跨平台模块分发。通用的 .a 仅包含单一系统架构且丢失函数参数/返回值类型元数据；.xulib 容器内嵌强类型 JSON Manifest 与各平台标准的 .a 架构切片。xu build 在编译期根据 --target 自动提取匹配切片并验证 SHA-256，静态类型检查期严格约束 C 导出调用，运行期保持零中间件开销。

编译器内置一级子命令 xu native 提供 compile（单目标 C 编译并注入元数据）、archive（原生对象打包）、pack（多切片聚合为 .xulib）、inspect（容器检视）与 extract（切片提取）命令。运行 xu doctor 可诊断本机 C 链接器与宿主构建环境的就绪状态。
