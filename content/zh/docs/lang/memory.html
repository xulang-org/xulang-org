内存模型

每个 owning 值同一时刻一个所有者。按值传参/返回/写入 owning 槽即 move。离开作用域确定性 drop。use-after-move 是编译错误。

写法含义
按值 string / []Tmove
&x共享借用
mut &x（x 须 mut）独占借用
*r解引用标量（写需 &mut）

共享借用存活期间不可写 / move / 再取 &mut。没有 unsafe 关键字。托管目标拒绝任意地址的 volatile 写。

0.9.4 的借用诊断

借用检查会遍历嵌套表达式。例如 f(mut &v, &v) 同时对 v 取得独占与共享借用，即使放在 int(f64(f(mut &v, &v)) * 32.0) 中也会报错。应传入不同的值，或拆开操作，先结束可变使用再取得共享借用。

循环体内产生的借用会在回边上保持活跃；下一轮迭代若与仍然活跃的借用冲突，也会被拒绝。升级后出现这类诊断时，应调整借用的作用域或所有权传递。完整迁移说明见 0.9.4 发布公告。

File、Conn 等资源采用 affine 所有权：move 转移资源，作用域退出时自动关闭，原生句柄保持包内可见。I/O 通过借用访问资源，使用进度 API 时须处理 EOF/错误携带的数据和明确的写入进度结果。
