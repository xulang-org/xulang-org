常用命令行参数：

  • --ctx <N> —— 限制并配置最大上下文序列长度。
  • --stride <N> —— 配置 perplexity 滑动窗口评测步长。
  • --grammar <path_or_inline>、--json-schema <path_or_json> —— 按 GBNF 上下文无关文法或原生 JSON Schema 约束 generate 采样（服务端支持 grammar、response_format 与 text.format）。
  • --models-dir <dir> —— 覆盖 models list|rm|pull 的本地缓存目录（默认 ~/.xu/models 或 XU_MODELS_DIR）。
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> —— 指定分页 KV 缓存存储精度（将 KV 显存/内存压缩为 1/2 或 1/4）。
  • --lora <path>、--lora-scale <f>、--lora-rank <N>、--lora-alpha <f>、--dataset <path>、--grad-accum <N>、--warmup-steps <N>、--lr-schedule <constant|cosine>、--save-ckpt <path>、--resume-ckpt <path>、--type <q4_0|q8_0|q4_k|q5_k|q6_k|q4_k_m|q5_k_m>、--mmproj <path>、--image <path|url|data_uri|rgb:...>、--verifier <contains|exact|json|math>、--group-size <K>、--gen-tokens <N>、--temp <milli>、--dpo-beta <f>、--clip-eps <f>、--kl-beta <f>、--teacher <path>、--distill-temp <f>、--distill-alpha <f>、--steps <N>、--lr <f>、--max-grad-norm <f> —— 加载/融合 PEFT SafeTensors LoRA 适配器、将 HF 目录/SafeTensors/GGUF 离线量化为 GGUF（quantize），或运行纯 Xu SFT train-lora（支持 AdamW 检查点续训）、train-dpo、train-grpo、在线可验证奖励 train-rlvr 与 train-distill 微调。
  • --draft <model>、--draft-k <N> —— 开启无损草稿模型投机采样与目标模型批量验证及精确 KV 缓存回滚。
  • --top-p <milli>、--min-p <milli>、--repeat-penalty <milli>、--presence-penalty <milli>、--frequency-penalty <milli>、--seed <int> —— 可复现核采样/Min-P 过滤与重复/存在/频率惩罚系数（1000 表示 1.0，支持任意正 top_k）。
  • --max-slots <N>、--api-key <K> —— 配置 serve 连续批处理最大并发槽位与 Bearer 密钥鉴权（/health 除外）。
  • --rope-type <auto|norm|neox> —— 指定 RoPE 配对布局（交错配对 norm 与拆半配对 neox；默认随 GGUF 架构自动识别）。
  • --ignore-eos —— 忽略 EOS 停止标记以运行定长吞吐基准测试。

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

基于 packages/metal 的 GPU 算力

在 Apple Silicon 平台上，官方外部包 packages/metal（v1.12.0 包发布版，导出 176 个原生符号并打包完整 6 平台 .xulib 切片）提供显式 F32Matrix、F16Matrix（MPSDataTypeFloat16）、原始字节写入（write_bytes）与六种量化权重存储——Q4Matrix（matrix_q4_0）、Q5Matrix（matrix_q5_0）、Q8Matrix（matrix_q8_0）、Q4KMatrix（matrix_q4_k）、Q5KMatrix（matrix_q5_k）与 Q6KMatrix（matrix_q6_k），并将单维/元素上限提升至 262,144 / 536,870,912；同时具备并发读锁隔离以及单命令缓冲区多算子批处理（Batch），配合非阻塞 Fence 与编译期借用和运行时形状/别名/设备守卫实现端到端 GPU 推理与训练：

@main
metal #"github.com/xulang-org/packages/metal"
#errors

fn gpu_ffn_batch(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                 w_gate &metal.Q4Matrix, w_up &metal.Q4Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>

    $b := d.begin_batch() >>>
    _ := b.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := b.gemv_q4_0_f32($&g, &normed, w_gate) >>>
    _ := b.gemv_q4_0_f32($&u, &normed, w_up) >>>
    _ := b.swiglu_f32($&out, &g, &u) >>>
    $f := b.commit() >>>
    _ := f.wait() >>>
    << out
}

适用边界与已知局限（选型前必读）

坦诚说明：Xu AI 栈强调零外部 C/C++ 运行库依赖与可控二进制体积，在以下场景存在明确的能力上限与性能权衡，请按实际负载选型。

  • 推理计算为纯 CPU 单线程，尚未接入 GPU：examples/llm_engine 当前不调度 packages/metal GPU，也不支持 CUDA / ROCm / Vulkan；xu 协程负责 HTTP 并发与连续批处理槽位调度，单步矩阵算子仍为单线程 CPU 执行。适合中小量化模型、嵌入式单文件工具与 CI 数值回归校验，不适合替代多卡 vLLM 或 GPU llama.cpp 承担 7B–70B 大模型生产高并发服务。
  • 量化路径性能差异与暂缺格式：ARM64 SDOT / p4k4 SIMD 快路径主要加速 F32、Q4_0 与 Q8_0；Q4_K / Q5_K / Q6_K / Q5_0 走纯 Xu #tensor 标量与分块解码路径（微模型实测约 54–58 tok/s，显著慢于 Q4_0×Q8_0 SDOT 的约 19k tok/s）。暂不支持 GGUF 的 Q2_K、Q3_K、Q4_1、Q5_1 及 imatrix IQ1–IQ4。
  • VLM --mmproj 与图像格式限制：vision/mod.xu 读取与 Xu ViT+MLP 布局匹配的 F32 SafeTensors（vision.*、v.patch_embd.weight、v.blk.*、mm.0/mm.2），不能直接加载上游 llama.cpp 的 mmproj-*.gguf；图像解码支持 PNG、JPEG、PPM 与无压缩 24-bit BMP（不支持 WebP、AVIF、HEIC）。
  • GBNF 与 --json-schema 约束边界：文法状态归一化上限为 64 个活跃分支（工作队列 512、嵌套深度 48）；json_schema_to_gbnf 支持 type / properties / required / items / enum / const / anyOf / oneOf 且按固定顺序输出键（先必填后可选），尚不支持 $ref/$defs、allOf、pattern 正则、数值/长度上下限及 additionalProperties: false 下的任意键序；超大词表（128k+）每步掩码开销高于预编译 DFA/bitmask 引擎。
  • 训练范围与 macOS 签名：train-lora / train-dpo / train-grpo / train-rlvr / train-distill 均为单机 CPU f32 LoRA 微调（无 GPU/多机训练与全量预训练，merge-lora 导出 F32 SafeTensors）；xu build 产物未内嵌代码签名，在 macOS ARM64 运行前须执行 codesign --force --sign - ./binary。
  • 生态包常见踩坑点：metal 仅限 Apple Silicon macOS 且尚未接入 llm_engine；rag.SqliteVectorStore 检索阶段需将行加载入内存做 $O(N)$ 全量余弦计算（适合万级以内切片，更大规模请用 PgVectorClient HNSW 或 QdrantVectorStore）；postgres 与 sqlite 已支持任意数量参数绑定，但 PgVectorClient 为单连接无内置连接池；a2a 与 gateway 的任务/熔断/限流/语义缓存均为单进程内存态，SSE 故障转移仅在首包前生效；AgentSwarm 仅编排 OpenAI 兼容 Agent；guardrails 本地规则需搭配 check_safety_openai 防御复杂越狱；eval.evaluate_json_schema 仅校验扁平 []SchemaFieldRule。
