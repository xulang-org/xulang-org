构建与运行本地 LLM 引擎（llm_engine）

examples/llm_engine/main.xu 将模型加载、视觉编码器、GBNF 语法约束与量化逻辑拆分为纯标准库子包（models、vision、gbnf、quantize），同时保留核心 MIR 融合核，支持从权重检查、量化打包、约束采样、PEFT 微调对齐到多槽连续批处理服务的全流程；Xu v0.14.3+ 已内置 Mach-O ad-hoc 签名，无需手动执行 codesign。

常用全局与子命令开关：

  • --threads <N>、--ctx <N>、--kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> —— 控制多线程推理、上下文长度与分页 KV 精度。
  • --grammar <path_or_inline>、--json-schema <path_or_json>、--gbnf-max-branches <N> —— 启用 VocabIndex Trie 语法与 Schema 约束解码并调节 NFA 分支上限。
  • --mmproj <path>、--image <path|url|data_uri|rgb:...> —— 加载 mmproj.gguf 或 SafeTensors 视觉投影并将图片注入 <image> 槽位。
  • --draft <model>、--draft-k <N>、--lora <path>、--lora-scale <f> —— 组合无损草稿投机解码与热插拔 LoRA 适配器。
  • --top-p <milli>、--min-p <milli>、--repeat-penalty <milli>、--presence-penalty <milli>、--frequency-penalty <milli>、--seed <int>、--rope-type <auto|norm|neox>、--ignore-eos —— 精确采样惩罚、RoPE 排布与停用词控制（1000 = 1.0）。
  • --max-slots <N>、--api-key <K>、--models-dir <dir>、--stride <N> —— serve 调度槽位/鉴权及模型目录/评测步长控制。

@main
#tensor

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

编译器选项与 MIR 张量融合

启用 --tensor-fusion（或环境变量 XU_TENSOR_FUSION=1）后，Xu 编译器 MIR 层自动识别 #tensor 与用户源码中的习惯数值循环，在保持冻结运行时 ABI 不变的前提下将其下沉为 ARM64 NEON / SDOT 与 x86-64 SSE2 / SSSE3 原生微内核（含 v0.14.3 新增 K-quant SIMD 路径）：

内核族MIR 运行时符号硬件指令路径
向量算子 __xu_tensor_dot_f32、__xu_tensor_axpy_f32、__xu_tensor_vadd_inplace_f32、__xu_tensor_vsub_f32、__xu_tensor_vmul_f32 ARM64 NEON fmul.4s / fmla.4s / fsub.4s；x64 SSE2 mulps / addps / subps
归一化与激活 __xu_tensor_add_sqsum_f32、__xu_tensor_norm_f32、__xu_tensor_swiglu_f32、__xu_tensor_softmax_scaled_f32 高维隐藏层归约、方差累计与向量化激活
浮点与量化矩阵乘法 __xu_tensor_gemv4_f32、__xu_tensor_gemm4x4_f32、__xu_tensor_gemv4_q4_0_p4k4_signed_f16_q8_0_f32、__xu_tensor_gemm4x8_q8_0_p4k4_f16_q8_0_f32 + K-quant SIMD 4×8 分块微内核，支持 ARM64 sdot.4s 与 x64 SSE2/SSSE3 算力对等及 K-quant 向量内积
分页注意力与 RoPE __xu_tensor_rope_f32、__xu_tensor_attn_scores_paged_f32、__xu_tensor_attn_vsum_paged_f32 支持 head_dim % 4 == 0（如 64、128、40）跨双架构分页解码
  • --tensor-fusion / XU_TENSOR_FUSION=1 —— 开启 SIMD 与量化矩阵下沉（默认保持 fusion-strict 精确浮点语义）。
  • --tensor-fast-math / XU_TENSOR_FAST_MATH=1 —— 解锁归约重结合、快速指数近似与深度展开流水线。

@main
gpu #"github.com/xulang-org/packages/gpu"
llm_metal #"github.com/xulang-org/packages/llm_metal"

fn run_gpu_inference(model_path string) {
    println(gpu.detect_backends().join(", "))
    $model := llm_metal.load_model(model_path, 2048) >>>
    $kv := llm_metal.new_paged_kv_cache(&model, 2048, 16) >>>
    tokens := llm_metal.generate_paged(&model, &[1, 2, 3], 32, 16)
    println(llm_metal.decode_tokens(&model, &tokens))
    _ := kv.close()
    _ := model.close()
}

已知局限与工程边界

工程提示：Xu AI 栈在零外部 C/C++ 推理库绑定与高集成度之间做了明确权衡，采用前请核对下述已验证边界：

  • llm_engine 为多线程 CPU 推理（GPU 推理见 llm_metal / gpu）：examples/llm_engine 已支持 --threads N 多核 CPU 并行，但仍不直接绑定 CUDA/Metal；Apple Silicon GPU 端到端推理请使用 packages/llm_metal，跨厂商 GPU 算子调用请使用 packages/gpu（统一分发至 metal / cuda_native / vulkan_native / CPU）。
  • 量化与训练精度边界：GGUF 已支持 K-quant（Q2_K–Q8_K）、Q4_0/Q4_1/Q5_0/Q5_1/Q8_0 与 K-quant SIMD，但 imatrix IQ1–IQ4 尚未支持；llm_engine 的 train-* 与 llm_metal.train_lora_step 均面向 LoRA 微调与对齐（f32 参数更新），不包含多机分布式全参预训练；图像解码支持 PNG/JPEG/PPM 与非压缩 24-bit BMP（不含 WebP/AVIF/HEIC）。
  • 向量存储与高并发网关选型：rag.SqliteVectorStore 在进程内缓存并扫描切片（$O(N)$ 精确检索，适合约万级以内语料），超大规模与高并发在线检索请使用 v1.16.0+ 的连接池化 PgVectorPool（HNSW/IVFFlat）或 QdrantVectorStore；gateway 现支持通过 Redis 共享熔断/限流/费用与缓存状态，但 SSE 流式故障转移仍仅在首个流块发出前触发，且生产环境仍建议在 a2a 前置反代/TLS 并为高风险场景启用 guardrails.strict_policy + 模型级安全审查。
  • Apple Silicon 签名已内置：自 Xu 0.14.3 起编译器已在发行与调试构建中直接嵌入 Mach-O LC_CODE_SIGNATURE，无需额外手动执行 codesign；如使用自定义第三方静态 .dylib（如自编译 metal_native）仍可通过环境变量按需覆盖路径。
