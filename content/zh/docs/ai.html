无需引入 C/C++ 第三方推理运行库，使用纯 Xu 从底层构建端到端 AI 系统：标准库 #tensor 低精度表示与数值原语、编译器 MIR SIMD 张量融合（ARM64 NEON/SDOT 与 x86-64 SSE2/SSSE3）、带 OpenAI 兼容 HTTP 服务的 examples/llm_engine/main.xu 本地推理引擎、Metal GPU 算子与纯 Xu openai、mcp 及向量数据库驱动。

编译并运行示例

examples/llm_engine/main.xu 是零外部运行库依赖的纯 Xu Transformer 推理引擎，原生支持 Safetensors 与 GGUF v2/v3（混合量化 Q4_K_M 含 Q4_K/Q6_K，以及 F32、F16、BF16、FP8 E4M3、Q4_0、Q5_0、Q8_0 与零拷贝压缩权重 / p4k4 布局），并自动解析 GGUF 元数据（rope_freq_scale、logit_softcap、分词器类型/架构及聊天模板）。引擎支持 Qwen3/Gemma2 逐头 qk_norm、多模板自动识别（ChatML、Llama-3、Gemma、Mistral）与多 EOS 终止、低精度分页 KV 缓存（--kv-dtype f32|f16|bf16|fp8_e4m3fn）、突破 2048 隐藏维度上限、SentencePiece（▁ / <0xHH>）与 GPT-2 预分词及 BPE 合并、$O(L)$ 采样器（top_k、top_p、--min-p、--repeat-penalty、--presence-penalty、--frequency-penalty），并在 serve 模式下提供 ARM64 多槽批处理解码、SSE 客户端断连取消与 KV 回收、Prefix KV 缓存复用、批量 /v1/embeddings、stream_options.include_usage、CORS 预检、--api-key 鉴权与 --max-slots 并发槽位配置。

./bin/xu build --tensor-fusion --tensor-fast-math examples/llm_engine/main.xu -o llm_engine
# （或使用 XU_TENSOR_FUSION=1 XU_TENSOR_FAST_MATH=1 ./bin/xu build ...）

# 使用 FP8 KV 缓存验证连续批处理与单请求数学一致性
./llm_engine verify model.gguf --kv-dtype fp8_e4m3fn

# 带 BPE 合并、Min-P / Top-P 核采样与重复/存在/频率惩罚的文本生成
./llm_engine generate model.gguf "Hi Paris" 64 700 40 \
  --kv-dtype f16 --top-p 900 --min-p 50 --repeat-penalty 1100 \
  --presence-penalty 100 --frequency-penalty 50 --seed 42

# 启动 OpenAI 兼容 HTTP 服务（/health、/v1/models、/v1/completions、/v1/chat/completions、/v1/embeddings）
# 支持 SSE 流式输出（含 stream_options.include_usage）、批量嵌入、CORS 预检与 Bearer 密钥认证
./llm_engine serve model.gguf 127.0.0.1:8080 --kv-dtype bf16 --max-slots 4 --api-key secret

常用命令行参数：

  • --ctx <N> —— 限制并配置最大上下文序列长度。
  • --kv-dtype <f32|f16|bf16|fp8_e4m3fn|fp8_e5m2|fp8_e4m3fnuz|fp8_e5m2fnuz> —— 指定分页 KV 缓存存储精度（将 KV 显存/内存压缩为 1/2 或 1/4）。
  • --top-p <milli>、--min-p <milli>、--repeat-penalty <milli>、--presence-penalty <milli>、--frequency-penalty <milli>、--seed <int> —— 可复现核采样/Min-P 过滤与重复/存在/频率惩罚系数（1000 表示 1.0，支持任意正 top_k）。
  • --max-slots <N>、--api-key <K> —— 配置 serve 连续批处理最大并发槽位与 Bearer 密钥鉴权（/health 除外）。
  • --ignore-eos —— 忽略 EOS 停止标记以运行定长吞吐基准测试。

#tensor 模块与数值原语

标准库 #tensor 提供安全的纯 Xu 低精度标量编码、跨步视图、GGML 量化块与 src/tensor/ops.xu 中的 20 个通用数值算子：

层次公开 API职责
标量编码 F16、BF16、Fp8E4M3Fn、Fp8E5M2、Fp8E4M3Fnuz、Fp8E5M2Fnuz、DType 位精确 IEEE/OCP FP16、BF16 与四种 FP8 互转，及运行时 dtype_named 解析
视图与量化块 TensorView（reshape、permute、read_f32_bytes、write_f32_bytes）、Q4Block、Q5Block、Q8Block、Q4KBlock、Q6KBlock、dot_q4_k_bytes_f32、dot_q6_k_bytes_f32、dot_q8_0_bytes_f32、dot_q5_0_bytes_f32 零拷贝形状重排/轴转置与字节视图读写、GGML 32/256 元素量化块解码与零分配字节内积
向量与相似度 dot_f32、axpy_f32、vadd_f32、vsub_f32、vmul_f32、vscale_f32、l2_normalize_f32、cosine_similarity_f32、argmax_f32 带偏移点积、FMA 累加、逐元素加减乘运算、L2 归一化、余弦相似度与最大值索引
Transformer 与量化 silu_f32、gelu_f32、rmsnorm_f32、layernorm_f32、softmax_f32、swiglu_f32、rope_f32、matvec_f32、matmul_f32、quantize_q8_0、quantize_q4_0_row 激活函数、RMSNorm/LayerNorm、Softmax、NeoX RoPE、GEMV/GEMM 与 Q8_0/Q4_0 行量化 
@main
#tensor

fn run_block(w &[]f32, x &[]f32) []f32 {
    n := x.len
    $normed := []f32{}
    $out := []f32{}
    for _ in 0:n {
        normed.push(f32(0))
        out.push(f32(0))
    }
    tensor.rmsnorm_f32($&normed, x, w, n, 0.00001)
    tensor.vscale_f32($&normed, f32(0.5), n)
    tensor.softmax_f32($&normed, n, f32(1))
    tensor.vmul_f32($&out, &normed, x, n)
    << out
}

编译选项与 MIR 张量融合

在 --tensor-fusion（或 XU_TENSOR_FUSION=1）编译模式下，编译器 MIR 张量降级通道会直接识别 #tensor 与用户代码中的规范纯 Xu 数值循环，在保持冻结运行时 ABI 不变的前提下下沉为原生 ARM64 NEON / SDOT 与 x86-64 SSE2 / SSSE3 机器码内核：

算子类别MIR 运行时内核符号目标指令集加速
向量算子 __xu_tensor_dot_f32、__xu_tensor_axpy_f32、__xu_tensor_vadd_inplace_f32、__xu_tensor_vsub_f32、__xu_tensor_vmul_f32 ARM64 NEON fmul.4s/fmla.4s/fsub.4s；x64 SSE2 mulps/addps/subps
归一化与激活 __xu_tensor_add_sqsum_f32、__xu_tensor_norm_f32、__xu_tensor_swiglu_f32、__xu_tensor_softmax_scaled_f32 向量化平方和与指数规约流水线
矩阵与量化乘加 __xu_tensor_gemv4_f32、__xu_tensor_gemm4x4_f32、__xu_tensor_gemv4_q4_0_p4k4_signed_f16_q8_0_f32、__xu_tensor_gemm4x8_q8_0_p4k4_f16_q8_0_f32 4×8 分块微内核，支持 ARM64 sdot.4s 与 x64 SSE2/SSSE3 对等实现
分页注意力与 RoPE __xu_tensor_rope_f32、__xu_tensor_attn_scores_paged_f32、__xu_tensor_attn_vsum_paged_f32 覆盖 head_dim % 4 == 0（含 64、128、40 等）与双架构
  • --tensor-fusion / XU_TENSOR_FUSION=1 —— 开启 MIR 张量模式匹配与硬件内核降级（fusion-strict 保持与纯 Xu 基线逐比特一致）。
  • --tensor-fast-math / XU_TENSOR_FAST_MATH=1 —— 启用重结合浮点规约、快速指数逼近与高吞吐量化展开。

基于 packages/metal 的 GPU 算力

在 Apple Silicon 平台上，官方外部包 packages/metal（v1.4.0）提供显式 F32Matrix、F16Matrix（MPSDataTypeFloat16）、原始字节写入（write_bytes）与量化权重存储——Q4Matrix（matrix_q4_0）、Q8Matrix（matrix_q8_0）与 Q4KMatrix（matrix_q4_k），并将单维/元素上限提升至 262,144 / 536,870,912；同时具备并发读锁隔离以及单命令缓冲区多算子批处理（Batch），配合非阻塞 Fence 与编译期借用和运行时形状/别名/设备守卫实现端到端 GPU 推理：

@main
metal #"github.com/xulang-org/packages/metal"
#errors

fn gpu_ffn_batch(d &metal.Device, x &metal.F32Matrix, w &metal.F32Matrix,
                 w_gate &metal.Q4Matrix, w_up &metal.Q4Matrix) metal.F32Matrix {
    $normed := d.matrix_f32(x.rows(), x.columns()) >>>
    $g := d.matrix_f32(x.rows(), w_gate.rows()) >>>
    $u := d.matrix_f32(x.rows(), w_up.rows()) >>>
    $out := d.matrix_f32(x.rows(), w_gate.rows()) >>>

    $b := d.begin_batch() >>>
    _ := b.rmsnorm_f32($&normed, x, w, 0.00001) >>>
    _ := b.gemv_q4_0_f32($&g, &normed, w_gate) >>>
    _ := b.gemv_q4_0_f32($&u, &normed, w_up) >>>
    _ := b.swiglu_f32($&out, &g, &u) >>>
    $f := b.commit() >>>
    _ := f.wait() >>>
    << out
}

metal 独立调用与 Batch 模式共同公开的 GPU AI 算子涵盖：gemm_f32、gemm_f32_nt、rmsnorm_f32、layernorm_f32、softmax_f32、gelu_f32、swiglu_f32、add_f32、mul_f32、scale_f32、rope_f32、qk_norm_f32、kv_cache_append_f32、attention_decode_f32、causal_attention_f32、embedding_f32、argmax_f32、gemm_f16、gemm_f16_nt、f16_to_f32、f32_to_f16 与寄存器即时反量化融合量化 GEMV（gemv_q4_0_f32、gemv_q8_0_f32、gemv_q4_k_f32）。

OpenAI 客户端、MCP、向量数据库与智能体自动化

围绕张量算子与本地推理引擎，Xu 生态还提供纯 Xu 客户端/服务端驱动与内建智能体交互协议：

  • OpenAI 与 MCP（外部包）：github.com/xulang-org/packages/openai 提供类型安全的纯 Xu OpenAI 兼容客户端（list_models、chat、chat_stream / chat_stream_chan 流式 SSE、工具调用与 embeddings）；github.com/xulang-org/packages/mcp 实现 Model Context Protocol JSON-RPC 2.0（2025-03-26）stdio 服务端及 Streamable HTTP JSON/SSE 客户端（tools、resources、prompts）。
  • 向量数据库（外部包）：提供 qdrant、milvus、chroma 的纯 Xu HTTP/gRPC 驱动，可直接把 RAG 检索链路与本地模型推理编译进同一个零依赖静态二进制。
  • 智能体自动化（XACP 与 #xacp API）：为本地 Xu 桌面应用提供结构化界面树、受限采样与审计化自动化操控能力。
