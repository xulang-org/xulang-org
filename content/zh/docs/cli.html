命令行与工具链参考

Xu {{xu_version}} · 统一单二进制驱动 xu <command> [options] [arguments]

xu 采用统一单二进制驱动架构，原生集成了 AOT 编译器、语义检查器、测试运行器、依赖包管理、代码格式化、文档提取、流程图绘制、LSP 语言服务以及在线热更新等完整工具链。所有命令与子工具均已完整支持官方统一的 --help 与 -h 结构化排版帮助输出。

1. 编译与运行 (build / run / check)

输入规则

  • 文件输入：xu build main.xu。单个或多个 .xu 文件直接参与编译。
  • 目录输入：xu build app/。目标目录必须包含 xu.xun 清单，会将该目录下所有 *.xu 源码合并编译为一个包，不递归遍历子目录。
  • 静态库链接：支持在命令行直接追加 module.a 或 module.xulib 原生静态库归档参与目标链接。

编译与优化选项

选项说明
-o, --output <path>指定输出文件路径。Windows 平台自动附加 .exe 扩展名。
--no-opt关闭全部 MIR 优化与默认寄存器分配（禁用函数内联与激进折减），极速构建。
--debug-build无优化构建，同时生成标准 DWARF 行号表与调试信息。
--debug生成 DWARF 行号表，保留当前选择的优化策略。默认优化等级为 1；等级 2 须显式指定 -O2。
--timings在标准错误 stderr 输出解析、MIR 优化、寄存器分配与代码生成的阶段耗时，以及 pattern-hits: 模式命中统计和每个函数的寄存器分配模式。
--offline离线构建模式：仅从本地 vendor/ 或缓存目录读取依赖，绝不触发网络请求。
--frozen冻结构建模式：离线且严格匹配现有的 xu.lock；若依赖缺失或摘要不符则强制失败。
--xacp嵌入 XACP 启动发现信息与 stdio 控制钩子。./app --xacp-help 打印机器可读摘要（capabilities: stdio）。仅限 hosted native 可执行程序。
--xacp-port <PORT>同时启用 XACP。PORT 为 0 到 65535 的整数（也接受 --xacp-port=PORT）。0 关闭 TCP。正端口是 <app> --xacp-tcp 在 127.0.0.1 上监听的端口。
--desktop图形桌面程序打包模式：调用 xu-desktop 打包（生成 macOS .app、Windows .exe、Linux ELF）。不能与 --xacp 一起使用。
--www <dir>桌面打包时指定嵌入的本地静态前端资产目录（覆盖默认 www/）。
--emit-obj生成目标平台的 XUOBJ 中间对象文件供外部目标链接器使用，而不直接生成可执行文件。
--cover在基本块插桩覆盖率计数器，用于覆盖率收集与分析。

# 1. 常规编译与运行

# 3. 生产环境严格离线与冻结构建
xu build . --frozen -o release/server

# 4. 打印编译管线详细性能与耗时统计
xu build main.xu --timings -o server

0.9.4 编译器诊断

定位编译或优化问题时，可通过以下环境变量控制诊断。它们不改变项目清单中的版本要求。

环境变量作用
XU_VERIFY=1在每个优化 pass 后运行完整 MIR 验证器，检查中间表示的一致性。
XU_DUMP_MIR=<函数名>导出指定函数的 MIR，便于检查降级与优化结果。
XU_PATTERNS_OFF=all关闭全部具名后端模式；也可传入逗号分隔的模式名。用于与默认构建对拍，未知名称会报错。
# macOS / Linux：验证每个 pass 并查看模式命中
XU_VERIFY=1 xu build main.xu --timings -o myapp

# 导出 main 的 MIR
XU_DUMP_MIR=main xu build main.xu -o myapp

# 生成关闭后端模式的对照产物
XU_PATTERNS_OFF=all xu build main.xu -o myapp-reference

PowerShell 中先设置变量，例如 $env:XU_VERIFY = '1'，再运行相同的 xu build 命令；诊断完成后用 Remove-Item Env:XU_VERIFY 清除。

XACP 控制通道（xu xacp / xu-xacp）

#xacp API 已包含在正式 {{xu_version}} SDK 提取结果中。本节依据对应发布源码。xu xacp 执行伴生工具 xu-xacp，源码树用 make xu-xacp 构建。导入 #xacp 不会嵌入发现信息或控制循环。契约以发布源码和冒烟脚本为准；旧样例 README/设计说明的分帧、权限和超时描述可能过时。原生会话和平台/UI 运行验收仍为待验。

xu --help 把该工具概括为 “inspect, run, and debug”。xu xacp --help 才是完整模式：inspect、run、debug、record、control、attach，以及 connect PORT。

构建与发现

xu build --xacp examples/xacp/main.xu -o app
xu build --xacp-port 4321 examples/xacp/main.xu -o app
./app --xacp-help

--xacp-port 隐含 --xacp。生成器只接受 hosted native 可执行程序。库、共享对象、测试脚手架、嵌入式目标和 --desktop 都会被拒绝。--xacp-help 打印后退出，它不是控制会话。端口为 0 时摘要以 tcp: disabled (port 0) 结束。正端口会打印 tcp: enabled 和 bind: 127.0.0.1:PORT。两种情况下 capabilities 都是 stdio。扫描在 -- 处停止，因此写在该标记之后的业务参数 --xacp-help 不会触发发现。

启动器模式

模式行为
xu xacp inspect <program>运行 <program> --xacp-help 并打印发现文本。不接受业务参数。目标程序会被执行。
xu xacp run <program> -- args...运行业务 main。在转发参数前再插入一个 --。不读取控制 stdin。
xu xacp debug <program> -- args...先发现，再按同样边界运行。不是断点调试器。发现失败则不会继续运行。
xu xacp record <program> -- args...流式输出最多 1 MiB 的 stdout，由调用方自行重定向。stderr 仍留给终端。仅 Unix；Windows 打印 record is not available on Windows yet 并以状态 1 退出。这不是 XACP UI 帧文件。
xu xacp control <program>以 <program> --xacp-stdio 启动，并继承调用方的 stdin 与 stdout。不接受业务参数。业务 main 不运行。Hello 在请求 finish 之前协商 INFO 或宿主令牌权限。
xu xacp attach <program> -- args...运行业务 main；应用必须调用 attach_stdio、注册 Screen，并在所属协程中轮询。协议独占 stdin/stdout；日志写入 stderr。UI 运行行为待验。
xu xacp connect PORT把带帧的 stdin/stdout 中继到 127.0.0.1:PORT。一次请求，再等一次响应。目标必须已经用 --xacp-tcp 在监听。PORT 为 1..65535。输入帧使用 XACP/1\n<N>\n，后接恰好 N 字节正文。帧边界上的 EOF 会断开连接。

run、debug、record、attach 的参数必须写在工具自己的 -- 之后。inspect 与 control 拒绝额外参数。子进程失败时，工具能读到退出状态就会原样返回。

stdio 与本机回环 TCP

用 Python 3 生成与指南完全一致的 hello 字节，保存为 control.xacp：

python3 - <<'PY'
from pathlib import Path
body = b"id: !i 1\nop: xacp.hello\nargs:\n  ver: !ver 1.0.0\n  nonce: docs-client\n"
Path("control.xacp").write_bytes(b"XACP/1\n" + str(len(body)).encode("ascii") + b"\n" + body)
PY
# stdio：管道送入帧；业务 main 被跳过
xu xacp control ./app < control.xacp

# TCP：用正端口构建，先监听，再从另一个终端连接
xu build --xacp-port 4321 main.xu -o app
./app --xacp-tcp
xu xacp connect 4321 < control.xacp

两种传输均使用 XACP/1\n<N>\n 加恰好 N 字节纯 XUN 正文。按 UTF-8 字节计数，包含正文换行，不含前缀；没有结束分隔符或额外分隔字节。传输解码后，parse_frame 只接收正文。API 指南给出 69 字节 hello 和 109 字节响应。-- 之前首个 --xacp-stdio 或 --xacp-tcp 生效；普通启动不监听，也不读取控制 stdin。

TCP 只监听 127.0.0.1。没有 TLS，也不能绑定其他地址。每个连接是独立会话。连接按顺序处理。失败的对端只结束自己的会话，监听继续接受。stdio 会话结束时进程退出。EOF 时的半帧返回 truncated_frame。超过 1 MiB 的帧返回 frame_too_large 并关闭该会话。帧错误的 id 为 0；schema 错误尽量使用有效的 id 提示，否则使用 0。

Hello 必须提供 ver: !ver 1.0.0 和非空 nonce。宿主未设置 XU_XACP_TOKEN 时权限至多为 INFO；设置后，客户端令牌缺失或不匹配会以 auth_failed 关闭会话，匹配后允许请求 PERM_ALL（15）的子集。INFO 下 proc.status 返回 pid。输出/UI 操作需要相应权限位，没有适配器时返回 not_implemented。启动控制没有注册 Screen；UI 附着需要注册和轮询，默认请求期限为 5000 ms，可用 XU_XACP_REQUEST_TIMEOUT_MS（1..600000）配置。目标挂起时，调用方仍需进程/I/O 超时。

2. 自动化测试 (test)

xu test 自动识别并编译测试用例。测试和基准函数必须位于 test.<name>.xu 文件中，属于 @main 包，且不带参数和返回类型。普通源文件不能声明 fn test_* 或 fn bench_*。将以下示例保存为 test.example.xu：

@main

fn test_add() {
    assert(1 + 1 == 2)
}
xu test test.example.xu -v
测试选项说明
-run <REGEXP>正则过滤：仅运行函数名匹配该正则表达式的测试用例。
-v详细模式：打印每个独立用例的执行状态（PASS/FAIL）与物理耗时。
-count <N>重复执行测试套件 N 次（当前解析器接受 1–1000；CLI 帮助仍写 1–100）。
-failfast一旦发生第一个断言失败立即停止后续测试。
-list列出所有符合匹配规则的用例名称并正常退出，不实际执行测试。
-short快速测试模式：在代码中 testing.short() 将判定为 true，用例可主动跳过耗时场景。
-bench <REGEXP>同时执行名称匹配正则的性能基准用例（fn bench_*）。
--cover在测试完成后汇总并打印代码块覆盖率统计数据。
# 运行项目下所有单测并输出耗时详情
xu test app/ -v

# 仅运行匹配网络相关测试，并在遇到第一个错误时中断
xu test . -run "net_.*" -failfast

# 运行性能基准测试
xu test . -bench "bench_sha256"

3. 项目初始化与依赖管理 (init / get / install)

0.8.x 提供了现代化、零外部依赖的项目管理与依赖解析体系，从根源杜绝依赖漂移：

xu init [module]：初始化工程清单与入口

在当前目录下快速初始化一个规范的 Xu 项目：

# 1. 采用当前目录名作为模块名初始化工程
xu init

# 2. 显式指定模块名称初始化工程
xu init myapp
  • 自动生成清单：生成规范的 xu.xun 清单文件并自动登记当前编译器版本（例如 xu: !ver {{xu_version}}）。若当前目录已存在 xu.xun，则自动报错拦截，避免覆盖现有配置。
  • 自动生成入口源码：若当前目录下尚未创建 main.xu，自动生成标准的入口源码模板。
  • 即开即用：初始化完成后，在当前目录直接执行 xu run . 即可秒级编译运行。

xu get <module>@<version> (0.8.12 核心新增)

在当前项目根目录下显式添加或更新单个依赖模块：

xu get <module>@<version>

上述命令为语法模板，请将占位符替换为真实模块及其发布标签。本站官方扩展包请使用SDK 内置包或对应固定源码提交，再执行 xu install。

  • 显式版本约束：必须提供精确的 SemVer 版本（选择的模块已发布且确认存在的标签）；拒绝使用 @latest 或通配符，从根源确保构建绝对确定性。
  • 事务原子保障：自动解析依赖图、下载源码到本地 vendor/、校验 SHA-256 完整性并更新 xu.xun 和 xu.lock。若过程中断或网络失败，自动原子回滚，不破坏现有工程。
  • 离线更新：支持 xu get <module>@<version> --offline，仅使用本地已有的包缓存完成添加。

xu install [dir]

根据项目 xu.xun 中已声明的 require: 规则，一键还原整个依赖拓扑图至本地 vendor/：

xu install                      # 还原当前目录项目依赖
xu install --offline            # 离线模式：仅使用本地全局缓存 (~/.xu/pkg)

详见 官方扩展包列表 与 模块与依赖规范细则。

6. 原生 C 模块与多目标打包 (xu native)

伴生原生工具 xu-native 已全面整合为一级子命令 xu native，负责在不依赖任何额外脚本的情况下完成跨平台原生 C 桥接库的构建、元数据嵌入与多架构切片聚合：

# 1. 编译 C 源码并注入 .xumeta 规范切片 (.a)
xu native compile --manifest native.json --target macos-arm64 bridge.c -o native/native_add-arm64.a

# 2. 聚合多平台切片为便携式单一分发容器 (.xulib)
xu native pack --manifest native.json --slice macos-arm64=native/native_add-arm64.a --slice macos-x64=native/native_add-x64.a -o native/native_add.xulib

# 3. 检视 .xulib 容器切片架构、大小与 SHA-256 校验和
xu native inspect native/native_add.xulib

# 4. 从 .xulib 提取指定目标架构的切片
xu native extract native/native_add.xulib --target macos-arm64 -o slice.a

7. 环境变量与全局配置 (xu env)

运行 xu env 可以快速打印当前工具链的有效环境变量配置。常用控制变量如下：

环境变量默认值作用与配置说明
XU_ROOT~/.xu当前激活的 Xu 编译器与工具链安装根目录。
XU_STDLIB_ROOT$XU_ROOT/src显式指定标准库源码所在目录。
XUPATH空模块与包查找根路径（Unix 采用冒号 : 分隔，Windows 采用分号 ;）。
XU_CACHE~/.xu/pkg网络依赖包下载缓存目录。
XUPROXYdirect依赖模块代理服务器 URL。支持多代理逗号 ,（404 时回退）与竖线 |（网络错误时回退）。
XUPRIVATE空私有模块前缀通配符，匹配的模块自动绕过代理与公开校验服务。
XUSUMDBdirect固定公钥校验日志服务器；配置为 off 时保持首次使用信任（TOFU）。
XUOS当前宿主系统当省略 --target 时默认采用的目标操作系统（linux, macos, windows, none）。

8. 语言服务协议与编辑器支持 (xu lsp)

伴生工具 xu-lsp 原生实现了微软语言服务协议（Language Server Protocol, JSON-RPC 2.0），通过标准输入输出 stdin/stdout 与各类现代 IDE（VS Code、Cursor、Neovim、Helix 等）无缝协作：

# 启动 LSP 守护进程（一般由编辑器插件后台自动启动）
xu lsp

# 查看 LSP 参数与使用说明
xu lsp --help

核心服务能力包括：语法与借用错误实时诊断、F12 / Cmd+Click 跳转定义、Markdown 类型与文档悬停提示、符号大纲（Cmd+Shift+O）、智能代码补全、查找全部引用（Shift+F12）与重命名重构（F2）。详见 VS Code / Cursor 插件指南。

源码调试（0.10.5）

xu debug 生成带 DWARF 的调试程序并调用宿主 LLDB/GDB；需先安装调试器。--break 设置源码行或函数断点，--eval 执行调试器命令，--batch 用于批处理。--binary 可调试已有可执行文件。

xu debug --help
xu debug --break main.xu:8 --run main.xu
