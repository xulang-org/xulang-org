命令行与工具链参考

Xu {{xu_version}} · 统一单二进制驱动 xu <subcommand> [flags]

xu 采用统一单二进制驱动架构，原生集成了 AOT 编译器、语义检查器、单测运行器、依赖包管理、代码格式化、文档提取、流程图绘制以及在线热更新等完整工具链。

子命令速查表

子命令语法核心作用
buildxu build <file|dir> [flags]AOT 编译为原生机器码二进制、共享库、WebAssembly 模块或跨平台桌面程序
runxu run <file|dir> [flags] [-- args]编译并立即运行（仅限本机架构）；默认自动清理临时产物，指定 -o 可持久化保留
checkxu check <file|dir> [flags]执行词法、语法解析与类型/所有权借用检查，不生成二进制目标文件
testxu test <file|dir> [flags]自动扫描测试源码并构建运行器，批量执行 fn test_* 与 fn bench_*
getxu get <module>@<version> [--offline](0.8.12 新增) 显式添加或升级依赖，写入 xu.xun，下载至 vendor/ 并更新 xu.lock
installxu install [dir] [--offline]根据现有 xu.xun 的 require: 规则解析依赖图，批量下载至 vendor/ 并校验锁文件

1. 编译与运行 (build / run / check)

输入规则

  • 文件输入：xu build main.xu。单个或多个 .xu 文件直接参与编译。
  • 目录输入：xu build app/。目标目录必须包含 xu.xun 清单，会将该目录下所有 *.xu 源码合并编译为一个包，不递归遍历子目录。
  • 静态库链接：支持在命令行直接追加 module.a 或 module.xulib 原生静态库归档参与目标链接。

全平台交叉编译目标 (--target)

Xu 编译器全平台原生内置全部架构后端，无需安装额外工具链即可直接跨平台生成：

编译与优化选项

选项说明
-o, --output <path>指定输出文件路径。Windows 平台自动附加 .exe 扩展名。
--no-opt关闭全部 MIR 优化与默认寄存器分配（禁用函数内联与激进折减），极速构建。
--debug-build无优化构建，同时生成标准 DWARF 行号表与调试信息。
--debug在保留高优化（O2 级别）的前提下生成 DWARF 行号表。
--timings在标准错误 stderr 输出解析、MIR 优化、寄存器分配与代码生成的精确阶段耗时统计。
--offline离线构建模式：仅从本地 vendor/ 或缓存目录读取依赖，绝不触发网络请求。
--frozen冻结构建模式：离线且严格匹配现有的 xu.lock；若依赖缺失或摘要不符则强制失败。
--desktop图形桌面程序打包模式：调用 xu-desktop 打包（生成 macOS .app、Windows .exe、Linux ELF）。
--www <dir>桌面打包时指定嵌入的本地静态前端资产目录（覆盖默认 www/）。
--emit-obj生成目标平台的 XUOBJ 中间对象文件供外部目标链接器使用，而不直接生成可执行文件。
--cover在基本块插桩覆盖率计数器，用于覆盖率收集与分析。

常用示例

# 1. 常规编译与运行
xu build main.xu -o myapp
xu run main.xu -- --port 8080 --verbose

# 2. 交叉编译为 WebAssembly 模块并在浏览器中使用
xu build src/calc.xu --target wasm32 -o dist/calc.wasm

# 3. 生产环境严格离线与冻结构建
xu build . --frozen -o release/server

# 4. 打印编译管线详细性能与耗时统计
xu build main.xu --timings -o server

2. 自动化测试 (test)

xu test 自动识别并编译测试用例。任何包含 fn test_* 的源文件（或 test.*.xu）均可被直接执行：

测试选项说明
-run <REGEXP>正则过滤：仅运行函数名匹配该正则表达式的测试用例。
-v详细模式：打印每个独立用例的执行状态（PASS/FAIL）与物理耗时。
-count <N>重复执行测试套件 N 次（最大支持 100 次，用于复现偶发并发问题）。
-failfast一旦发生第一个断言失败立即停止后续测试。
-list列出所有符合匹配规则的用例名称并正常退出，不实际执行测试。
-short快速测试模式：在代码中 testing.short() 将判定为 true，用例可主动跳过耗时场景。
-bench <REGEXP>同时执行名称匹配正则的性能基准用例（fn bench_*）。
--cover在测试完成后汇总并打印代码块覆盖率统计数据。
# 运行项目下所有单测并输出耗时详情
xu test app/ -v

# 仅运行匹配网络相关测试，并在遇到第一个错误时中断
xu test . -run "net_.*" -failfast

# 运行性能基准测试
xu test . -bench "bench_sha256"

3. 项目初始化与依赖管理 (init / get / install)

0.8.x 提供了现代化、零外部依赖的项目管理与依赖解析体系，从根源杜绝依赖漂移：

xu init [module]：初始化工程清单与入口

在当前目录下快速初始化一个规范的 Xu 项目：

# 1. 采用当前目录名作为模块名初始化工程
xu init

# 2. 显式指定模块名称初始化工程
xu init myapp
  • 自动生成清单：生成规范的 xu.xun 清单文件并自动登记当前编译器版本（例如 xu: !ver {{xu_version}}）。若当前目录已存在 xu.xun，则自动报错拦截，避免覆盖现有配置。
  • 自动生成入口源码：若当前目录下尚未创建 main.xu，自动生成标准的入口源码模板。
  • 即开即用：初始化完成后，在当前目录直接执行 xu run . 即可秒级编译运行。

xu get <module>@<version> (0.8.12 核心新增)

在当前项目根目录下显式添加或更新单个依赖模块：

xu get github.com/xulang-org/packages@v0.1.1
  • 显式版本约束：必须提供精确的 SemVer 版本（如 @v0.1.1）；拒绝使用 @latest 或通配符，从根源确保构建绝对确定性。
  • 事务原子保障：自动解析依赖图、下载源码到本地 vendor/、校验 SHA-256 完整性并更新 xu.xun 和 xu.lock。若过程中断或网络失败，自动原子回滚，不破坏现有工程。
  • 离线更新：支持 xu get <module>@<version> --offline，仅使用本地已有的包缓存完成添加。

xu install [dir]

根据项目 xu.xun 中已声明的 require: 规则，一键还原整个依赖拓扑图至本地 vendor/：

xu install                      # 还原当前目录项目依赖
xu install --offline            # 离线模式：仅使用本地全局缓存 (~/.xu/pkg)

详见 官方扩展包列表 与 模块与依赖规范细则。

4. 代码工具与文档 (fmt / doc / map)

xu fmt：官方标准格式化

xu fmt src/main.xu -w           # 原地格式化单个文件
xu fmt src/ -w                  # 递归格式化 src/ 下的所有 .xu 源码
xu fmt main.xu                  # 仅将格式化结果输出至终端 stdout，不修改原文件

xu doc：API 文档提取与实时预览

# 1. 提取所有公开 API 生成 Markdown 文档
xu doc src/net --public -o docs/net.md

# 2. 启动内置 XUDOCS Web 实时文档服务器 (默认监听 127.0.0.1:6060)
xu doc src/ --serve --addr 127.0.0.1:8080

--serve 启动的 HTTP 服务内置提供 / 交互浏览、/docs.md 原始 Markdown 以及 /health 健康检查端点。

xu map：源码拓扑与流程图生成

# 生成标准 Mermaid flowchart 流程图
xu map src/main.xu -o flow.mmd

# 输出轻量机器可读的节点与连线数据，供绘图画布渲染
xu map src/ --graph

5. 系统维护与在线更新 (doctor / setup / update)

xu doctor：环境健康体检

xu doctor                       # 诊断当前系统 C 链接器与基础编译工具
xu doctor --desktop             # 诊断桌面打包工具链 (WebKitGTK, GTK4, WebView2, MinGW)

xu setup：原生安装向导

配套的 xu-setup 拥有自绘纯原生图形向导与控制台静默模式，可随时重新配置全局环境：

xu setup -y                     # 静默一键配置全局 PATH 与 XU_ROOT
xu setup --prefix /opt/xu -y   # 指定目标安装目录进行安装
xu setup --cli                  # 强制控制台交互模式 (无图形界面的服务器)

xu up / xu update：官方 Release 热升级

直接自举更新 xu 自身及伴生工具链，支持自动校验 SHA-256 签名并执行原子替换：

xu up --check                   # 仅检查官方 GitHub Releases 是否有新版本
xu up                           # 自动下载并升级至最新正式稳定版
xu update --version {{xu_version}}        # 锁定并更新/降级至指定版本
xu update --force               # 强制重新安装当前相同版本

6. 环境变量与全局配置 (xu env)

运行 xu env 可以快速打印当前工具链的有效环境变量配置。常用控制变量如下：

环境变量默认值作用与配置说明
XU_ROOT~/.xu当前激活的 Xu 编译器与工具链安装根目录。
XU_STDLIB_ROOT$XU_ROOT/src显式指定标准库源码所在目录。
XUPATH空模块与包查找根路径（Unix 采用冒号 : 分隔，Windows 采用分号 ;）。
XU_CACHE~/.xu/pkg网络依赖包下载缓存目录。
XUPROXYdirect依赖模块代理服务器 URL。支持多代理逗号 ,（404 时回退）与竖线 |（网络错误时回退）。
XUPRIVATE空私有模块前缀通配符，匹配的模块自动绕过代理与公开校验服务。
XUSUMDBdirect固定公钥校验日志服务器；配置为 off 时保持首次使用信任（TOFU）。
XUOS当前宿主系统当省略 --target 时默认采用的目标操作系统（linux, macos, windows, none）。
XUARCH当前宿主架构当省略 --target 时默认采用的目标硬件架构（arm64, x64, riscv64 等）。
