官方扩展包 (Packages)

官方模块：github.com/xulang-org/packages · SDK 内模块版本 0.2.0 · 29 个服务集成包及共享 transport 包

Xu {{xu_version}} SDK 包含外部驱动及原生源码资源，官网 API 从该安装包提取。驱动涵盖数据库、缓存、消息、对象存储与服务发现；协议和平台边界见各包说明。

1. 选择 SDK 内置包或固定源码提交

将项目放在解压后的 SDK 旁，通过本地来源声明内置 packages；安装位置不同时调整相对路径：

module: my_app
version: !ver 0.1.0
xu: !ver {{xu_version}}
require:
  "github.com/xulang-org/packages": file:../xu-v{{xu_version}}/packages

也可以指定该 SDK 使用的完整不可变提交来获取源码：

require:
  "github.com/xulang-org/packages": git:https://github.com/xulang-org/packages.git@0122e87a5f87b52d3ead9390ad01165e7d7645ad

在项目目录中解析并锁定依赖，再检查和构建：

xu install
xu check main.xu --offline
xu build main.xu -o my_app

模块版本与 Git 标签分别管理：本安装包声明模块版本 0.2.0，以上固定源码地址直接选择准确提交。请将 xu.lock 与应用一同维护；冻结构建、vendor 和代理用法见模块与依赖。

2. 在代码中引用扩展包

Xu 对所有外部扩展包采用明确的命名空间别名机制，语法格式为：别名 #完整包路径。这不仅避免了全局命名污染，也保证了所有代码依赖关系透明可见。

@main

// 1. 标准库无需别名，以 # 开头
#database/sql
#fmt

// 2. 外部 packages 扩展包声明别名与完整路径（别名即代码中的调用命名空间）
mysql    #github.com/xulang-org/packages/mysql
redis    #github.com/xulang-org/packages/redis
postgres #github.com/xulang-org/packages/postgres

fn main() int {
    // 使用别名进行调用
    fmt.println("Drivers loaded successfully")
    << 0
}

注意：不能写 #mysql 或 #redis。# 仅用于官方标准库；所有外部扩展包均属于 github.com/xulang-org/packages 根模块，必须带有完整的仓库命名空间。

3. 快速上手实战示例

实战 1：配合 database/sql 使用 MySQL 驱动

标准库 database/sql 提供连接池、事务与结果集抽象，具体的驱动实现由 packages 的 mysql 包提供：

@main
#database/sql
#fmt
mysql #github.com/xulang-org/packages/mysql

fn main() int {
    dsn := "root:123456@tcp(127.0.0.1:3306)/test_db?tls=false"
    mut db := sql.open(mysql.driver(), dsn)
    db.ping() or (err) {
        fmt.println("Database ping failed:", err.msg())
        << 1
    }
    fmt.println("Connected to MySQL successfully!")
    db.close() or (err) { << 1 }
    << 0
}

实战 2：连接与操作 Redis 缓存

@main
#fmt
redis #github.com/xulang-org/packages/redis

fn main() int {
    mut client := redis.connect("127.0.0.1:6379") or (err) {
        fmt.println("Redis connect error:", err.msg())
        << 1
    }
    client.set("app_version", "v0.8.12") or (err) { << 1 }
    val := client.get("app_version") or (err) { << 1 }
    fmt.println("Key 'app_version':", val)
    client.close()
    << 0
}

实战 3：使用 S3 / MinIO 进行对象存储

@main
#fmt
s3 #github.com/xulang-org/packages/s3

fn main() int {
    mut client := s3.new("endpoint.example.com", "access_key", "secret_key", "my-bucket")
    client.put_object("welcome.txt", "Hello from Xu!") or (err) {
        fmt.println("S3 upload failed:", err.msg())
        << 1
    }
    fmt.println("Object uploaded successfully")
    << 0
}

5. 边界与注意事项

  • SQLite 原生依赖与 .xulib：SQLite 驱动底层通过 C 语言桥接。官方扩展包采用了便携式的 .xulib 多架构切片容器（内嵌 macos-arm64、macos-x64 等通用 .a 切片与 ABI 校验元数据）。如果在 packages 仓库源码环境中二次开发，需在 packages 根目录执行 make native 生成底层架构切片。详细机制与通用 .a 的差异对比见 原生模块与 .xulib 规范。
  • 离线与生产构建（Frozen Builds）：在生产 CI/CD 流水线中，建议提交生成的 vendor/ 和 xu.lock，并使用 xu build main.xu --frozen。编译器将严格禁止任何外部网络请求，保障构建的 100% 确定性与安全。

更多模块图解析细节与原生模块规范，请参考：模块与依赖规范 (Modules & Dependencies) 与 原生模块与 .xulib 规范。

构建 SQLite 原生桥接

SQLite 示例须先从内置 C 源码构建原生桥接。以下命令已在 macOS ARM64 验证，请在 SDK 的 packages 目录执行，并安装匹配的 C 工具链。其他目标需要对应工具链与目标切片。

cd xu-v{{xu_version}}/packages
xu native compile --manifest sqlite/native/native.json --target macos-arm64 -O2 -DSQLITE_THREADSAFE=1 -DSQLITE_OMIT_LOAD_EXTENSION=1 sqlite/native/bridge.c sqlite/vendor/sqlite3.c -o sqlite/native/sqlite-macos-arm64.a
xu native pack --manifest sqlite/native/native.json --slice macos-arm64=sqlite/native/sqlite-macos-arm64.a -o sqlite/native/sqlite.xulib
