文档

安装

本文对应 Xu {{xu_version}}。安装包是否可下载，以 GitHub Releases 的实际附件为准。

使用包含 bin/、src/ 和工具的完整 SDK。标准库源码是编译导入的必要输入；单独把编译器改名放进 PATH 不构成完整开发环境。

方案一：免安装浏览器沙箱 (Zero Install)

无需在本地下载或配置任何环境，可直接进入 xulang.org 在线 Playground 沙箱。该沙箱基于客户端 WebAssembly（纯浏览器前端执行，零服务端排队等待），即可实时体验完整的语言特性、标准库调用与语法交互。

方案二：终端一行命令极速安装 (推荐)

Xu 提供了开箱即用的自动化安装脚本，自动检测操作系统与芯片架构、下载对应的官方 SDK 并持久化配置全局环境变量，安装后在系统任意终端均可直接执行 xu：

macOS / Linux（终端一行执行）

# 自动检测芯片架构（ARM64 / x86_64）、下载并持久化配置 Shell 环境变量
curl -fsSL https://xulang.org/install.sh | bash -s -- --version {{xu_version}} --yes

亦可直接从 GitHub Releases 下载各系统独立的免提权安装程序（二进制单文件，无需任何第三方依赖）：

chmod +x xu-setup-linux-x64 && ./xu-setup-linux-x64 -y

Windows（PowerShell 或 GUI 图形向导）

PowerShell 单行命令：

& ([scriptblock]::Create((irm https://xulang.org/install.ps1))) -Version "{{xu_version}}"

原生自绘 GUI 图形向导：
从 GitHub Releases 下载 xu-setup-windows-x64.exe，双击即可运行零依赖的原生图形向导，自动配置系统注册表用户 Path 与 XU_ROOT。

安装完成后，打开新的终端窗口输入 xu --version，即可在系统任意位置全局运行。

方案三：原生独立安装程序与离线 SDK 安装

如需离线部署、内网分发或精确控制安装包版本，可直接下载对应平台的原生安装包：

操作系统推荐安装包说明
Windows 下载 xu-v{{xu_version}}-windows-x64-setup.exe
或 xu-setup-windows-x64.exe		 原生单文件离线安装包，直接双击启动自绘图形向导，自动配置注册表用户 Path 与 XU_ROOT，无脚本执行策略拦截。终端亦可直接执行 .\xu-setup-windows-x64.exe -y 静默安装。
macOS 下载 xu-v{{xu_version}}-macos-arm64.pkg
或 xu-setup-macos-arm64		 macOS 原生图形安装向导，自动配置 /etc/paths.d/xu，系统所有终端全局立即可用；亦可下载独立安装程序 xu-setup-macos-arm64 免提权运行。
Linux 下载 xu-setup-linux-x64
或 xu-setup-linux-arm64		 原生单文件二进制程序，运行 chmod +x xu-setup-linux-x64 && ./xu-setup-linux-x64 -y，自动解压 SDK 并写入用户 Shell 环境变量配置。

离线 SDK 归档包安装

若从 下载页 或 GitHub Releases 下载了完整的 SDK 压缩包（Unix 为 .tar.gz，Windows 为 .zip），解压后根目录已内置原生安装程序：

# Windows：解压后在资源管理器中直接双击根目录下的 xu-setup.exe
# 或在命令行中执行：
.\xu-setup.exe -y

# macOS / Linux：解压后在终端运行根目录下的 xu-setup
./xu-setup -y

默认更新 PATH 中已有的 SDK；未发现时安装到用户主目录下的 .xu（macOS .pkg 默认为 /usr/local/xu）。如需自定义安装目录，可传入参数 --prefix /custom/path。在自动化 CI 脚本中，使用 ./xu-setup --yes 或 .\xu-setup.exe --yes 安装全部工具；若只需临时体验，可在解压目录下执行 source env.sh（PowerShell 为 . .\env.ps1）。

验证全局环境

安装完成后，打开新的终端窗口（CMD、PowerShell、Terminal 或 VS Code 内置终端），验证工具链全局可用：

xu --version
xu env
xu doctor

升级、重复安装与修复

重新运行上方安装命令即可升级或修复当前 SDK，包括旧版更新器误报版本不匹配或上次安装未完成的情况。安装器先在同一文件系统准备新 SDK，核验完整文件清单与十个工具，再替换安装目录；原 SDK 保留在安装器输出的备份路径。SDK 管理范围以外的用户数据会保留。

如需指定目标，Unix 命令末尾追加 --prefix /path/to/xu；PowerShell 追加 -Prefix "C:\Tools\Xu"。目标父目录必须可写；系统安装可能需要管理员权限。不修改终端配置时使用 Unix --no-modify-path、PowerShell -NoModifyPath 或原生 Setup --no-modify-path。

xu --version
xu env
xu update --check
# 已安装 0.10.7 或更高版本后：
xu update
# 重新安装当前版本并修复全部 SDK 文件：
xu update --force

xu update 与 Setup 使用相同的完整 SDK 替换流程，更新编译器、配套工具、标准库、packages、示例和编辑器文件。xu update --version <版本> 可选择特定发行版本。版本变更请查看发行记录。

验证编译

xu check hello.xu
xu run hello.xu
xu build hello.xu --output hello

macOS / Linux 的可执行产物已有执行权限。PowerShell 中建议使用 --output 指定路径。

环境与源码构建

XU_ROOT 指向 SDK 或编译器仓库；XU_STDLIB_ROOT 可显式指定标准库 src/。XUPATH 追加搜索目录，不能替代外部模块的 require: 声明。工具 xu-fmt、xu-doc、xu-map、xu-doctor、xu-desktop、xu-lsp 应与 xu 放在同一个 bin 目录。

源码位于 xu 仓库。make xu 使用已有 hosted 产品种子自举，并重建工具；清洁检出需要先准备产品种子及 bootstrap 伴随仓库，不能只凭源码直接执行编译器。packages、examples、vscode-xu 分别维护在独立仓库。
