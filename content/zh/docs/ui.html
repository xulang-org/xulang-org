UI / WebView

本页介绍 UI 开发分支：基础绘图与保留布局需要 Xu 0.10.0+；编辑控件、扩展菜单、屏幕和 WebView 请求需要 0.10.1-dev.2+；统一控件样式需要 0.10.1-dev.3+。开发版尚未发布，请使用对应源码构建的 SDK。

#ui 管理窗口、事件与桌面服务；#ui/draw 记录绘图帧；#ui/layout 计算布局；#ui/widgets 管理控件、交互与保留场景；#ui/webview 承载网页及请求桥接。

构建与示例

应用包含 main.xu、xu.xun、带 PNG 图标的 brand/；WebView 可添加 www/。macOS 使用 AppKit/WebKit，Windows 使用原生宿主与 WebView2，Linux 使用 GTK4，网页另需 WebKitGTK 6.0。先检查目标工具链，再打包。

# 从匹配的 Xu 源码根目录运行；应用目录须有 xu.xun
bin/xu doctor --desktop --target macos-arm64
bin/xu build /path/to/examples/examples/16_ui_webview/style_gallery \
  --target macos-arm64 --desktop -o /tmp/XuStyles

示例仓库提供 python3 scripts/ui_examples.py check all 和 run style_gallery；通过 XU_ROOT 选择匹配的 Xu 源码。输出放在 build/ui/<target>/。macOS 为 .app，Windows 为 .exe，Linux 为 ELF。跨目标编译不等于目标机交互验收。

绘图帧与资源

一个 worker 消费 App.event_ch；等待 canvas_ready 后，用 draw.context_of 取得 Context。Context 与资源属于 canvas_id / generation，关闭窗口后失效。每次以 Context.new_frame / Frame.begin 开始，记录完整帧后只调用一次 present；失败时 cancel。空闲时保留上一帧，不持续重绘。可先合并排队事件，再提交一次绘制。

Frame 的坐标是浮点逻辑像素，原点在左上角；Frame.scale(1.0, 1.0) 是原比例。兼容的包级 draw.scale(100, 100) 使用百分比。push / pop 同时保存变换、裁剪与画笔；栈必须配对。Frame 上限为 4 MiB、100000 条命令、256 层状态。DisplayList 复用命令，Surface / SurfaceCache 复用栅格结果。

画布默认不平移。 macOS、Windows、Linux 都需要在画布就绪后显式调用 draw.set_pan_enabled(1) 才启用内置拖拽 / 滚轮相机；关闭时重置偏移。应用仍可接收拖拽和滚轮事件。控件 attach 会启用输入并关闭相机。

Image、TextLayout、DisplayList、Surface、缓存与输入会话都有显式释放方法。资源必须保留到引用它们的 Frame 被 present、freeze 或 snapshot 成功接受；已接受的记录会持有所需资源版本。复制资源句柄不创建独立资源；使用相应 clone / dispose 契约。

保留布局与事件

Constraints 从父向子传递，尺寸从子向父返回。布局树支持 row / column / stack / padding；单树最多 4096 节点、深度 64。View 保存稳定节点 ID、脏标记、命中与重绘边界；这不是按需构建的虚拟列表。

通过 dispatch_event 路由键盘和指针，并把原生文字事件、剪贴板结果交给 Editor.event。节点回调中的绘制矩形、指针位置为节点局部坐标；node_bounds / Editor.place 使用画布坐标。布局或祖先滚动改变后，在绘制前调用 place_editor 同步命中和 IME 几何。拖动滚动条时为节点开启 set_capture_outside，使指针离开视口后仍可拖动。

统一控件样式

dark_styles、light_styles、contrast_styles 返回完整 Styles。font 和 text_scale 控制文字，density 控制几何；各 ControlStyle 可用 inherit_font = false 单独选择字体。外观包括颜色、圆角、边框、焦点、内边距、最小尺寸、对齐和阴影。

@main
#ui/draw
#ui/widgets

fn main() int {
    mut styles := widgets.light_styles()
    styles.text_scale = 1.4
    styles.density = 0.85
    styles.button.radius = 10.0
    styles.button.icon_placement = widgets.icon_trailing
    mut rule := widgets.state_paint(widgets.state_focused | widgets.state_invalid)
    rule.unless = widgets.state_disabled
    rule.fields = widgets.paint_border | widgets.paint_focus
    rule.border = draw.rgb(220, 38, 38)
    rule.focus = draw.rgb(251, 113, 133)
    styles.button.states.push(rule)
    styles.validate() or (err) {
        eprintln(err.msg())
        << 1
    }
    << 0
}
控件可调整内容与入口
Buttonmeasure_styled / paint_styled；图片用 measure_icon_styled / paint_icon_styled，支持四向位置、间距和禁用透明度
Checkbox字体、间距、指示器尺寸、标记线宽；勾选标记与标签分别取色
Input / TextArea字体、行高、内边距、占位、选区前景 / 背景、光标、预编辑下划线、只读与错误状态
Progress轨道、指示条、尺寸、圆角、禁用和错误状态
Scroll滚动条宽度、边距、最小滑块、焦点和状态；paint_scrollbar 放在 overlay_styled 中

基础状态位为 disabled=1、hovered=2、pressed=4、focused=8、selected=16、invalid=32、read_only=64。默认背景优先级是禁用 → 错误 → 只读 → 选中 → 按下 → 悬停 → 普通。StatePaint 的 when 位须全部匹配，unless 位须全部不匹配；按数组顺序覆盖，后匹配规则胜出，仅修改 fields 指定的颜色 / 图标透明度。每个控件最多 32 条规则。

作用域、测量与缓存

View.set_styles 设置根主题。set_style_scope 保存完整主题快照，后代继承到下一作用域；全局主题变化不会覆盖显式局部主题。clear_style_scope 恢复继承；styles_for 返回独立克隆。颜色或装饰变化只使绘制缓存失效；字体或尺寸变化还会重新测量通过 set_style_measure 注册的节点。

@main
#ui/widgets

fn configure(view &mut widgets.View, brand_node int, label_node int) int {
    styles := widgets.light_styles()
    view.set_styles(&styles) or >>
    mut local := styles.clone()
    local.button.radius = 12.0
    view.set_style_scope(brand_node, &local) or >>
    view.set_style_measure(label_node, true) or >>
    view.mark_measure(label_node) or >>
    << 0
}
fn main() int { << 0 }

StyledPainter 的 measure_styled / paint_styled / overlay_styled 借用当前有效主题。调用 layout_styled，同步编辑器位置，再调用 present_styled；无脏更新时返回 false。snapshot_styled 用于离屏结果。标签使用 StyledLabel 缓存排版；修改文字后 set_text 并 mark_measure。回调中不修改 View 或拓扑；资源在窗口关闭时释放。

旧的八字段 Theme 和 paint 接口继续兼容。主题由应用显式切换；原生菜单 / 对话框跟随平台外观，WebView 使用 CSS。阴影是最多八层的有界近似。当前控件范围是上表各项，自定义控件通过 StyledPainter 接入。

编辑控件与 IME

widgets.input 与 text_area 创建持久 Editor。聚焦时原生 TextInput 会话拥有编辑和预编辑状态；失焦后 Editor 保留提交值。支持选区拖动、方向键、Home / End、Shift 扩选、系统复制 / 剪切 / 粘贴；单行 Enter 提交，多行 Enter 换行。剪贴板异步结果仅用于发起时的会话版本。

set_read_only(true) 释放原生输入会话，保留本地选择、导航和复制，拒绝输入、剪切和粘贴，迟到 IME 提交不改值。enable(false) 禁用交互。文本最多 16384 字节 UTF-8，不含 NUL；大文本和大字体组合还受原生排版预算限制。选区索引为 UTF-8 字节位置。Windows 命中查询需要 DirectWrite；旧 Wine 缺少对应实现。

结构化菜单与屏幕

Window.set_menu_entries 原子替换每窗菜单树。根 parent=-1 且必须是 submenu，其余 parent 是更早的 submenu 数组下标；最多 256 项、深度 8。只有 menu_check 可 checked，只有 action / check 可设置快捷键。menu_primary 在 macOS 对应 Command，在 Windows / GTK 对应 Control。点击以 ev_menu_clicked 返回，应用更新勾选状态后重新设置菜单。macOS 在未提供时补充标准 Edit 菜单。

@main
#ui

fn configure_menu(window &ui.Window) int {
    mut entries := []ui.MenuEntry{}
    entries.push(ui.submenu("document", "Document", -1))
    mut reset := ui.menu_action("reset", "Reset", 0)
    reset.key = 82
    reset.modifiers = ui.menu_primary | ui.mod_shift
    entries.push(reset)
    entries.push(ui.menu_separator(0))
    entries.push(ui.menu_check("readonly", "Read only", 0, false))
    window.set_menu_entries(entries) or >>
    << 0
}
fn main() int { << 0 }

Window.screens_async 返回 Request；完成后用 screen_result 解码 bounds、work_area、scale、primary / current。先检查 primary_known / work_area_known。Windows 桌面矩形是物理像素，macOS / GTK 是逻辑桌面坐标，由 physical_coordinates 标明；均不能直接当作画布局部坐标。

异步桌面请求

剪贴板、文件选择、提示、屏幕与 WebView 原生查询返回 ui.Request；接收 ev_request 后用 request_of 解码，再用 result.matches 校验完整身份。提交成功只代表已受理。status 分别为 completed=0、cancelled=1、failed=2、unsupported=3、timed_out=4；空字符串也可能是成功结果。

@main
#ui

fn handle_result(event &ui.Event, pending &ui.Request) int {
    if event.kind != ui.ev_request { << 0 }
    result := ui.request_of(event) or >>
    if !result.matches(pending) { << 0 }
    if result.status == ui.request_completed { println(result.value) }
    << 0
}
fn main() int { << 0 }

RequestOptions.timeout_ms=0 使用 5000 ms，合法显式范围为 1–3600000 ms；提示框默认 300000 ms。Request.cancel 返回是否受理取消，不能撤销已经完成的剪贴板写入。保持事件消费者运行，关闭窗口后不再复用该 generation 的请求或资源。

WebView 请求生命周期

用 bind_ipc_requests_www 接收 InvokeRequest（id、window_id、generation、name、payload），与 App.run 分开在 Xu worker 中运行。网页调用如下；返回值是带 id 和 cancel() 的 Promise。JS 默认超时 30000 ms，显式范围 1–3600000 ms；支持 AbortSignal。listen 返回解除订阅函数。

const controller = new AbortController();
const pending = window.__XU__.invoke("echo", "Hello 世界", {
  timeoutMs: 5000,
  signal: controller.signal
});
pending.then(value => console.log(pending.id, value))
       .catch(error => console.log(error.name, error.message));
// pending.cancel();  // or controller.abort()

单个 invoke 请求（含协议头）及返回值最多 1 MiB；最多 64 个活跃派发额度，排队请求体 / 结果共用 8 MiB。请求名最多 256 个 UTF-8 字节。取消、导航和关闭会丢弃迟到结果；取消不能强制中断正在运行的用户回调，额度待回调返回后释放。并发请求可乱序完成。

WebView.eval_async、find_async、cookies_async、set_cookie_async、clear_cookies_async 使用相同 ui.Request / ev_request 生命周期，原生结果最多 64 KiB。原生完成回调在 UI 线程；应用派发在 Xu worker。兼容等待接口不消费 App 的公开事件队列。每窗 / 文档身份隔离，导航后不能把旧结果应用到新页面。
