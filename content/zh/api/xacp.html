#xacp

Xu Agent Control Protocol 安全核心 · 语言仓库 0.10.10-dev.1

导入：#xacp

来源：xu#23 的 src/xacp。本页附在已生成的 {{xu_version}} 目录旁边，不计入那一批提取出的包数量。

#xacp 是与传输无关的安全核心：帧上限、XUN 校验、权限和会话生命周期。导入它不会打开控制通道。stdio 与本机回环 TCP 是运行时钩子，只有 xu build --xacp 或 --xacp-port 才会插入。

命令行：xu xacp · 常见问题 · 可运行样例

会话

open_session() 返回 STATE_NEW（0）会话，权限为 PERM_NONE，代数为 1，下一个请求 id 为 1。close_session 将其改为 STATE_CLOSED（2），增加代数，清掉活动请求并收回权限。STATE_OPEN 为 1。

同一时刻只能有一个活动请求。begin_request 只接受正数且等于 next_id 的 id，然后预约它。finish_request 释放该 id。完成 id 1 时，会话从 STATE_NEW 进入 STATE_OPEN。id 或代数不匹配返回 stale_request。已有活动请求时再次 begin 返回 request_in_flight。已关闭会话返回 session_closed。

函数作用
open_session() Session新建无权限会话。
close_session(s &mut Session)关闭并清空权限。
cancel_request(s &mut Session)丢弃活动请求，不把会话打开。
begin_request(s &mut Session, r &Request) Outcome在 authorized 允许时预约下一个单调 id。
finish_request(s &mut Session, id int) Outcome释放活动 id。id 1 会打开会话。
authorized(s &mut Session, r &Request) boolxacp.hello 仅在 STATE_NEW。其后的操作需要对应权限位。
dispatch(s &mut Session, d &xun.Doc, l &Limits) Outcome只做核心生命周期。完成 xacp.hello，不授予 development 权限。其他已知操作在 begin 成功后返回 not_implemented；未授权时返回 permission_denied。

Hello 与权限

权限变更是宿主策略。set_permissions 只在会话仍为 STATE_NEW 时成功，并且只接受 0..15 内的位。未知位会被拒绝。请求一旦 finish，权限不再改变。

常量值操作
PERM_NONE0xacp.hello，且仅来自 STATE_NEW
PERM_INFO1proc.status
PERM_PROCESS2proc.output
PERM_UI_READ4ui.tree、ui.screenshot、ui.record
PERM_UI_MUTATE8ui.input、ui.act
PERM_ALL15development_permissions() 与 enable_development()

enable_development(s) 即 set_permissions(s, PERM_ALL)。它不会关闭 schema 校验、会话生命周期、原生资源释放或内存上限。hello 已经结束后再调用会返回 false，因为会话已经是 STATE_OPEN。启动期的 stdio 与 TCP 适配器在合法 hello 已经 begin、尚未 finish_request 时调用它，此时状态仍是 STATE_NEW。这条路径才会回答 permissions: development。库函数 dispatch 不会。

hello 的 schema 接受可选的非空 token 字符串。启动适配器不把该字段当作访问口令。

帧与上限

parse_frame 接受以 --- !xacp 加换行开头、以换行加 === 结尾的文档。空正文、尾随数据和超过 MAX_FRAME_BYTES 的帧都会被拒绝。正文是 XUN。validate_request 要求根字典恰好包含 id、op、args。id 为 !i 且必须为正。hello 的 ver 必须是 !ver 1.0.0。

default_limits() 使用下列硬上限。自定义 Limits 只能更小。

常量值
MAX_FRAME_BYTES1048576（1 MiB）
MAX_STRING_BYTES65536
MAX_FIELDS64
MAX_TABLE_ROWS10000
MAX_NODE_ID16777215

consume_input 与 consume_output 会拒绝负数、单次超过帧上限、或使会话累计超过帧上限的计数。启动期读取器自己执行逐帧上限：超限返回 frame_too_large 并关闭该会话。EOF 时的半帧返回 truncated_frame。完整 EOF 关闭会话。非法帧和 schema 失败的请求 id 为 0，代码为 frame_error 或 schema_error。

启动期响应沿用同一帧壳。形状是 id、ok，以及 data 或 error.code：

--- !xacp
id: !i 1
op: xacp.hello
args:
  ver: !ver 1.0.0
===
--- !xacp
id: !i 1
ok: !b true
data:
  state: OPEN
  permissions: development
===

已知操作

schema 只允许下列操作。其余都是未知操作。

操作权限启动期控制通道
xacp.helloPERM_NONE，且仅 STATE_NEW校验通过后，在 finish 之前调用 enable_development()。数据为 state: OPEN 与 permissions: development。
proc.statusPERM_INFOargs 必须为空。返回真实的 os.getpid() 与 state: OPEN。
proc.outputPERM_PROCESS做 schema 校验（stream 为 stdout 或 stderr）。没有输出适配器时返回 not_implemented。
ui.treePERM_UI_READ做 schema 校验。没有 Screen 适配器时返回 not_implemented。
ui.screenshotPERM_UI_READ同上。这条通道不返回真实像素。
ui.inputPERM_UI_MUTATE同上，包括步进校验之后。
ui.actPERM_UI_MUTATE同上。schema 允许的动作名是 focus、click、set_text、set_checked。
ui.recordPERM_UI_READ同上。schema 模式为 events 与 frames。这不是启动器的 stdout record 模式。

在启动通道上，not_implemented 发生在 begin_request 之后，因此该 id 已被消耗，下一帧必须使用随后的 id。permission_denied 在 id 前进之前返回。

本阶段没有事件推送。宿主如果持有真实的 ui/widgets.Screen，可以调用带类型的入口（ui_tree、ui_screenshot、ui_screenshot_node、ui_input、ui_input_request、ui_act、start_recorder、finish_recorder、abort_recorder、dispatch_screen）。这些调用仍要求会话拥有对应权限位，并在进入 widget 之前检查窗口 id、节点 id、缩放（0.1 到 4.0）、文本长度以及行数或事件预算。截图返回拥有所有权的 draw.Surface，调用方负责 dispose。dispatch_screen 对 ui.record 返回 stream_required，并指向 start_recorder。启动适配器没有注册 Screen，因此 --xacp-stdio 与 --xacp-tcp 目前都不会产出这些数据。

传输钩子

src/xacp/stdio.xu 位于同一个包。--xacp 构建会在 main 开头插入 stdio_preflight(port)。那才是控制入口。普通 #xacp 导入不会发出这段启动代码。

  • stdio_preflight(port) 扫描参数直到 --。先遇到的 --xacp-tcp 或 --xacp-stdio 生效，并在不运行 main 其余部分的情况下退出。其他启动方式直接返回，业务 main 照常运行。它们不监听，也不读取控制 stdin。
  • serve_stdio() 读写进程的标准流。帧为 --- !xacp … === 再加换行。会话独占标准流。EOF 结束进程。
  • serve_tcp(port) 只在 127.0.0.1:port 监听。构建端口必须是 1..65535；端口 0 关闭 TCP，此时该函数失败。每个已接受的连接有自己的会话。连接按顺序处理。失败的对端只结束自己的会话，监听继续接受后续连接。没有 TLS，也不能绑定其他地址。

--xacp-help 是单独的启动期打印，不是控制会话。它的 capabilities 行是 stdio。构建端口为 0 时还会打印 tcp: disabled (port 0)。正端口会打印 tcp: enabled 和 bind: 127.0.0.1:PORT。启动器模式见命令行参考。

尚未覆盖

  • 没有 TLS。
  • 不能绑定 127.0.0.1 以外的地址。
  • 启动通道上还没有真实的 UI Screen 适配器。proc.output 与各项 UI 操作会先校验，再返回 not_implemented。
  • 目标持续无输出或不退出时，宿主没有超时或强制终止。调用方需要自行设置进程超时。
  • 生成器只接受 hosted native 可执行程序。库、共享对象、测试脚手架、嵌入式目标以及 --desktop 都会被拒绝。
  • 启动器的 record 在 Windows 上仍不可用。该模式录制的是 stdout，不是 ui.record。
