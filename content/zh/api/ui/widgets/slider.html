Slider

在连续区间内调节数值

在演练场运行 Xu 示例 ↗

示例由浏览器中的 Xu/WASM 运行器执行。

体验什么

拖动滑块，或聚焦后按方向键，查看当前数值。

使用要点

创建时提供最小值、最大值与当前值。按业务设置步长，并说明拖动时更新还是完成后提交。

通过 Screen 创建

下面的 Screen 构造方法返回节点 ID。将 ID 交给 Screen 的布局、状态与事件接口；它不是下方独立控件类型的实例。

原生 Xu 创建片段：在已有 Screen 的初始化阶段调用 configure；窗口创建、事件循环与资源释放参见完整原生示例。

#ui/widgets

fn configure(screen $&widgets.Screen) int {
    id := screen.slider(0.0,100.0,40.0) or >>
    screen.place(id,24.0,24.0,320.0,80.0) or >>
    << id
}

($&Screen) slider

XuAPI
pub fn (s $&Screen) slider(minimum f64,maximum f64,value f64) int

用途

在 Screen 中创建 Slider，返回组件节点 ID；创建失败时抛出错误。

参数

s $&Screen
本次调用使用的 Screen 实例；以独占借用传入，方法可修改它，调用方仍持有实例。
minimum f64
minimum（f64）
maximum f64
maximum（f64）
value f64
value（f64）

返回值

int — 组件节点 ID，供 place 和其他 Screen 方法使用。

放置、状态与事件

组件由应用拥有。Screen.place 放置节点，Screen.set_enabled 和 Screen.set_visible 管理可用性与显示。状态变化后重新呈现；创建和修改时处理 or 错误，不在绘制回调中修改拓扑。ToastHost 使用自己的队列接口。

($&Slider) input

XuAPI
pub fn (s $&Slider) input(input &ui.InputEvent) Action

用途

处理拖动和键盘调节，在连续变化和最终提交之间区分动作类型。

参数

s $&Slider
本次调用使用的 Slider 实例；以独占借用传入，方法可修改它，调用方仍持有实例。
input &ui.InputEvent
同一窗口、画布和代次的输入事件；坐标按控件所在的画布空间传入。

返回值

Action 描述本次交互：kind 是动作类型，consumed 表示事件是否已处理，request_focus 请求焦点，needs_paint 表示需要重绘。

使用时注意

  • ACTION_CHANGE 表示连续变化，ACTION_COMMIT 表示一次已改变数值的交互完成；value 是当前数值。启用 set_commit_only 后不发送连续变化。

($&Slider) set_commit_only

XuAPI
pub fn (s $&Slider) set_commit_only(enabled bool)

用途

选择只在一次调节结束时发出提交动作，适合变化处理较昂贵的业务。

参数

s $&Slider
本次调用使用的 Slider 实例；以独占借用传入，方法可修改它，调用方仍持有实例。
enabled bool
为 true 时抑制拖动中的 ACTION_CHANGE，保留结束时的 ACTION_COMMIT。

返回值

不返回值；设置时会清除当前待提交标记。

使用时注意

  • 拖动时控件内部数值仍更新并重绘；调用方把昂贵操作放到提交动作中处理。
