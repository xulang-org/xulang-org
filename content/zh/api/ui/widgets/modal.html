Modal

在独立对话框中完成当前决策

在演练场运行 Xu 示例 ↗

示例由浏览器中的 Xu/WASM 运行器执行。

体验什么

打开确认框，分别取消与确认。

使用要点

模态期间将交互限制在对话框，关闭后将焦点返回触发位置。确认、取消及关闭需要明确的业务含义。

通过 Screen 创建

下面的 Screen 构造方法返回节点 ID。将 ID 交给 Screen 的布局、状态与事件接口；它不是下方独立控件类型的实例。

原生 Xu 创建片段：在已有 Screen 的初始化阶段调用 configure；窗口创建、事件循环与资源释放参见完整原生示例。

#ui/widgets

fn configure(screen $&widgets.Screen) int {
    id := screen.modal("Apply changes?","Review before confirming.") or >>
    << id
}

($&Screen) modal

XuAPI
pub fn (s $&Screen) modal(title string,message string) int

用途

在 Screen 中创建 Modal，返回组件节点 ID；创建失败时抛出错误。

参数

s $&Screen
接收者 $&Screen（独占借用）
title string
title（string）
message string
message（string）

返回

int — 组件节点 ID，供 place 和其他 Screen 方法使用。

放置、状态与事件

组件由应用拥有。Screen.place 放置节点，Screen.set_enabled 和 Screen.set_visible 管理可用性与显示。状态变化后重新呈现；创建和修改时处理 or 错误，不在绘制回调中修改拓扑。ToastHost 使用自己的队列接口。
