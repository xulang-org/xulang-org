2026-10-17 · 语言服务与编辑器工具

Xu LSP 与 vscode-xu：原生语言服务协议支持与编辑器生态升级

纯原生自举实现的 xu-lsp 语言服务正式落地，支持实时诊断、跨模块跳转、文档悬停与重命名重构；官方 VS Code 扩展规范化更名为 vscode-xu。

在以往的开发体验中，Xu 语言在编辑器端主要依赖 TextMate 语法高亮，语法与类型诊断需在终端中手动执行 xu check。随着 Xu 0.8.13 开发周期的推进，Xu 迎来了首个官方、自举实现的语言服务协议服务端——xu-lsp（命令行统一入口 xu lsp）。同时，官方 VS Code 扩展仓库正式重命名为 vscode-xu。

纯自举架构，告别 Oracle 镜像

xu-lsp 按照 Xu 体系的同级伴生工具（Sibling Tool）架构设计，完全采用 Xu 语言自身编写，直接复用标准库原生的 #encoding/json、#xu/format、#os 与编译驱动。它作为独立工具编译产出为 bin/xu-lsp，主编译器驱动 xu 通过 xu lsp 无缝调度，彻底告别了对 Rust primer（bootstrap oracle）的运行时依赖。

已就绪的核心 LSP 8 大能力

  • 实时语法与类型诊断（Live Diagnostics）： 监听编辑器的实时编辑事件，将未存盘内存缓冲区交由编译器高速校验，并在输入时即刻推送错误诊断标注（textDocument/publishDiagnostics），无需频繁手动存盘。
  • 代码一键格式化（Document Formatting）： 在编辑器中按快捷键（Shift+Option+F / Shift+Alt+F）直接触发 textDocument/formatting，无损复用 Xu 标准库官方格式化引擎 #xu/format。
  • 跨模块与标准库定义跳转（Go to Definition）： 在导入语句（如 #strings、#encoding/json）上按 F12 可直接打开对应标准库入口源文件；光标在形如 strings.split 的调用处按 F12，自动穿透跳转至目标函数定义；同时支持同模块跨文件定义定位与当前文件符号定位。
  • 富文本 Markdown 文档悬停（Hover Tooltips）： 鼠标悬停在关键字、原语类型（int、string、struct、xu 等）或内置函数上，即刻呈现语法签名与说明；悬停在用户自定义或标准库函数上，自动提取前置多行 // 注释并原汁原味渲染为 Markdown 卡片。
  • 文档符号大纲（Document Symbols & Outline）： 完整提取源文件内所有顶层函数、接收者方法、结构体、枚举与常量及其代码区间，完美点亮 VS Code 的 Outline 大纲视图与 Cmd+Shift+O 快速符号导航。
  • 智能代码补全（Code Completion）： 主要提供关键字、内置函数和当前文件声明的建议；成员链与外部包的语义补全能力有限。
  • 当前文件及同目录引用查询（Find All References）： 按 Shift+F12 匹配当前文件及同目录 Xu 文件中的标识符文本；结果可能包含同名但无关的符号。
  • 当前文件符号重命名（Rename Symbol）： 按 F2 为当前文件生成标识符文本替换，关键字受保护。请检查编辑预览中的同名符号，并另行更新其他文件。

官方扩展重命名为 vscode-xu

为符合主流编程语言社区的生态命名惯例（如 vscode-go、vscode-rust、vscode-zig），官方编辑器扩展仓库由原先的 vscode 正式更名为 vscode-xu。编译器 SDK 自动化安装脚本与伴生仓库解析机制已全面适配。

编辑器接入示例

// VS Code / Cursor: settings.json
{
  "xu.languageServerPath": "xu",
  "files.associations": {
    "*.xu": "xu"
  }
}

对于 Neovim（搭配 nvim-lspconfig）或 Helix 编辑器，只需将 LSP 服务命令配置为 xu lsp，即可在不同终端和编辑器中享受一致的现代语言服务体验。

获取与试用

在 Xu 源码仓库中执行 make xu-lsp 或 make tools 即可生成最新的 bin/xu-lsp。安装最新构建的 vscode-xu 插件后，重启窗口即可享受完整的 Xu 现代 IDE 交互体验。
