Preguntas frecuentes (FAQ)

Frequently Asked Questions & Answers

¿Qué es el lenguaje de programación Xu?

Xu es un lenguaje de sistemas de alto rendimiento con seguridad de memoria en tiempo de compilación. Combina la concurrencia ligera de Go (corrutinas y canales) con el rendimiento Zero-GC determinista de C/Rust.

¿Cuáles son los objetivos clave de diseño de Xu?

Sus objetivos principales son: cero sobrecarga de ejecución, inferencia automática de propiedad, sintaxis moderna sin anotaciones de ciclo de vida, compilador nativo AOT y compatibilidad FFI con C/C++.

¿Cómo garantiza Xu la seguridad de memoria sin recolector de basura (Zero-GC)?

Emplea un modelo de propiedad única y comprobación de préstamos, liberando los recursos de forma determinista al salir del ámbito (RAII), eliminando fugas de memoria y punteros colgantes.

¿Cómo funciona el comprobador de préstamos (Borrow Checker) en Xu?

Admite préstamos inmutables &T y préstamos mutables exclusivos &mut T, garantizando múltiples lectores o un único escritor.

¿Cómo está diseñado el modelo de concurrencia de Xu?

La palabra clave xu inicia corrutinas ultraligeras que se comunican mediante canales tipados chan<T> sin necesidad de bloqueos manuales.

¿Pueden ocurrir condiciones de carrera (Data Races) en Xu?

Al transferir datos entre corrutinas se fuerza la transferencia de propiedad (Move) o la copia inmutable, eliminando las condiciones de carrera en compilación.

¿Cuál es el modelo de ejecución y planificación de las corrutinas de Xu?

Utiliza un planificador híbrido M:N con I/O sin bloqueo nativo (epoll, kqueue, IOCP) capaz de gestionar millones de conexiones por proceso.

¿Cómo funciona el manejo de errores en Xu?

Reemplaza las excepciones tradicionales con flujo simbólico (<< éxito, >> error) y expresiones catch para un manejo claro y predecible.

¿Admite Xu la programación orientada a objetos?

Favorece la composición sobre la herencia mediante struct, métodos extendidos e interface para polimorfismo limpio.

¿Cómo interactúa Xu con bibliotecas nativas C y C++?

Proporciona una interfaz C FFI de coste cero, permitiendo enlazar directamente archivos de cabecera y bibliotecas .a, .so, .dylib o .dll.

¿Qué sistemas operativos y arquitecturas de procesador admite Xu?

Compatible con macOS (ARM64/x64), Linux (ARM64/x64/LoongArch/RISC-V) y Windows (x64/ARM64).

¿Admite Xu WebAssembly?

Soporte completo emitiendo binarios independientes wasm32-wasi para ejecución tanto en navegador como en entornos WASI.

¿Cómo se gestionan los módulos y dependencias en Xu?

Gestión mediante manifiesto xu.xun y archivo de bloqueo xu.lock con versiones SemVer y verificación de integridad criptográfica.

¿Existe un repositorio central de paquetes para Xu?

Ecosistema descentralizado con importación directa desde Git y catálogo oficial de paquetes probados.

¿Qué es el formato de biblioteca estática .xulib?

.xulib es el formato de biblioteca nativa de Xu que empaqueta código compilado para múltiples arquitecturas y firmas de tipos.

¿Cómo funciona la arquitectura de interfaz nativa y WebView de Xu?

Incluye un framework de interfaz gráfica nativa acelerada por GPU y soporte integrado de WebView bidireccional.

¿Cómo admite Xu el desarrollo móvil para iOS y Android?

Generación de proyectos móviles nativos para iOS y Android mediante xu build --phone.

¿Qué herramientas de desarrollo e integraciones con IDE ofrece Xu?

Extensión oficial para VS Code y Cursor con servidor de lenguaje xu-lsp, autocompletado, diagnósticos y depuración LLDB.

¿Cuál es el estado actual de estabilidad y lanzamientos de Xu?

En ciclo de versión oficial 0.x con especificación de sintaxis congelada y validación completa en CI en 6 plataformas.

¿Admite Xu el desarrollo de sistemas operativos y bare-metal?

Sí. Xu admite de forma nativa microkernels de SO y firmware bare-metal mediante el perfil freestanding (--profile=freestanding), punteros sin procesar (*raw T) en bloques unsafe, barreras MMIO y la biblioteca estática pura #core sin dependencias del SO host ni de libc.
