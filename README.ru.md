## Компактный язык с прозрачным потоком управления

XU объединяет статическую проверку владения и заимствований во время компиляции с легковесными корутинами и типизированными каналами. Исходный код компилируется AOT в нативный машинный код или WebAssembly, а жизненный цикл ресурсов управляется детерминированно.

| Архитектурные решения | Что это даёт |
| :--- | :--- |
| **Владение без сборщика мусора (Zero-GC)** | Статическая проверка перемещений и заимствований во время компиляции, автоматический вывод времен жизни и детерминированная очистка ресурсов. |
| **Встроенная конкурентность** | Запуск корутины ключевым словом `xu`; обмен значениями через типизированные каналы `chan`. |
| **Наглядный поток управления** | `<<` возвращает значение, `>>>` сигнализирует об ошибке, а `>>> (err) { … }` обрабатывает её в месте вызова. |
| **Интегрированный инструментарий** | Сборка, запуск, статический анализ, тестирование, форматирование, генерация документации и поддержка LSP через единую утилиту `xu`. |

## Взгляните на код XU

Два рабочих потока (worker), один канал и явный путь обработки ошибок:

```xu
@main
#errors

fn score(name string) int {
    if name.len == 0 { >> errors.new("пустое имя") }
    << name.len * 10
}

fn worker(name string, results chan int) {
    value := score(name) >>> (err) {
        results <- 0
        <<
    }
    results <- value
}

fn main() int {
    results := chan int{cap: 2}
    xu worker("hello", results)
    xu worker("world", results)
    println(<-results + <-results)
    << 0
}
```

Сохраните в файл `main.xu` и выполните `xu run main.xu`. Программа выведет `100`.

Директива `#errors` импортирует пакет. Конструкция `xu worker(...)` запускает корутину. Две операции приёма из канала аккумулируют результат; в случае ошибки в функции `score` блок `>>> (err) { … }` отправляет резервное значение `0` и выходит из корутины.

## С чего начать

Опробуйте язык в [онлайн-песочнице](https://xulang.org/ru/playground) прямо в браузере без установки или [скачайте SDK](https://xulang.org/ru/download) для локальной разработки. После установки:

```sh
xu --version
xu run main.xu
xu build main.xu -o hello
```

Продолжите знакомство с [руководством для начинающих](https://xulang.org/ru/docs/start), [справочником по синтаксису](https://xulang.org/ru/docs/lang/syntax) или [запускаемыми примерами](https://github.com/xulang-org/examples).

XU активно развивается в линейке **версий 0.x**. См. [Releases](https://github.com/xulang-org/xu/releases) для загрузки официальных релизов SDK и [статус и ограничения](https://xulang.org/ru/docs/status) для информации о поддержке платформ и сред выполнения. [Панель бенчмарков](https://xulang.org/ru/benchmarks) фиксирует измеренные нагрузки, версии компиляторов и подтверждение источников.

Воспользуйтесь функцией [Поиск по API](https://xulang.org/api/), чтобы быстро найти нужный пакет или перейти к объявлению на странице. Нажмите клавишу `/` вне полей ввода для открытия строки поиска; стрелки и Enter служат для перехода по результатам, а клавиша Escape закрывает окно. Каталог API компактно сворачивается на мобильных устройствах. Заголовки объявлений являются постоянными ссылками, а кнопка «Copy link» позволяет скопировать ссылку на страницу или конкретный символ.

Главная страница справочника API содержит ярлыки для частых задач, описания разделов и встроенный поиск по стандартной библиотеке, UI и внешним пакетам. Страница каждого пакета начинается с интерактивного навигатора объявлений: фильтруйте по имени, назначению или типу, чтобы быстро перейти к сигнатуре и описанию. Связанные примеры исходного кода аккуратно свернуты по умолчанию.

Этот репозиторий организации также содержит исходный код официального веб-сайта. Сайт собирается под официально опубликованный **SDK XU**, указанный в файле `VERSION`; девелоперские сборки остаются изолированными.

### Локальная сборка

Требуется **Python 3.10+** (только стандартная библиотека). Статическая сборка и проверки выполняются автономно без XU, Node.js или дополнительных репозиториев.

```sh
make build                       # Сборка dist/ с валидацией внутренних ссылок и ресурсов
make run                         # Локальный предпросмотр на http://127.0.0.1:8080
make run PORT=18080               # Предпросмотр на пользовательском порту
make check                       # Запуск регрессионных тестов статического сайта
make build BASE_PATH=/xulang-org  # Сборка под пользовательский подпуть URL
make clean                       # Очистка dist/ и build/playground/
```

| Путь | Назначение |
| :--- | :--- |
| `content/{en,zh}/` | Документация, руководства, статьи блога и материалы API. |
| `templates/` | Шаблоны страниц, справочные руководства и подборки примеров. |
| `www/` | Стили, скрипты, шрифты, иконки и статические ресурсы. |
| `playground/typed/` | Клиентская среда выполнения WebAssembly, написанная на XU. |
| `scripts/` | Статический сборщик, генератор API и валидация выпусков. |
| `tests/` | Регрессионные тесты сайта, песочницы и каналов. |
| `brand/` | Фирменные ресурсы и гайдлайны визуального стиля. |

Сгенерированные файлы помещаются в каталоги `dist/` и `build/` (включены в .gitignore). Фрагменты контента объявляют заголовки через `<!--title: ...-->` и компилируются в маршруты каталогов, например `docs/start/index.html`.

### Общие метаданные сайта

Количество пакетов в сводке берется из сгенерированных инвентарей `content/{en,zh}/api/index.html`. Сборщик проверяет совпадение обоих инвентарей и существование страниц пакетов; страницы деталей виджетов и предварительные просмотры не включаются в подсчёт. При изменении состава пакетов инвентарь обновляется генератором.

Файл `templates/releases.json` содержит двуязычные примечания к выпуску, свежие записи на главной странице блога и ссылки в боковой панели блога. Добавляйте новые релизы туда вместе с соответствующими статьями блога на двух языках. Предыдущие архивные статьи остаются редакционным контентом. Главные баннеры, шапка и подвал не содержат патч-номер SDK; страницы загрузки, документации и API отображают точную версию. Структурированные метаданные ПО корректно идентифицируют выбранный SDK.

Ручной выбор языка сохраняет значение `xu-lang=en` или `xu-lang=zh` в localStorage и куки со сроком жизни 1 год (SameSite=Lax). LocalStorage действует в пределах всего домена, куки привязаны к базовому пути развёртывания. Ссылка переключения языка также содержит параметр `?lang=en` или `?lang=zh` для работы при заблокированных хранилищах. Явный валидный параметр URL имеет наивысший приоритет, затем localStorage, затем куки. Автоматический выбор китайского языка происходит только на чистой английской главной странице: сначала по сохранённому выбору, затем по локали браузера (упрощённый китайский). При блокировке всех хранилищ повторные визиты без query-параметра снова ориентируются на локаль браузера.

В карте сайта sitemap намеренно опущен тег `lastmod`. Время клонирования репозитория или время генерации API не отражает дату редакционных правок; чистая пересборка без изменений не должна имитировать обновление контента. Даты добавляются только при наличии надежной истории изменений по каждой странице с учетом общих зависимостей.

### Материалы API и примеры

Руководства для LLM используют шаблоны `templates/llms/*.md`, общие примеры сайта, файл `VERSION` и `www/benchmarks.json`. Статическая сборка формирует их с актуальной версией SDK; выполните `python3 scripts/gen_llms.py`, чтобы обновить закоммиченные копии в `www/llms*.txt`.

Курируемый текст описаний находится в `templates/api-guides/{en,zh}/`. Генератор API объединяет его с объявлениями типов из выбранного SDK. Примеры импортируются из официального репозитория examples по фиксированному неизменяемому коммиту; упакованные снапшоты в `www/api-examples/` обеспечивают независимость локальных сборок и CI.

Описания функций содержатся в `templates/api-contracts.json` с ключами по пакету, типу получателя и имени символа. Для каждого языка указываются назначение, параметры и возвращаемое значение; поле `notes` фиксирует ограничения и предусловия, `errors` — поведение при ошибках, а `examples` — полные программы под SDK с ожидаемым `output`. В коде используются обратные кавычки. Члены структур отображаются как поля или методы интерфейсов, а не как обычные параметры функций.

Проверенные исходники содержат `source_sha256` (сигнатура и тело) и `package_sha256` (файлы пакета, включая внутренние хелперы). При несовпадении хешей генерация останавливается: изучите реализацию, скорректируйте описание и только затем обновите хеши. Имена параметров и поля примеров валидируются до записи страниц. Запуск локальных примеров с соответствующим компилятором:

```sh
python3 scripts/check-api-examples.py --xu /path/to/selected-sdk/bin/xu
```

Для синхронизации объявлений и примеров выберите совместимые исходники в `templates/api-examples.json`, выполните проверку с выбранным SDK и передайте путь к репозиторию examples и его полный commit SHA:

```sh
make api XU_ROOT=/path/to/selected-sdk XU_PACKAGES_ROOT=/path/to/selected-sdk/packages \
  XU_EXAMPLES_ROOT=../examples XU_EXAMPLES_REF=FULL_EXAMPLES_COMMIT_SHA
```

Выбранные файлы должны строго соответствовать этому коммиту. Без этих двух параметров команда `make api` повторно использует и верифицирует упакованные снапшоты. Нативные примеры запускаются локально через SDK.

Многофайловые проекты упаковывают `main.xu`, обработчики событий и таблицы стилей. Каждый проект можно развернуть на странице API, включая раздел «Другие связанные примеры»; сопутствующие файлы доступны для отдельной загрузки. В каталоге фиксируется требуемая версия SDK, если она отличается от выбранного релиза сайта, поэтому примеры с экспериментальными API не создают ложного впечатления об их доступности в стабильном релизе.

Для выборочного обновления отдельных проектов без перезаписи остальных снапшотов запустите генератор с исходниками выбранного релиза и укажите флаг `--examples-project` для каждой целевой папки:

```sh
python3 scripts/gen-api.py --src /path/to/selected-sdk/src --packages /path/to/selected-sdk/packages \
  --examples ../examples --examples-ref FULL_EXAMPLES_COMMIT_SHA \
  --examples-project examples/16_ui_webview/component_workshop \
  --examples-project examples/16_ui_webview/style_gallery
```

Точечное обновление сохраняет неизменными байты, контрольные суммы и ссылки на коммиты остальных проектов. Перед запуском зарегистрируйте каждый исходный файл обновляемого проекта в `templates/api-examples.json`.

### Песочница на WebAssembly

Используйте совместимый SDK и Node.js 22+ для компиляции и оптимизации среды выполнения XU в WebAssembly.
В файле package-lock зафиксирован оптимизатор Binaryen; для чисто статических сборок по-прежнему достаточно Python.

```sh
npm ci --ignore-scripts # Установка зафиксированного оптимизатора WASM
make wasm XU_ROOT=/path/to/released-sdk
make check-playground  # Проверка выполнения WASM и примеров в Node.js
make check-chan        # Проверка примеров каналов с нативным XU
make build             # Упаковка среды выполнения в dist/
```

Песочница работает полностью на стороне клиента в браузере. Документация и главная страница не выполняют предзагрузку WASM. При первом запуске страницы модуль скачивается и асинхронно компилируется, после чего передается веб-воркеру для инициализации и выполнения кода на Xu. Скомпилированный код переиспользуется в пределах вкладки; при ошибке инициализации доступен повтор, а остановка или переключение программ прерывает выполнение предыдущего воркера.

Линейная память стартует с размера, сформированного SDK, и динамически расширяется до 256 МиБ. Файл `build/playground/build.json` сохраняет размеры WASM и gzip, дайджест, параметры оптимизатора и лимиты памяти. Скомпилированный WASM хранится в `build/playground/`.

### Бенчмарки и публикация

Для обновления результатов тестирования загрузите полный отчет GitHub Actions по шести платформам, затем выполните:

```sh
python3 scripts/import-benchmarks.py --artifacts DIR --bench-root PINNED_BENCH_CHECKOUT --commit FULL_SHA --run-id ID --date YYYY-MM-DD
python3 scripts/sync_all_benches.py --bench-root PINNED_BENCH_CHECKOUT
python3 scripts/gen-benchmarks.py
```

Укажите коммит bench, соответствующий идентификатору `bench_commit` в артефактах. Импорт верифицирует версии компиляторов, целостность исходников, сходимость неподвижной точки, полный реестр нагрузок и вывод stdout. Экспорт сохраняет все канонические идентификаторы тестов и исходный текст без псевдонимов и фильтрации. Неизмеренные ячейки остаются пустыми; для строк C/Rust берется минимальная медиана среди уровней O1/O2/O3.

Версия в `VERSION` определяет ссылки на дистрибутивы, справочник API и рантайм в браузере. Воркфлоу GitHub Pages сверяет SHA-256 опубликованного SDK, тестирует вывод и развёртывает сайт на GitHub Pages при отправке изменений в ветку `main`.

### Графический интерфейс: API UI и примеры

[Руководство по UI на английском](content/en/docs/ui.html) и [на китайском языке](content/zh/docs/ui.html) описывают официальный SDK Xu, указанный в `VERSION`. Все шесть пакетов — `ui`, `ui/draw`, `ui/layout`, `ui/chart`, `ui/widgets` и `ui/webview` — представлены в навигации опубликованного API. Прежние ссылки предварительных версий API автоматически перенаправляют на соответствующие опубликованные страницы с сохранением якорных ссылок на объявления.

Текстовые руководства расположены в `templates/api-guides/{en,zh}/ui*`, а спецификации контрактов и описания полей — в `templates/api-contracts.json`. Запустите команду `make api` с выбранным SDK для обновления объявлений. Каталог примеров охватывает рисование (draw), компоновку (layout), редакторы, системные сервисы, окна, запросы WebView, стили и галерею расширенных компонентов. Каждый пример сопровождается ссылкой на неизменяемый проект и загрузкой исходного кода с проверкой контрольной суммы.

Для будущих неопубликованных API генератор поддерживает режим предварительного просмотра разработки без изменения выбранного стабильного релиза:

```sh
python3 scripts/gen-api.py --src /path/to/development-sdk/src --preview --package ui
make build
make check
```

Руководства и контракты предпросмотра используют файлы `templates/api-guides/{en,zh}/preview/ui*` и `templates/api-preview-contracts.json`. Такой предпросмотр снабжается версией dev SDK и SHA-256 исходников и имеет приоритет над старыми редиректами. Релизные сборки сайта по-прежнему опираются на официальный стабильный SDK и упакованные примеры.

В браузере доступна [галерея компонентов из трёх страниц](https://xulang.org/ru/playground?example=ui-gallery):
общая логика десктопного интерфейса на Xu охватывает базовые элементы, Radio, ListBox, Scroll, Tabs, StyledLabel, Card, Badge, Progress и редактор текста в режиме просмотра под WebAssembly. Отрисовка выполняется на Canvas. Текстовый редактор в галерее работает только для отображения; нативное редактирование и системный ввод IME в ней не поддерживаются. Примеры с фигурами и счётчиком кликов работают полноценно. Подробнее см. в [руководстве по браузерному UI](playground/README.md) о синхронизации исходников, поддерживаемых API, управлении с клавиатуры и ограничениях воспроизведения.

Документация компонентов выстроена по иерархии **API → UI → Widgets → компонент** и включает 46 страниц компонентов на каждом языке. Файл `templates/widgets.json` определяет категории, примечания к использованию и описания сценариев. Скрипт `scripts/gen-widgets.py` соединяет каталог с опубликованными объявлениями и генерирует нативные фрагменты инициализации. Он запускается автоматически после формирования API релизов. Флаг `--check` проверяет актуальность закоммиченных страниц.

Все 46 компонентов снабжены интерактивными редактируемыми примерами на Xu/WASM. Их исходные тексты находятся в каталоге `playground/examples/widget-*.xu` и публикуются скриптом `python3 scripts/gen-widget-examples.py`. Некоторые демонстрируют составное или ограниченное поведение: DatePicker реализован в виде полосы выбора даты, WebView представлен макетом, TaskButton не порождает фоновые задачи, а текстовые поля поддерживают базовое клавиатурное редактирование без системного буфера обмена и IME. Описание каждого компонента честно фиксирует границы возможностей; выполнение кода в песочнице не гарантирует полную функциональность десктопного компонента.

[Руководство по браузерному UI](https://xulang.org/ru/docs/ui/#browser-playground) описывает варианты в ComboBox, чекбоксы MultiSelect, настройки Popover и передачу фокуса в Modal. Рабочее пространство и предпросмотр выдержаны в соответствии со стилевым гайдлайном XUUI: рамки фокуса в фирменном киноварном цвете и выравнивание подписей элементов управления по вертикали. На смартфонах разделы «Файлы», «Редактор», «Просмотр» и «Вывод» вынесены в отдельные вкладки. Режим Fit масштабирует полотно по размеру экрана; режим 100% с панорамированием (Pan) позволяет изучить крупный холст, при этом для взаимодействия с элементами режим панорамирования отключается.
